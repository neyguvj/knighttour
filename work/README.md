# work/ — рабочая scratch-папка

Единственное место в репозитории для временных артефактов агента: логов бенчей,
прогонов, статус-файлов, одноразовых скриптов и разбора данных. Наружу (`/tmp`,
`$TMPDIR`, `/var/...`) агент ничего не пишет.

## Структура — по задачам

Каждая задача получает свой подкаталог `work/<task>/`, где `<task>` — идентификатор
задачи: номер плана/ADR (`plan13`, `adr019`), `chore-<slug>` или иной короткий slug
текущей работы. Внутри — свободная раскладка, общепринятые имена:

```
work/
  plan13/            # одна задача — свой каталог, чужие не трогаем
    sweep5.log       # логи прогонов (make bench ... > work/plan13/sweep5.log)
    gate.status      # статусы фоновых прогонов
    analyze.py       # одноразовый скрипт задачи (в tools/ не попадает)
```

## Правила

- Новый артефакт — только внутрь `work/<task>/`; в корне `work/` файлов нет.
- Всё содержимое `work/` игнорируется git (кроме этого README): здесь ничего не
  коммитится; числа для истории переезжают в ADR/план, сырьё остаётся локально.
- Одноразовый скрипт живёт в каталоге своей задачи; стал переиспользуемым —
  переехал в `tools/` (см. skill `tools`), а из `work/` удаляется.
- Задача закрыта — её каталог можно удалить целиком; полагаться на его наличие
  нельзя, ссылки в ADR/планах указывают на путь как на след прогона, не как на
  артефакт репозитория.
