# Техническое задание: подсчёт всех открытых маршрутов коня

## Постановка задачи

Подсчитать количество всех **открытых маршрутов (туров)** коня на доске N×N,
N ∈ {5, 6, 7, 8}.

**Открытый тур** — последовательность ходов коня, посещающая каждую клетку доски
ровно один раз и не возвращающаяся в начальную клетку. Два тура различаются,
если различаются как последовательности клеток (повороты/отражения считаются
отдельными турами; сокращение симметриями — внутреннее дело алгоритма, итог
всегда «полный» счёт).

## Вход и выход

- **Вход**: размер доски `-size` (5–8), число воркеров `-workers`, глубина разреза
  `-precompute-depth` (см. `specs/main.md`).
- **Выход**: количество открытых туров (uint64) + отчёт мониторинга по фазам.

```
$ go run main.go -size 5 -workers 1
$ go run main.go -size 8 -workers 8
```

## Эталонные значения (проверочные числа тестов)

| Доска | Открытых туров |
|-------|-----------------|
| 5×5   | 1 728 |
| 6×6   | 6 637 920 |
| 7×7   | 165 575 218 320 |

Значения зафиксированы в тестах (`toursExpected`); расхождение — падение теста.
Для 8×8 эталон не зафиксирован (число поместится в uint64, но полный перебор
долгий).

## Функциональные требования

1. Корректный полный перебор: итог не зависит от числа воркеров и глубины разреза.
2. Параллелизм по всем фазам; детерминированный итог при конкурентной записи.
3. Мониторинг прогресса в реальном времени с разбивкой по фазам и ETA.
4. Graceful shutdown по Ctrl+C: частичный отчёт, без паник (см. `specs/main.md`).
5. Отмена через `context.Context` проходит сквозь все фазы.

## Нефункциональные требования

- Память ограничена сверху: пик — аккумулятор классов M (см. `specs/decisions/`).
- Производительность: горячий путь без аллокаций; замеры и методология —
  `specs/benchmarks.md`.
- Go ≥ 1.25 (см. `go.mod`), гонки запрещены (`make test` под `-race`).

## Границы решения

- Доски > 8×8 не поддерживаются (битборд `uint64`).
- Считаются только туры (посещение всех клеток); частичные маршруты — не цель.
