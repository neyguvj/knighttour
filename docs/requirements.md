# Техническое задание: подсчёт всех открытых маршрутов коня

## Постановка задачи

Подсчитать количество всех **открытых маршрутов (туров)** коня на доске N×N,
N ∈ {5, 6, 7, 8}.

**Открытый тур** — последовательность ходов коня, посещающая каждую клетку доски
ровно один раз и не возвращающаяся в начальную клетку. Два тура различаются,
если различаются как последовательности клеток (повороты/отражения считаются
отдельными турами; сокращение симметриями — внутреннее дело алгоритма, итог
всегда «полный» счёт).

## Вход и выход

- **Вход**: размер доски `-size` (5–8), число воркеров `-workers`, глубина разреза
  `-precompute-depth` (см. `specs/main.md`).
- **Выход**: количество открытых туров (uint64) + отчёт мониторинга по фазам.

```
$ go run main.go -size 5 -workers 1
$ go run main.go -size 8 -workers 8
```

## Эталонные значения (проверочные числа)

Направленный открытый тур — это гамильтонов путь графа ходов коня; два направления одного и того
же обхода считаются раздельно. Ниже полные счётчики для всех поддерживаемых досок: открытые туры
(гамильтоновы пути) и замкнутые туры (гамильтоновы циклы) как второй, независимый якорь
корректности.

| Доска | Открытых туров | Замкнутых туров |
|-------|-----------------|-----------------|
| 5×5   | 1 728           | 0               |
| 6×6   | 6 637 920       | 19 724          |
| 7×7   | 165 575 218 320 | 0               |
| 8×8   | 19 591 828 170 979 904 | 26 534 728 821 064 |

Открытые туры досок 5×5–7×7 зафиксированы в тестах (`toursExpected`); расхождение — падение теста.
Числа 8×8 тестами не проверяются: их полный перебор текущим конвейером невыполним (ADR-036). Это
внешний оракул для будущей реализации (план 23) — счётчик обязан сойтись с этими значениями, а не
воспроизвести их прогоном на этой машине.

Источники: открытые туры — OEIS A165134 («число направленных гамильтоновых путей n×n графа коня»,
член a(8) внесён Chernov в 2014). Замкнутые туры — число направленных гамильтоновых циклов; на
нечётных досках их нет по критерию Швенка, поэтому нули осмысленны. Для чётных досок это OEIS
A001230 (неориентированные) с множителем 2 за направление: 6×6 — 9 862 неориентированных, 8×8 —
13 267 364 410 532. Замкнутый счёт 8×8 получен методом бинарных диаграмм решений (BDD) в работах
Löbbing–Wegener и McKay — тот же класс алгоритма, что предлагает план 23.

## Функциональные требования

1. Корректный полный перебор: итог не зависит от числа воркеров и глубины разреза.
2. Параллелизм по всем фазам; детерминированный итог при конкурентной записи.
3. Мониторинг прогресса в реальном времени с разбивкой по фазам и ETA.
4. Graceful shutdown по Ctrl+C: частичный отчёт, без паник (см. `specs/main.md`).
5. Отмена через `context.Context` проходит сквозь все фазы.

## Нефункциональные требования

- Память ограничена сверху: актуальный пик — живая task-cache; историческое число пика
  относилось к аккумулятору классов M эпохи class mode (см. `specs/decisions/`).
- Производительность: горячий путь без аллокаций; замеры и методология —
  `specs/benchmarks.md`.
- Go ≥ 1.25 (см. `go.mod`), гонки запрещены (`make test` под `-race`).

## Границы решения

- Доски > 8×8 не поддерживаются (битборд `uint64`).
- Считаются только туры (посещение всех клеток); частичные маршруты — не цель.
