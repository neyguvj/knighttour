# Knight Tour — Поиск всех открытых маршрутов коня

![Test Status](https://github.com/neyguvj/knighttour/actions/workflows/test.yml/badge.svg)

Реализация алгоритма поиска всех открытых маршрутов коня (knight's tours) на досках от 5×5 до 8×8 с использованием параллельных вычислений и продвинутых оптимизаций.

**Открытый маршрут** — это последовательность ходов коня, при которой он посещает каждую клетку доски ровно один раз (не возвращаясь в начальную клетку).

## Quick Start

```bash
# Быстрый запуск на доске 5×5 (по умолчанию)
go run main.go

# Запуск на доске 6×6 с параллелизмом
go run main.go -size 6 -workers 8

# С предварительным разбиением подзадач
go run main.go -size 5 -workers 8 -precompute-depth 2
```

## Примеры использования

### Доска 5×5 (известное значение: 1728)

```bash
# Последовательный поиск
go run main.go -size 5 -workers 1
# Total paths: 1728, Pruned: ~100K, Time: ~10ms

# Параллельный поиск с 8 воркерами
go run main.go -size 5 -workers 8
# Total paths: 1728, Pruned: ~150K, Time: ~20ms

# С предварительным разбиением (precompute-depth=2)
go run main.go -size 5 -workers 8 -precompute-depth 2
# Total paths: 1728, Pruned: ~47K, Time: ~2.4ms
```

### Доска 6×6

```bash
# Последовательный поиск (медленно!)
go run main.go -size 6 -workers 1
# Total paths: 6,637,920, Pruned: ~1B, Time: ~1m45s

# Параллельный поиск с 8 воркерами
go run main.go -size 6 -workers 8
# Total paths: 6,637,920, Pruned: ~1B, Time: ~35s

# С предварительным разбиением (precompute-depth=2)
go run main.go -size 6 -workers 8 -precompute-depth 2
# Total paths: 6,637,920, Pruned: ~725M, Time: ~21s
```

## Параметры командной строки

| Флаг | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `-size` | `int` | `5` | Размер доски (от 5 до 8) |
| `-workers` | `int` | `1` | Количество параллельных воркеров для поиска |
| `-precompute-depth` | `int` | `0` | Глубина предварительного разбиения подзадач (0 = без разбиения) |

## Оптимизации

### 1. Битовые маски (uint64)
Для представления состояния посещенных клеток используется `uint64`, что позволяет:
- Компактно хранить состояние (до 64 клеток на доске)
- Выполнять операции за O(1): `&`, `\|`, `<<`, `>>`
- Быстро подсчитывать количество посещенных клеток через `bits.OnesCount64`

### 2. Симметрия доски (группа D₄)
Доска обладает 8 симметриями:
- 4 поворота: 0°, 90°, 180°, 270°
- 4 отражения: по горизонтали, по вертикали, по главной диагонали, по побочной диагонали

Это позволяет:
- Рассматривать только **канонические** стартовые позиции (6 уникальных на доске 5×5)
- Умножать результаты на размер орбиты для получения полного количества путей
- Снижать объём поиска в 8 раз для центральных позиций, в 4 раза — для угловых и рёберных

### 3. Dead-end pruning
Отсечение тупиковых ветвей поиска:
- Проверяются непосещённые клетки без непосещённых соседей (изолированные)
- Эффективен на поздних этапах поиска, когда остаётся несколько клеток
- Существенно сокращает количество рекурсивных вызовов

### 4. Кэширование с шардингом
Потокобезопасный кэш для мемоизации промежуточных результатов:
- **64 шарда** для параллельного доступа без блокировок
- Использует FNV-1a хэш от битового состояния
- Канонизация путей через `Symmetry.CanonicalizePath()` объединяет симметричные состояния

### 5. Разбиение на подзадачи (precompute-depth)
Глубокий DFS разбивается на подзадачи:
- При `depth > 0` дерево поиска разделяется на поддеревья на указанной глубине
- Подзадачи могут быть переиспользованы при разных стартовых позициях
- Позволяет эффективно распределить нагрузку между воркерами

## Результаты тестирования
