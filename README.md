# Knight Tour — Поиск всех открытых маршрутов коня

![Test Status](https://github.com/neyguvj/knighttour/actions/workflows/test.yml/badge.svg)

Реализация алгоритма подсчёта всех открытых маршрутов коня (knight's tours) на досках от 5×5 до 8×8 с использованием параллельных вычислений и продвинутых оптимизаций.

**Открытый маршрут** — это последовательность ходов коня, при которой он посещает каждую клетку доски ровно один раз (не возвращаясь в начальную клетку).

## Quick Start

```bash
# Быстрый запуск на доске 5×5 (по умолчанию)
go run main.go

# Запуск на доске 6×6 с параллелизмом
go run main.go -size 6 -workers 14

# С более глубоким предварительным разбиением подзадач
go run main.go -size 6 -workers 14 -precompute-depth 12
```

## Параметры командной строки

| Флаг | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `-size` | `int` | `5` | Размер доски (от 5 до 8) |
| `-workers` | `int` | число ядер CPU | Количество параллельных воркеров (1 = последовательный режим) |
| `-precompute-depth` | `int` | `5` | Глубина предварительного разбиения подзадач (от 1 до size²/2) |
| `-oracle-depth` | `int` | `0` | Размер маски для оракула форм во второй фазе (0 = старая схема через префикс-кэш) |

## Как это устроено

Дальше — рассказ об алгоритме по порядку: от представления доски и сокращения пространства поиска через симметрию, к двухфазному подсчёту, отсечению тупиковых ветвей и замерам. Детальные описания каждого компонента — в каталоге `specs/`.

### Структура графа

Всё состояние поиска — это одна 64-битная маска: один бит на клетку, 1 означает «посещена», 0 — «не посещена». Для доски до 8×8 (64 клетки) это помещается в одно машинное слово, поэтому копирование состояния — обычное присваивание, а само состояние служит готовым ключом для кэша. Битовые операции вынесены в отдельный пакет, а вызывающий код перебирает установленные биты через итератор, не обращаясь к битам напрямую.

Над маской лежит предвычисленный граф ходов коня. При старте для каждой клетки один раз строятся список соседей и побитовая маска этих соседей. Проверка «куда можно ходить из текущей клетки» сводится к пересечению маски соседей с маской непосещённых клеток — за O(1). Соседи хранятся в фиксированном порядке восьми возможных ходов коня; сортировка по эвристике Вонсдорфа сознательно не используется — замер показал, что она не меняет число узлов дерева поиска, а только добавляет стоимость сортировки в каждом узле (см. «Вывод»).

### Симметрия доски

Квадратная доска обладает группой симметрий D₄ — восемью преобразованиями: четыре поворота и четыре отражения. Это позволяет сократить пространство поиска в несколько раз.

Все восемь преобразований:

1. Без изменений (тождество)
2. Поворот на 90°
3. Поворот на 180°
4. Поворот на 270°
5. Отражение по горизонтали
6. Отражение по вертикали
7. Отражение по главной диагонали
8. Отражение по побочной диагонали

Поиск ведётся только из **канонических** стартовых позиций — по одному представителю на класс симметричных клеток. Результат из каждого представителя умножается на размер его орбиты: для «общих» клеток орбита равна 8, для угловых, реберных и диагональных — 4, для центра нечётной доски — 1.

### Канонизация состояния

Число продолжений маршрута зависит только от посещённой маски и текущей клетки, но не от того, где начался маршрут. Поэтому любую пару (маска, текущая клетка) приводят к минимальному виду среди восьми симметрий, и симметричные поддеревья — в том числе префиксы из разных стартовых орбит — сливаются в одну запись кэша. Горячий путь работает через предвычисленные таблицы подстановки: без замыканий, делений и взятия остатка, а маска трансформируется перебором только установленных битов, а не всей доски.

### Первая фаза: генерация подзадач

Алгоритм двухфазный. В **первой фазе** из канонических стартовых позиций DFS раскручивает префиксы до заданной глубины `-precompute-depth`; достигнув её, префикс сохраняется в кэш с весом орбиты и дальше не раскручивается. Ветви на этом пути всё так же отсекает прунер (см. «Отсечение путей»). Мелкие подзадачи лучше распределяются между воркерами, а симметричные префиксы схлопываются в одну запись с суммарным весом.

Число канонических стартовых групп на досках 5–6 всего около шести, поэтому при большом `-precompute-depth` простого параллелизма «по стартам» не хватает — воркеры простаивают. Стратегия генерации выбирается по глубине относительно порога (5):

- **Однофазная** (глубина ≤ 5): DFS от каждой канонической стартовой группы, группы обрабатываются параллельно — их достаточно для загрузки воркеров.
- **Двухфазная** (глубина > 5):
  - **фаза A** — заполнение промежуточного кэша на фиксированной глубине порога (тот же однофазный путь);
  - **фаза B** — каждая из тысяч промежуточных записей независимо докручивается до целевой глубины. Параллелизм в тысячи раз выше, чем у стартовых групп.

Корректность двухфазной генерации: граф и прунер инвариантны относительно симметрий D₄, поэтому продолжения всех симметричных копий одного префикса изоморфны. Догрутка канонического представителя с агрегированным весом воспроизводит ровно то же содержимое кэша, что и однофазная генерация — это покрыто тестами.

На нечётных досках дополнительно фильтруются старты: граф ходов коня двудольный, но с дисбалансом цветов (например, 13 против 12 на 5×5), поэтому открытый тур обязан начинаться на клетке «большинства». Старты другого цвета отсекаются ещё на этапе генерации.

### Кэширование

Кэш — потокобезопасная мемоизация промежуточных результатов. Он разбит на 64 шарда, каждый под собственным блокируемым мьютексом, что позволяет параллельно читать и писать в разные части кэша. Выбор шарда идёт по безаллокационному мультипликативному хэшу ключа — по его старшим битам.

Ключ записи — каноническая пара (маска посещённых клеток, текущая клетка) **без стартовой позиции**: число продолжений зависит только от маски и текущей клетки, поэтому симметричные состояния и даже префиксы из разных стартовых орбит сливаются в одну запись. Значение — агрегированный вес: сумма по всем слившимся префиксам «число продолжений × размер орбиты». Умножение на орбиту зашивается именно при генерации (единственный корректный момент, раз ключ не содержит старта), а запись накапливает вклады из разных групп. Итоговый вклад подзадачи в ответ — «число продолжений из неё × её вес»; на этапе подсчёта ни стартовая позиция, ни размер орбиты уже не нужны.

Кэш полезен на досках до 6×6 (ускорение 2–3×); на 7×7 и выше доля попаданий падает ниже 1% из-за экспоненциального пространства состояний.

### Отсечение путей

После каждого хода DFS проверяет, не оказалась ли ветвь тупиковой. Проверка двухуровневая и всегда включена.

- **Локальный dead-end** за O(степени клетки): по инварианту родительский узел уже прошёл проверку, поэтому новую изолированную клетку мог создать только последний ход. Достаточно просмотреть непосещённых соседей только что посещённой клетки и проверить, не потеряли ли они всех соседей. Маски соседей не копируются — читается предвычисленная маска графа за O(1).
- **Глобальные проверки** (только если осталось более одной непосещённой клетки, на битовых масках):
  - у текущей клетки нет непосещённых соседей — ветвь мертва;
  - **связность** — оставшийся путь живёт только в непосещённых клетках, они обязаны образовывать одну компоненту. Проверяется «заливкой» от младшего бита с расширением фронта масками соседей; по ходу считается степень каждой клетки;
  - **эвристика концов** — гамильтов путь имеет ровно два конца. Если вершин степени 1 три и более — отсечь; если ровно две и ни одна не соседна с текущей клеткой — отсечь.

Ни одна проверка не отсекает ветвь, содержащую полный маршрут: связность обязательна (путь не может покинуть компоненту без возврата в посещённые клетки), а эвристика концов — необходимое условие существования гамильтова пути. Эквивалентность наивной реализации и корректность покрыты вероятностными тестами.

Замеры полного подсчёта (M4 Max): против прунера только с dead-end доска 5×5 ускоряется с ~3.2 мс до ~0.7 мс, 6×6 — с ~16.7 с до ~1 с.

### Вторая фаза: подсчёт

Во **второй фазе** каждая запись кэша обрабатывается воркером: из её состояния подсчитываются все продолжения до полного маршрута, результат умножается на вес записи, и вклады агрегируются в общий счётчик без блокировок.

Главная оптимизация второй фазы — **досрочное завершение через реверс** (meet-in-the-middle). Префикс-кэш первой фазы переиспользуется как таблица обратных ответов. Для узла с маской посещённых клеток и текущей клеткой число продолжений равно числу «обращённых суффиксов» — путей, покрывающих ровно оставшиеся (непосещённые) клетки и входящих в соседа текущей клетки. Значение кэша — сумма по всей симметричной орбите ключа, поэтому для конкретной пары нужное число берётся делением значения кэша на размер орбиты (деление всегда точное).

Благодаря этому DFS подсчёта останавливается на уровне «всего клеток − глубина генерации» и отвечает запросом к кэшу вместо дальнейшего спуска. Оптимизация включается только тогда, когда уровень достижим (двойная глубина не превышает числа клеток), иначе выполняется чистый полный поиск. При глубине, равной половине клеток, каждая подзадача решается одним набором запросов — чистый meet-in-the-middle.

Безопасность прунинга: нужный обращённый суффикс продолжается через текущую клетку обратно по уже покрытому пути, поэтому он не мог быть отрезан прунером на генерации (прунинг инвариантен относительно симметрий). На нечётных досках старты нужных путей — концы реальных туров, то есть правильного цвета.

Стоимость — одно сравнение глубины на узел и одна трансформация маски на узел. В связке с двухфазной генерацией деградация на больших глубинах устраняется: на 6×6 при глубине 18 время падает с ~0.26 с до ~0.086 с, а оптимум смещается на глубину около 14–15 (~0.063 с).

### Альтернатива второй фазы: оракул форм

Слабое место старой схемы — цена мгновенного ответа: огромный префикс-кэш. На 8×8 при глубине ≥12 он требует ~16 ГБ ещё до начала подсчёта и физически не помещается в память.

Оракул отвечает на вопрос «сколькими способами можно покрыть ровно этот набор клеток путём, заканчивающимся вот здесь» напрямую, без глубокого префикс-кэша. Идея простая: ответ зависит только от **формы** набора, а не от того, где он лежит на доске. Ход коня определяется разницей координат, а все пути заперты внутри формы — значит границы доски на ответ не влияют. Тот же вырез, сдвинутый в другое место или повёрнутый/отражённый, даёт ровно тот же ответ.

Поэтому оракул кэширует ответы по формам:

- **Нормализация.** Для набора клеток перебираем 8 поворотов/отражений, каждый сдвигаем в угол, выбираем минимальный вариант — «эталонная форма». Все размещения одной формы сливаются в одну запись кэша — таблица примерно в 10–20 раз меньше, чем при кэшировании по конкретным позициям.
- **Вычисление при промахе.** Ответ для новой формы считается на месте: перебираются пути только внутри неё (она маленькая, с теми же отсечениями тупиков, что и основной поиск). Каждая форма считается один раз, дальше значение только читается.
- **Деление на симметрии не нужно.** Оракул отдаёт точный ответ для конкретной пары «форма + конец», поэтому деление на размер группы симметрий из старой схемы полностью выпадает.

Два параметра независимы: корни остаются мелкими (например, 10), а оракул работает с глубокими масками (например, 16). Там, где старая схема не помещается в память, у оракула альтернативы нет: десятки мегабайт корней + растущая по мере надобности таблица. На досках, где префикс-кэш влезает, старая схема быстрее (на 6×6 оракул дороже на 17% … ×3.5 в зависимости от глубины), поэтому по умолчанию (`-oracle-depth 0`) включена она:

### Мониторинг

Прогресс выводится без блокировок (атомарные счётчики) — одна перезаписываемая строка раз в секунду, по активной фазе: `generation` при однофазной генерации, `gen A` / `gen B` при двухфазной, затем `counting`. В строке — доля выполненных задач, найденные пути, число записей в кэш (вызовов записи, а не уникальных записей) и число отсечённых прунером ветвей, а также оценка оставшегося времени. По завершении печатается итог по каждой фазе и общее число путей. Накладные расходы — менее 1%.

## Вывод

На досках 5×5 и 6×6 время выходит на плато: на 5×5 — около 0.23 мс начиная с глубины 4, на 6×6 — оптимум около 0.064 с на глубине 14–15. Двухфазная генерация убрала деградацию на больших глубинах: на 6×6 при глубине 18 время фазы B растёт линейно (~67 мс), а фаза подсчёта, наоборот, сжимается до ~27 мс. На 7×7 оптимум — глубина 22 (~4 мин 6 с), плато на глубинах 21–23: выше экспоненциально дорожает фаза B, ниже — фаза подсчёта.

**Измеренные и отвергнутые оптимизации:**

- **Баланс цветов как критерий отсечения** — на 5×5/6×6 срабатывает 0 раз: инвариант выполняется автоматически вдоль любой легальной ветви DFS, а на нечётных досках старты уже фильтрует правило чётности.
- **Сортировка кандидатов по Вонсдорфу** — количество узлов дерева поиска не меняется вовсе (прунер локален и не зависит от порядка перебора), при этом время растёт на 10–20% из-за сортировки в каждом узле.
