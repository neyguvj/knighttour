# План 28. Матрица N(s,t): попарный подсчёт гамильтоновых путей между фиксированными клетками

## Статус

Выполнен (2026-10-24) и закрыт как принятый инструмент (шаг 4): ADR не заводится — содержательного
решения с числами развязка не потребовала, резерв 045 освобождён. Пакет `pairs` в ветке: матрица
`N(s,t)` (строки D4-представителей + доопределение), оракулы (перебор 5×5 полностью, симметрия,
D4-эквивариантность, `Σ_t` против `GenerateTasks`, `Σ_{s,t}` против эталонов 1 728 / 6 637 920),
MITM-зонд. Числа развязки: матрица 6×6 в юнитах под `-race` — 26,7 с (бюджет ≤ 30 с, выборка орбит
по правилу шага 2); MITM 5×5 — 6,7 с; зонд 6×6 `k18` тяжёлый (752 с, пик ≈ 5,4 ГБ) и живёт только
gated-бенчем по правилу плана. Справочная стоимость (`BenchmarkPairsRowCost`, без `-race`): строка
6×6 — 0,72 с, матрица (4 воркера) — 0,74 с, то есть ≈13 прогонов конвейера (~54 мс) на строку —
ожидание плана `10²–10³` не подтвердилось: анкерёванный спуск с отсечениями дешевле оценки.

## Мотивация и базовые числа

Счётчик умеет итог доски: `total = Σ W(task)·f(task)` по каноническим префиксам (specs/counter.md).
Все текущие якоря корректности глобальные: итог доски, тождества цензов, инвариантность к воркерам
и глубине. Ни один из них не отвечает на вопрос «а правильно ли разложены вклады между конкретными
концами». Матрица `N(s,t)` — число направленных гамильтоновых путей из клетки `s` в клетку `t` —
даёт класс внутренних проверок:

- симметрия `N(s,t) = N(t,s)` (обращение пути);
- эквивариантность относительно D4: `N(σs, σt) = N(s,t)`;
- сумма строки `Σ_t N(s,t)` равна счёту туров из `s`;
- сумма всех клеток равна направленному итогу доски (1 728 / 6 637 920 / …, docs/requirements.md).

Это независимые якоря: они считают иным спуском и сходятся с конвейером по числам. Плюс задел на
будущее: проверка склеек разрезов (опыты планов 26–27) и исследовательский интерес — суммы матрицы
по орбитам дают портрет доски, которого нет у скалярного итога.

Базовые числа для оценок: полный прогон конвейера 6×6 на глубине 14 — 54,26 мс (README, workers=14);
направленные итоги досок: 5×5 — 1 728, 6×6 — 6 637 920, 7×7 — 165 575 218 320.

## Идея / Гипотеза

Строку матрицы `N(s,·)` считает анкерёванный спуск от `s` до полного покрытия с гистограммой
последней клетки; мемоизация конвейера ему не нужна и недоступна (см. «Корректность», пункт про
форму значения). На 6×6 строка стоит на порядки больше полного прогона конвейера, но остаётся
в юнит-бюджете: анкерится только 6 представителей D4-орбит (по лемме Бернсайда на досках 5×5 и
6×6 орбит ровно по 6), а сумма всех направленных путей ограничивает работу сверху величинами
порядка миллионов листьев. Независимый MITM-зонд сбалансированным разрезом подтверждает строку 6×6
иным алгоритмом.

## Корректность

- Гистограмма последней клетки при полном анкерёванном спуске от `s` равна строке `N(s,·)` по
  определению: каждый направленный путь имеет единственный старт и единственный конец.
- Прунер безопасен: `ShouldPruneAfterVisit` — необходимое условие дополняемости (specs/pruner.md),
  отсечённые ветви не содержат гамильтоновых дополнений, гистограмма не меняется.
- Форму значения task-cache нельзя доверить строки: запись «маска → гистограмма класса конца»
  агрегирует второй конец пути (стартовый лист таблицы теряется в весе слота). Расширение формата —
  вторжение в горячий путь конвейера, запрещено решением задачи; поэтому механизм — отдельный
  тонкий контур поверх `graph`, `state`, `pruner`, `symmetry`, `workerpool`.
- Восстановление полных строк через D4 законно: граф коня эквивариантен относительно D4, поэтому
  `N(σs, σt) = N(s,t)`; строки канонических представителей орбит (поле `Canonical` группы из
  `symmetry.GetCanonicalGroups`) доопределяют все клетки.
- Сумма строки сверяется с независимым источником: `searcher.GenerateTasks(ctx, sink, s, 1, totalCells)`
  пишет каждое полное дополнение весом 1, сумма весов таблицы — счёт туров из `s` (тестом).
- MITM-зонд: путь `x_0…x_{N−1}` (`N` — число клеток) расщепляется по границе `m`: префикс
  `x_0..x_{m−1}` от `s` и суффикс `x_m..x_{N−1}`, обращённый в путь из `t`. Склейка точна: маски
  дополняют друг друга до полной, добавляется только проверка смежности концов. Префиксная сторона
  режется прунером (безопасно по тому же необходимому условию), суффиксная перечисляется без
  межсторонних отсечений.

## Дизайн

Новый пакет `pairs` вне конвейера подсчёта (прецеденты роли: `split`, `zdd` — инструменты, не
импортируемые в `counter` и CLI). Контракт — specs/pairs.md.

- `Row(ctx, g, start)` — анкерёванный DFS до полного покрытия; базовый случай добавляет 1 в слот
  последней клетки; кандидаты и отсечения — как в горячем спуске searcher, но своим кодом.
- `Compute(ctx, g, workers)` — строки для канонических представителей орбит стартов параллельно
  через `workerpool.Pool.Run`, затем последовательное доопределение всех клеток формулой D4;
  детерминированный итог.
- `mitmRow(ctx, g, start, m)` (неэкспортируемый) — зонд: карта префиксов `(маска, конец) → вес`
  глубины `m` из `s`; затем для каждой клетки `t` таблица путей глубины `totalCells − m` из `t`
  (`(маска, конец) → вес`) и склейка по дополняющей маске и смежности концов. Баланс
  `m = ⌈totalCells/2⌉`.
- Горячий путь конвейера (`counter`, `searcher`, `cache`) не меняется ни на строку; feature-флагов
  нет (ADR-021); CLI не расширяется — библиотечный API плюс тесты.

## Аллокационный бюджет

- `Row`: рекурсия глубиной `n²` со стековыми значениями (`state.State`, счётчик), гистограмма
  `n² × 8 Б`; в узле спуска аллокаций нет (битборды — значения). Максимум памяти строки — стек.
- Строки представителей: `6 × n² × 8 Б` (6×6: 288 Б) плюс итоговая матрица `n⁴ × 8 Б`
  (6×6: 10,2 КБ; 7×7: 310 КБ). Копий графа и разделяемых структур нет — чтение неизменяемого
  `graph` без блокировок, каждая горутина пишет свой слот.
- MITM-зонд: префиксная карта `|P| × ~48 Б` (ключ маска+конец, вес; порядок величины накладных
  расходов go-отображения), таблица суффиксов пересоздаётся на `t` и живёт по очереди: пик
  `≈ max(|P|, |T_max|) × 48 Б`, где `|P|`, `|T|` — числа частичных путей без повторения клеток
  на половинах разреза; измеряются шагом 3 до решения о месте зонда.

## Шаги

1. Пакет `pairs`: `Row` + оркул-тесты на 5×5 (полная матрица против независимого перебора пар,
   симметрия обращения, D4, цветовой паритет, частичный прогон при отмене ctx).
2. `Compute`: строки представителей + доопределение D4; якоря сумм: `Σ_t` против
   `GenerateTasks` полной глубины (5×5 все клетки, 6×6 выборка), `Σ_{s,t}` против эталонов доски
   (1 728 / 6 637 920); инвариантность к числу воркеров. Замер бюджетов: если тест полной матрицы
   6×6 под `-race` превышает 30 с, в юнитах остаётся выборка орбит, а полная матрица уходит
   за `-bench`-фильтр (правило фиксируется здесь до реализации).
3. MITM-зонд: на 5×5 — обычный тест, все строки против `Row`. На 6×6 — сначала ценз чисел
   полупутей при `m = 18` (числа записей и пик памяти), затем по правилу: ≤ 60 с под `-race` —
   обычный тест одной строки; иначе зонд живёт только бенчмарком `BenchmarkPairsProbe`. Цель
   Makefile добавляет реализация (документальная фаза правит только `specs/`), шаблон зафиксирован:

   ```make
   # Usage: make bench-pairs-probe N=<5|6>
   bench-pairs-probe:
   	@if [ -z "$(N)" ]; then echo "usage: make bench-pairs-probe N=<5|6>"; exit 2; fi
   	go test -v -run='^$$' -bench='BenchmarkPairsProbe/size$(N)' -benchmem -benchtime=1x -timeout=24h ./pairs/
   ```

   плюс имя цели в `.PHONY`; методология — specs/benchmarks.md «Зонд попарного счёта».
4. Вычитка specs/pairs.md под фактический код, строка в индекс specs/README.md, закрытие плана:
   ADR-045 только при содержательном решении с числами, иначе статус «Принято как инструмент».

## Метрики успеха

- Корректность (жёстко): все оркул-тесты зелёные под `-race`; совпадение матрицы с перебором 5×5
  полностью; `Σ_{s,t}` точное на 5×5 и 6×6; MITM-зонд сходится с `Row` побитово (все строки 5×5,
  минимум одна строка 6×6 в юните или за фильтром).
- Бюджет: шаг матрицы 6×6 в `make check` — не более 30 с под `-race` (порог понижения — см. шаг 2);
  MITM на 5×5 — не более 10 с; конвейер не замедлился (`make bench` 5×5/6×6 в шуме повторов —
  вторжения нет по построению).
- Стоимость строки (справочно, публикуется тестом-бенчем): сколько прогонов конвейера стоит строка
  и матрица на 6×6 — ожидание `10²–10³` полных прогонов на строку, то есть секунды против 54 мс.

## Риски

- Полная матрица 6×6 под `-race` оказывается дороже юнит-бюджета → правило шага 2: выборка орбит
  в юнитах, полная матрица за `-bench`-фильтром. Откат — не мержить ветку (ADR-021).
- MITM-полупути на 6×6 раздуваются памятью/временем → ценз до решения о месте зонда; при тяжёлом
  исходе зонд остаётся gated-бенчем с `peakRSS_MB` и не попадает в `make check`.
- Ошибка восстановления D4 маскируется симметричными данными тестов → сверка восстановленных
  строк с прямым `Row` на всех клетках 5×5 и на выборке членов орбит 6×6.
- Соблазн «дописать гистограмму концов» в task-cache отклонён заранее: формат значения — горячий
  путь, вторжение запрещено решением; при появлении чисел в пользу расширения — отдельный план и ADR.
