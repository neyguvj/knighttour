# План 26. Разрез доски пополам со склейкой по связности (cut & paste): ценз движка половин

## Статус

Закрыт (2026-10-23) как направление счёта: вердикт ценза — **NO-GO**, ADR-043 «отклонено».
Гипотеза пика опровергнута измерением на всех точках: `layerPeakHalf` не ниже, а выше пика
целодосочного frontier DP (5×5 Paths — 3 783 962 против 165 568, ×22,9; 6×6 Cycles — 5 479 689
против 1 467 072, ×3,7; на 6×6 Paths счёт обрывается, не доходя до склейки, при 126 790 469 живых
записей — уже выше целодосочного пика). Предсказанный пик 8×8 — от ~1 ТБ (демпфированная модель)
до десятков ТБ при пороге ~28 ГБ; порог нарушен даже моделью нулевого роста. Причина: спаривание
пеньков шва мультипликативно умножается на профиль внутреннего окна в каждом ключе. Условный шаг
`zigzag` не заводится — отставание не «порядок и меньше», а полтора–три порядка, и от формы шва
множитель не убирается. Пакет `split` и ценз остаются в `main` как инструмент (прецедент ADR-040).

Рядом открывались два независимых плана, наследующих формализм σ из этого файла как цитату:
план 27 (произведение ZDD половин через шов, доработка ядра `zdd`) и план 28 (матрица N(s,t) поверх
reversal-конвейера). Их файлы — в своих worktree; движки независимы, общий только формализм
интерфейсного состояния. Числа ADR-043 касаются движка половинного DP; судьба планов 27/28 — за
их собственными замерами.

## Мотивация и базовые числа

Дорожная карта закрыла 8×8 по всем рассмотренным ветвям, каждая — числами:

- reversal — по времени: нижняя граница count-фазы 331 сутки на d=14 и 519 суток на d=15 при пике
  6 ГБ (ADR-036);
- послойный frontier DP — по памяти: счёт Paths 8×8 требует ≈4,7·10¹³ состояний, 2–4 ПБ (ADR-038);
  измеренные пики состояний: 5×5 Paths — 165 568, 6×6 Cycles — 1 467 072, 6×6 Paths — 108 642 911;
- ZDD — по памяти: доминирует таблица мемоизации (≈29 Б на запись после ADR-041); полная постройка
  6×6 `Paths narrow` — 250 059 810 записей при ширине разреза 12, а детерминированный прогон 7×7
  оборвался на 787 806 693 записях под потолком `22<<30` (ADR-040, ADR-042); ширины narrow-порядка
  досок 5–8 — 6/12/14/16.

Общий корень отказа frontier DP и ZDD: послойный обход проходит через середину доски, и состояние
несёт связность обеих половин одновременно. Разрез пополам с независимым счётом половин этот
множитель снимает: половины считаются отдельно, а их связность проверяется один раз при склейке —
по композициям спариваний шва.

Стенд замера потенциала — тот же, что у всех цензов: Apple M4 Max (14 ядер), 36 ГБ. Эталонные числа
для сверки — `docs/requirements.md`.

## Формализм σ (канон для планов 27 и 28)

Доска N×N, вершины V разрезаны вертикалью по колонкам: L = {col < c}, R = {col ≥ c}; шов
E× — рёбра коня с концом в каждой половине. Для прямого сбалансированного разреза (c = ⌈N/2⌉) число
рёбер шва ровно 6N−8: колонки (c−1,c) дают 2(N−2) ребра, а колонки (c−2,c) и (c−1,c+1) — по 2(N−1).
Это 22/28/34/40 рёбер для досок 5–8.

**Интерфейсное состояние половины** H ∈ {L,R} относительно множества рёбер X, образующего
гамильтонов путь или цикл:

- `S ⊆ E×` — использованные рёбра шва;
- `M` — совершенное спаривание терминалов T_H: пеньков (концов рёбер S в вершинах половины) плюс
  локальных глобальных концов пути; фрагменты пути внутри половины покрывают её вершины дизъюнктными
  путями, концы этих путей — ровно терминалы; преждевременный цикл запрещён;
- `ε ∈ {0,1,2}` — число глобальных концов пути в половине (для Cycles ε = 0). Позиции концов в σ не
  входят: их суммирует DP половины, в σ попадает только счётчик. Величина |S| + ε обязана быть чётной.

`N_H(σ)` — число множеств рёбер внутри H, реализующих σ; считается послойным frontier DP по половине.

**Склейка.** Половины разделяют одно S. Вспомогательный граф G_σ: вершины — рёбра S плюс два внешних
маркера глобальных концов; рёбра — пары спариваний M_L и M_R (шаг альтернирует половины). Тогда
объединение половин — один гамильтонов путь (цикл) тогда и только тогда, когда G_σ связен; для
Cycles это эквивалентно тому, что композиция-перестановка τ_L ∘ τ_R на S имеет одну орбиту. Итог:

```
total = Σ_{σ_L, σ_R совместимы} N_L(σ_L) · N_R(σ_R),
        совместимость = равные S, для Paths ε_L + ε_R = 2 и связный G_σ
```

что и записано кратко как Σ_σ N_L(σ)·N_R(σ̄) для комплементарного состояния σ̄.

**Конвенция счёта** (как в планах 07 и 23): движок перебирает множества рёбер, каждый тур входит
один раз независимо от направления; сравнение с направленными эталонами — умножением на 2 для обоих
семейств. Сверка: Paths×2 = 1 728 / 6 637 920 / 165 575 218 320 и Cycles×2 = 0 / 19 724 / 0 для
досок 5×5/6×6/7×7.

**Зеркало.** Для чётных N отражение доски по вертикальной средней линии переводит разрез в себя и
меняет половины местами: N_L(σ) = N_R(ρσ). Достаточно посчитать одну таблицу и отобразить σ при
склейке — время и память половинного счёта вдвое меньше. Для нечётных N половины несравненны
(⌈N/2⌉ и ⌊N/2⌋ колонок), зеркало неприменимо.

## Идея / Гипотеза

Измеримое утверждение: для каждой доски 5–7 послойный пик состояний DP половины ниже пика состояний
целодосочного frontier DP той же доски минимум на порядок (сверяемые точки ADR-038: 165 568 /
1 467 072 / 108 642 911), потому что состояние несёт связность только одной половины, а пик по слоям
половины — сумма внутренних окон вдоль длинной оси и живых пеньков шва, но не их произведение через
всю доску. Экстраполяция по измеренной последовательности 5–7 с удержанием якоря 7×7 (методология
ADR-040) предсказывает полный счёт 8×8 разрезом в пике ≤ ~28 ГБ и за время < 30 суток на стенде
36 ГБ. Пороги продолжения — те же, что у плана 23; не выполнен любой — план закрывается числами
(ADR-вердикт NO-GO), пакет остаётся в `main` как инструмент (прецедент ADR-040).

## Корректность

- DP половины переживает множество рёбер H со степенями ≤ 2, без преждевременных циклов и с
  терминалами ровно σ; склейка проверяет единственное оставшееся условие глобальности — связность.
  Каждый гамильтонов путь (цикл) доски представим ровно одной парой совместимых состояний, итог точен.
- Переполнение uint64 частичных весов в рантайме не контролируется: веса состояний половины — это
  числа полуконфигураций, они не ограничены сверху итогом доски. Свидетельство достаточности —
  метрика `maxWeight/op` ценза и жёсткая сверка итога с эталонами (перевес виден как расхождение).
- Детерминизм: DP однопоточное, склейка идёт по каноническому обходу таблиц — счётчики и итог
  воспроизводимы бит-в-бит между процессами, плавает только wall-время (прецедент `BenchmarkZDDCensus`).

## Дизайн движка ценза

Новый пакет `split` — standalone-измеритель вне CLI и конвейера reversal (роль как у `zdd`,
ADR-040): контракт — `specs/split.md`. Компоненты:

1. **Геометрия разреза.** Сбалансированный вертикальный разрез c = ⌈N/2⌉; доска коня — из пакета
   `graph`; нумерация пеньков по сторонам, шов — 6N−8 рёбер.
2. **DP половины.** Послойный frontier DP вдоль длинной оси половины (строками сверху вниз): слой —
   строка половины; активное внутреннее окно ≤ 5 строк × ⌈N/2⌉ колонок плюс живые пеньки шва с метками
   спаривания и счётчиком концов. Две живые таблицы поколений, ключ упакован, веса uint64.
3. **Склейка.** Таблица второй половины индексируется группами по S; для каждой пары одной группы —
   проверка связности G_σ за O(|S|); итог Σ N_L·N_R по совместимым парам.
4. **Варианты шва:** `straight` — прямой сбалансированный разрез; `mirror` — он же с D4-сжатием
   (одна таблица на обе половины, только чётные N). Опциональный шаг — `zigzag`: разрез,
   минимизирующий |E×|; включается только если прямой шов не обещает GO (см. «Шаги», шаг 5).

Ценз `BenchmarkSplitCensus` (`split/census_test.go`): точки `size{N}/{paths|cycles}/{straight|mirror}`,
таблица точек в коде, отбор фильтром `-bench`, переменных окружения нет (ADR-020); тяжёлые точки под
`flock ../kt-bench.lock`; peak RSS через `internal/memtest`. Метрики и методология —
`specs/benchmarks.md` §«Ценз разреза пополам со склейкой».

## Аллокационный бюджет

Множителя воркеров нет: ценз однопоточный. Копий доски нет; состояние живёт только как ключ таблицы
(та же дисциплина, что у `frontier`/ADR-038 и `zdd`).

- Таблица поколений DP половины: запись = упакованный ключ + вес uint64. Ключ — профиль внутреннего
  окна (≤ 5⌈N/2⌉ активных клеток: степень и метка фрагмента) плюс метки спаривания живых пеньков
  (до 6N−8 на 8×8 — 40). Оценка ключа на 8×8 — 2–4 слова uint64, запись 24–40 Б; открытая адресация
  при заполнении ≤ 0,75 — ≈32–53 Б на состояние; транзиент роста ×2 (пара массивов при удвоении).
  Пик: `max_layer_states × Б/запись`, точные Б/запись снимаются цензом как отношение резидента к
  числу состояний.
- Итоговые таблицы σ: |Σ_L| + |Σ_R| записей той же раскладки, обе резидентны на склейке.
- Склейка: индекс групп по S — O(|Σ_R|) дополнительно; проверяемых пар Σ_S |L_S|·|R_S| — метрика
  `joins/op`, время склейки публикуется отдельно от DP.

Проверка порога идёт по байтовому бюджету (зарезервированные байты и peak RSS), а не по числу
состояний, как в ADR-040: раскладка фиксируется измерениями на 5–7, прогноз 8×8 — перенос измеренной
цены состояния на экстраполированное число состояний.

## Этап ценза — точки, метрики, пороги

Точки: доски 5×5/6×6/7×7, семейства Paths и Cycles, варианты straight всегда, mirror для чётных N.
Сверка итога жёсткая: `Paths × 2` и `Cycles × 2` обязаны точно совпасть с эталонами
`docs/requirements.md`, расхождение — падение бенчмарка через `b.Fatalf`. Память ограничена мягким
байтовым потолком с ошибкой `ErrOverCap` вместо OOM (механика ADR-038/040); обрыв публикуется как SKIP
с прогрессом, и прогресс обрыва служит якорем нижней границы, если 7×7 не достраивается (приём
ADR-040/042).

Публикуемые метрики: |Σ| по половинам (`sigmaL/op`, `sigmaR/op`), послойный пик состояний DP
половины (`layerPeakHalf/op`), проверяемых пар на склейке (`joins/op`), время DP и склейки,
`maxWeight/op`, `peakRSS_MB/op`.

Пороги вердикта (решение оператора, пороги плана 23): предсказанный пик 8×8 ≤ ~28 ГБ **и** проекция
времени < 30 суток по консервативной границе измеренной последовательности. Экстраполяция — по
измеренным состояниям и цене состояния с удержанием якоря 7×7; сравнение базы — пики frontier DP
ADR-038 и байтовые модели ADR-040/041.

## Шаги

1. Спека пакета `specs/split.md`, методология ценза в `specs/benchmarks.md`, строка в индекс
   `specs/README.md` — этот план и есть фаза 1. Цель Makefile `bench-split-census` по контракту из
   `specs/benchmarks.md` — за кодером.
2. Ядро `split`: геометрия разреза, DP половины со спариваниями пеньков, склейка по композициям;
   мягкий потолок `ErrOverCap`. Тесты: оракул-перебор на малых досках, эталоны 5×5 (оба семейства) и
   6×6 Cycles в юнит-бюджете `-race`, тождество mirror ≡ straight на чётных, детерминизм счётчиков,
   обрыв по заниженному потолку. Зелёный `make check`.
3. Ценз `BenchmarkSplitCensus` с метриками и таблицей точек; прогон 5–7 под `flock ../kt-bench.lock`,
   по точке на процесс (честный peak RSS).
4. Экстраполяция на 8×8 по измеренной последовательности с якорем 7×7; сравнение вариантов шва;
   вердикт по порогам — в ADR-043 (заводит benchmarker).
5. Условный шаг `zigzag`: если прямой/зеркальный разрез не достигает порогов, но отставание —
   порядок и меньше, замерить разрез с минимальным |E×| (зигзаг) и пересмотреть экстраполяцию; только
   после него — окончательный вердикт.
6. Закрытие: NO-GO → план помечается закрытым, ADR-043 «отклонено» с числами ценза, пакет `split`
   остаётся в `main` как измерительный инструмент (прецедент ADR-040). GO → полный счёт 8×8 отдельной
   фичей со сверкой Paths × 2 = 19 591 828 170 979 904 и Cycles × 2 = 26 534 728 821 064; формализм σ
   к тому времени уже процитирован планами 27/28.

## Метрики успеха

- Корректность: `Paths × 2` и `Cycles × 2` на 5–7 совпали с эталонами точно (жёстко).
- Гипотеза пика: послойный пик половины ниже пика состояний frontier DP той же доски минимум на
  порядок на всех измеренных точках.
- Вердикт: предсказанный пик 8×8 ≤ ~28 ГБ и время < 30 суток (порог продолжения); иначе — закрытие
  числами в ADR-043.

## Риски

- **|Σ| экспоненциален по ширине шва** (6N−8 рёбер на 8×8 — 40): метод живёт только если достижимых
  σ с учётом степеней и связности на порядки меньше геометрического верха. Митигция: ценз измеряет
  |Σ| напрямую до любой ставки на 8×8; откат — не мержить ветку (ADR-021), пакет остаётся инструментом.
- **Пик DP половины может сесть у нижних слоёв**, где внутреннее окно уже пусто, а спаривания пеньков
  полны: тогда выигрыш над целодосочным DP только в константе. Митигция: послойный профиль публикуется,
  форма кривой видна до вердикта; при плохой форме — шаг `zigzag` с меньшим швом.
- **Склейка квадратична внутри групп по S** (Σ_S |L_S|·|R_S|): группы могут оказаться крупными.
  Митигция: метрика `joins/op` и раздельное время склейки; при перевесе — grouping по канону ρ раньше.
- **Переполнение uint64 частичных весов** не контролируется рантаймом; свидетельство — `maxWeight/op`
  и жёсткая сверка итога (прецедент плана 07).
- Откат — не мержить feature-ветку (ADR-021); переключателя в коде нет.
