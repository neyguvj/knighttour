# План 07. Frontier-based DP (transfer matrix) — альтернатива семейству DFS на доске 8×8

## Мотивация

Оба существовавших тогда конвейера (class mode и reversal) устроены одинаково:
префикс DFS плюс экспонента по дополнению. Стоимость растёт как ~c^q по числу
клеток дополнения q, поэтому 8×8 недостижима — «часы на точку» даже при d=32
(план 05). Frontier-based search (столбцовая DP со связностями, известная также
как plug DP) меняет сам класс сложности: экспонента зависит только от ширины
фронтьеры — это O(1) колонок, — а рост линеен по числу клеток. Это единственный
известный подход, где 8×8 стоит минут, а не часов.

## Идея

Клетки обрабатываются лексикографически, по столбцам. Для каждой уже обработанной
клетки решаем, какие из её коневых рёбер входят в гамильтов путь. Состояние
фронтьеры хранит:

- для каждой активной вершины (она ещё может получать рёбра) — текущую степень
  (0/1/2) и метку компоненты связности частичного решения (partition label);
- заранее запрещены циклы короче полной длины и вершины со степенью больше 2;
- в конце ровно одна компонента, все степени ∈ {1,2}, ровно две вершины степени 1
  для открытого тура и ни одной для замкнутого — он считается отдельно.

Специфика хода коня: ребро из колонки c может уходить в c+1 и c+2, и симметрично
назад. Поэтому фронтьера занимает 2–3 колонки, а активная ширина доходит примерно
до 24 вершин при N=8. Метка состояния — 2 бита степени на вершину плюс метки
разбиения в канонической форме; оценка 16–20 байт на состояние. Хранение —
плоская таблица с открытой адресацией (приём из плана 01) под следующее поколение,
а переход к нему удаляет лишние колонки.

Учёт симметрий D4 в этой схеме не нужен: она и так считает всё за один проход,
а веса стартовых орбит исчезают как концепция.

## Оценки и ожидаемая стоимость

Аналогичные подсчёты для графов, подобных решётке, дают 10^7–10^9 состояний на
шаге при ширине 8. Конь разрежен (степень вершины ≤ 8), но ходы дальнобойны,
поэтому окно шире. Главный риск — разрастание метки разбиения из-за длинных
ходов. Честная вилка: от секунд на 8×8 до «не влезает никуда». Отсюда формат
разведочной реализации.

## Шаги разведки (когда придёт черёд)

1. Реализовать DP для **замкнутых туров** на досках 5×5/6×6; эталонные числа есть,
   и известные последовательности для 4×N–8×N тоже есть.
2. Замерить пик состояний по шагам на 6×6 и экстраполировать на 7×7/8×8; вердикт
   «вкладывать / закрыть» дописать в этот файл.
3. Только при вердикте «вкладывать»: открытые туры (две вершины степени 1),
   обработка вырожденных случаев, сверка итогов с текущим конвейером
   (5×5/6×6 полностью, 7×7 точечно).

## Риски

- Экспонента по ширине фронтьеры на коневом графе может оказаться неприемлемой
  уже на 8 колонках: ходы ±2 растягивают окно. Варианты борьбы — другой порядок
  обхода и сжатие несвязных компонент.
- Метка разбиения дорога: каждый переход требует канонизации, а состояния лежат
  в плоской таблице; реализация на Go без плотности C++ будет страдать — разведка
  покажет.
- Две степени свободы (открытый и замкнутый тур) вместе с чётностью удваивают
  код; начинать строго с одного варианта.
