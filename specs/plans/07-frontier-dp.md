## Мотивация

Обе существующие трубы (class mode и reversal) — это «префикс DFS + экспонента по
дополнению»: стоимость растёт как ~c^q по числу клеток дополнения q, поэтому
8×8 недостижима («часы на точку» даже при d=32, план 05). Frontier-based search
(столбцовая DP со связностями, «plug DP») меняет класс сложности: экспонента
только по ширине фронтьеры (O(1) колонок), линейно по числу клеток. Единственный
известный подход, где 8×8 — минуты, а не часы.

## Идея

Обрабатываем клетки лексикографически (по столбцам). Для каждойprocessed-клетки
решаем, какие из её рёбер коня входят в гамильтов путь. Состояние фронтьеры:

- для каждой «активной» вершины (ещё может получать рёбра) — текущая степень
  (0/1/2) и компонентсвязности частичного решения (partition label);
- запрет раньше времени: циклов короче полной длины, вершин степени >2;
- в конце: ровно одна компонента, все степени ∈ {1,2}, ровно две вершины
  степени 1 (открытый тур) или ноль (замкнутый — отдельно).

Специфика хода коня: ребро из колонки c может уходить в c+1 и c+2 (и симметрично),
поэтому фронтьера = 2–3 колонки ⇒ активная ширина до ~24 вершин при N=8.
Метка состояния: степень 2 бита/вершина + partition labels (canonical form) —
оценка 16–20 байт на состояние, хранение — плоская таблица (открытая адресация,
приём из плана 01) следующего поколения; переходы — редукция «лишних» колонок.

Канцелирование D4 доски в этой схеме не нужно — она и так считает «всё за один
проход»; веса стартовых орбит исчезают как концепция.

## Оценки и ожидаемая стоимость

Аналогичные подсчёты для grid-подобных графов дают 10^7–10^9 состояний на шаге
при ширине 8; конь разрежен (deg ≤ 8, но «дальнобоен» — шире окно). Главный
риск — разрастание partition-метки из-за длинных ходов. Честная вилка: от
«секунды на 8×8» до «не влезает никуда». Отсюда формат spike.

## Риски

- Экспонента по ширине фронтьеры на коневом графе может оказаться неприемлемой
  уже на 8 колонках (ходы ±2 растягивают окно; варианты борьбы — другой порядок
  обхода, сжатие несвязных компонент).
- Partition-метка дороги: нужны канонизация на каждом переходе и плоская таблица
  состояний (в Go-реализации без C++-плотности будет больно) — spike покажет.
- Пересылка: две степени свободы (открытый/замкнутый) × чётность — удвоение кода;
  начинать строго с одного варианта.
