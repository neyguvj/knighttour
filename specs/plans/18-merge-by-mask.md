peak RSS −≥25%, wall ≤+5%.

## Мотивация и базовые числа

Task-cache хранит по записи на каноническую **пару** `(state, end)`: число записей равно числу
различных канонических пар, а это — суммарное по маскам число **классов концов** (концы одной маски,
не связанные стабилизатором маски, дают отдельные записи). Каждая такая запись в swiss-слоте Go
платит полный ключ `path.Path` (16 Б: state повторяется в каждой записи одной маски) + 8 Б значения
+ метаданные ⇒ **27–28 Б/запись** (ADR-003), при этом lookup `completions()` суммирует
`h(U,u)` по `u ∈ N(t)∩U` — все классы концов одной маски нужны одновременно, т.е. раздельные
записи общей маски читаются пачкой соседних `Get` с дублированием ключа.

База чисел — локальный main `b62a6a8`, точка **7×7 d22, workers=14** (`make bench-size N=7
DEPTHS=22`, Apple M4 Max 14 CPU, GOGC 40 конвейером): полоса контроля планов 16/17 — wall
**175–180 с**, `genB_ms` **~108–112 с**, `cnt_ms` **~66–68 с**, peak RSS **5.16–5.31 ГБ**,
`taskEntries` **92 315 032** (записей-пар после L2-гейта, ADR-030), `writesB` 942 644 146,
итог 165 575 218 320. Свежий контроль main ×2 перед стендом обязателен (дневной дрейф — прецеденты
планов 13/15/16).

## Идея / Гипотеза

Одна запись на каноническую **маску** `K`, значение — гистограмма «класс конца → W» (вклады те же
аддитивные, что сейчас). Число записей падает с `Σ_K k(K)` до `#масок` (`k` — число классов концов
маски), байты таблицы — с `27·k̄` до `≈ 18.3 + 8.6·k̄ Б/маску` (расчёт в «Аллокационном бюджете»).
Гипотеза: при среднем числе классов `c̄ ≥ 1.5` peak RSS конвейера падает **на ≥25%** при регрессе
wall **≤5%**; hot-lookup не дорожает (один `Get` на маску вместо одного на конец, стоимость
переезжает в свод класса и скан гистограммы).

Ключевой неизвестный определяет жизнеспособность: реальное распределение `k(K)` на таблице 7×7.
При `c̄ < 1.5` — план закрывается (Этап 0, гейт ниже).

## Корректность

- **Математика классов.** Для маски `K` стабилизатор `Stab(K) ⊆ D4` действует на клетки `K`;
  пары `(K,e)`, `(K,e')` лежат в одной D4-орбите пар ⟺ `∃t ∈ Stab(K): te = e'`. Число классов
  концов маски — в точности число её нынешних канонических записей (слияние не меняет
  разбиение, а упаковывает его). `h(K,e)` — геометрический инвариант, постоянен на классе;
  `orbitSize(K,e) = 8/|Stab(K,e)|` тоже постоянен (стабилизаторы сопряжённых концов равны) и
  вычислим из `perms`-таблицы на чтении — **хранить не обязательно**.
- **Итог бит-идентичен.** `f` постоянна на классе (`f(gK,ge)=f(K,e)`), поэтому задачи
  `(K, r, W_r)` (r — репрезентант класса) дают тот же целый `Σ W·f`, что нынешние пары:
  `W_r = Σ_{e∈class r} W_(K,e)`, деление `W_r / orbitSize(K,r)` точно (обобщение точности
  ADR-011 с попарного ключа на класс).
- **Лемма гейта записи (ADR-030) переносится**: предикат `ShouldPruneState` вычисляется до
  канонизации и D4-эквивариантен, «мёртвый ключ никогда не запрашивается» — свойство орбиты;
  мёртвые классы не пишутся и не запрашиваются, тождество итога сохранено.
- **Tie-break исключён конструктивно.** `K` = минимум преобразованных масок; при нетривиальном
  стабилизаторе минимум маски достигается несколькими кадрами `t`, но сведение конца к
  репрезентанту класса (минимум орбиты `Stab(K)`) поглощает эту неоднозначность: результат не
  зависит от выбора кадра. Писатель и читатель вызывают **одну и ту же** функцию symmetry —
  рассогласование невозможно по построению, плюс юнит-тест равенства на случайных парах.

## Дизайн

**Формат записи.** `key = K (state.State, чистый uint64; end ∈ mask всегда — информации не теряется,
включая 8×8)`, `value = гистограмма класс→W`. Упаковка значения — два кандидата (выбор по данным
Этапа 0):

- **(a)** `map[uint64]inline-вектор`: `{count; пары [kcap]uint64}`, пара упакована `(rep:8 | W:56)`
  (`W < 2^56` — запас против `writesB ~ 1e9`); `kcap` = p95 из Этапа 0, переполнение — spill в
  боковой целочисленный слайс (указатель в значении ломает pointer-free слот — решение по данным).
- **(b)** «как сейчас, но записи склеены»: `map[path.Path]uint64` остаётся (слот ADR-003 не меняется),
  значение несёт `(offset:32 | count:32)` в append-only слайс упакованных W по маскам.

**Писатель (`dfsTask`).** На листе: `TransformStates(st)` → `K = min`, кадр `t*`, множество
`Stab(K) = {t: states[t] == K}` (всё уже в руках); конец `c = perms[t*][end]`, сведение `c` к
репрезентанту класса (мин по орбите `Stab(K)`), аддитивный вклад W. Пер-энд работа — один подсмотр
в `perms` + малый скан; цикл уникальности `orbitSize` из `CanonicalFromStates` с листа уходит.
Degenerate self-write `ExtendTask` проходит тот же путь.

**Читатель (`completions`).** Тот же фрейм: `TransformStates(unvisited)` один раз, `K`, `t*`,
`Stab(K)`; далее по `u ∈ N(t)∩U`: реп класса `r(u)`, **один** `Get(K)` на маску (можно с
одноэлементным стековым кэшем повтора), в гистограмме — W класса, ответ `+ W/orbitSize(K,r)`
(деление точное, orbitSize считается из `perms`).

**Роль задач не меняется.** `View.All`/диспатч разворачивает запись обратно в задачи `(K, r, W_r)`;
`entryBatch` и формулы K/B/C пересчитывают размер элемента (Path 16 Б → маска 8 Б + rep + W),
механика ADR-032/033 дословна. Обе роли `Cache` (промежуточная gen A и task-cache) — общий тип,
формат меняется у обеих; worklist gen A материализуется развёрнутыми классами (число задач gen B
падает вместе с записями).

**Симметрия — новый API** (эскиз): `CanonicalMaskFrame(st) (K state.State, frame uint8, stab
mask)` + `ClassRep(stab, cell) int` + `CellOrbitSize(stab, cell) int` — всё по `perms`, без аллокаций.

## Аллокационный бюджет

На маску (`k` классов), против нынешних `27·k` Б:

| раскладка | Формула Б/маску | k=1 | k=2 | k=3 |
|---|---|---|---|---|
| сейчас (пара-записи) | `(16+8+1)/0.93 · k` | 27 | 54 | 81 |
| (a) inline-вектор | `(8 + V(k) + 1)/0.93`, `V = 8·(1+k)` по слову | ~27 | ~35.5 | ~44 |
| (b) slot+slab | `27 + 8k` | 35 | 43 | 51 |

Расчётные сбережения таблицы при однородном `k`: −23% при k=1.5, −34% при k=2 (раскладка (a)).
Пик RSS ≈ live×~1.4 (GOGC 40) и доминируется таблицей ⇒ для гейта −25% по пику нужно `c̄ ≳ 1.7`
или благоприятное («длиннохвостое») распределение — Этап 0 публикует прогноз до кода. Новых копий
таблицы нет; диспатч остаётся безаллокационным на запись (размер батч-элемента пересчитывается).

Итерация 2 (вариабельная упаковка: тег-слово + slab `cap(k)=2^⌈log₂k⌉` + рециклинг корзин),
оценки по гистограмме классов Этапа 0 (`work/18-merge-by-mask/hist_d2{0,1}.csv`): точный
copy-on-append без запаса и рециклинга платит Σⱼ₌₂^k j слов на запись — в сумме ≈5.3 слова/маску
на d21 (≈4.9 слова/маску на d20), т.е. таблица ужимается лишь на ~10–15% — гейт −25% по пику с
такой ценой переездов недостижим, отсюда ёмкость-запас и корзины. Выбранная раскладка: верхняя
оценка (корзины попадают всегда) slab = Σ cap(k) ≈ 2.6 слова/маску на d21 ⇒ ≈39 Б/маску против
базы 66.9 (−42% таблицы); нижняя (переезды без попаданий, Σ(2·cap−2)) ≈ 3.8 слова/маску ⇒
≈49 Б/маску (−27%). Доля попаданий в корзины — наблюдаемый риск, публикуется стендом через
`peakRSS_MB/op`. Маски k=1 slab не трогают вовсе; утечки за пределы slab нет (append-only +
переиспользование, карта pointer-free).

## Риски

- **Удорожание горячего lookup** (сведение класса + скан гистограммы вместо одного map-hit) →
  mitigation: один `Get` на маску вместо per-end, реп ≤8 подсмотров в `perms`, стековый кэш повтора;
  гейт `cnt_ms`/wall.
- **Длинный хвост k и процент попаданий в корзины** (цена переездов, итерация 2) → ёмкость
  `cap(k)` степенью двойки + рециклинг блоков того же класса; фактическую цену slab покажут
  `peakRSS_MB/op` стенда; маски k=1 остаются однословным значением без slab.
- **Рассогласование tie-break писателя/читателя** → одна общая функция symmetry + юнит-тест равенства;
  сведение к репрезентанту класса делает кадр-амбигуитет неустранимым источником расхождения.
- **Рост значения против числа записей** (k=1 маска в (a) стоит как пара, а не вдвое дешевле) →
  формула break-even выше; Этап 0 прогнозирует по реальному распределению, а не по среднему.
- Формат меняется у обеих ролей `Cache` (gen A тоже) — размер worklist/батчей синхронно; ошибки —
  класс тестов шага 4.
- Откат = не мержить feature-ветку (ADR-021); переключателя в коде нет и не заводится.
