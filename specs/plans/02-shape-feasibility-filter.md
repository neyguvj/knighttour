## Мотивация и базовые числа

На 7×7 d22 финальный проход считает `h` для 68 379 933 форм, из них
**44 930 025 (65.7%) дают `h == 0` по всем концам** — то есть большинство времени DP
тратится на формы, заведомо не дающие вклада. Время counting: 371 с из 596 с прогона.

Распределение по глубинам (там же): zeros/shapes = 61.7% (d20), 65.7% (d22),
68.6% (d24), 50.2% (d16).

## Что заведомо НЕ поможет (зафиксировать, чтобы не пробовать снова)

**Цветовой паритет.** Граф ходов коня двудомный, и путь, покрывающий `U`, требует
`|black − white| ≤ 1`. Но `U` — дополнение легального префикса длины `d`: префикс сам
чередует цвета, поэтому дисбаланс цветов дополнения всегда ≤ 1 при любом легальном
префиксе. Фильтр не сработает никогда — это же объясняет «0 срабатываний» из README
(там проверялось на генерации, аргумент тот же).

**Повторять проверки связности и степени «ещё раз, до DP».** `CountShape` вызывает
`ShouldPruneAfterVisit(cur, todo)` на входе в рекурсию (shapecount/shapecount.go:181),
а тот делает flood-fill по `G[todo]` со счётчиком вершин степени 1
(pruner/pruner.go:68). Значит связность и «>2 вершин степени 1» уже проверяются до
первого рекурсивного шага, и форма, мёртвая по этим причинам, стоит один проход по
маске, а не полное DP. Экономия от дублирования — только ×(число концов) ≈ 2.57.

Следовательно смысл имеет только то, что **сильнее** текущего набора проверок.

## Дизайн

### Этап 0 — измерение (без него план дальше не идёт)

Инструментировать финальный проход на реальном распределении форм и посчитать, как
разбиваются нули:

1. `dead-at-root` — отсёкся текущим `ShouldPruneAfterVisit` на первом же вызове DP;
2. `articulation-3+` — удаляется вершина, остаётся ≥ 3 компонент (сейчас не проверяется);
3. `endpoint-mismatch` — в `G[U]` ровно две вершины степени 1, и фиксированный конец `u`
   среди них отсутствует;
4. `forced-cycle` — цепочки вершин степени 2 замыкаются в цикл короче `|U|`;
5. `deep` — структурно форма жива, ноль выясняется только после полного перебора.

Инструмент: тест-оболочка/субтест в `shapecount`, принимающий дамп форм (выгрузка из
прогона 7×7 d18–d22 и 6×6 d13; формат — `state uint64` + маска концов), плюс флаг
собранной статистики. Цель — одна таблица «доля нулей по классам» и верхняя граница
выигрыша любого фильтра: она равна сумме долей классов 2–4 (класс 1 уже бесплатен).

Если доля классов 2–4 окажется меньше ~20% от всех нулей — план закрывается выводом в
`specs/shapecount.md`, что дешёвыми проверками нули не берутся, и приоритет смещается на
план 03 (переиспользование подзадач).

### Этап 1 — фильтры, не стоящие лишних проходов

Реализуются внутри уже существующего flood-fill'а прунера, без нового обхода графа:

- **Filter A (`endpoint-mismatch`).** Flood-fill считает `deg1Mask` и `deg1Count`;
  при `deg1Count == 2` добавляется проверка «фиксированный конец ∈ deg1Mask» (для задачи
  `h(U,u)` конец зафиксирован, в отличие от генерации, где важна смежность с `last`).
  Стоимость — пара побитовых операций на уже посчитанной масске.
- **Filter B (`forced-cycle`, частичный).** Вершины степени 2 обязательны: их два инцидентных
  ребра обязаны быть в пути. Прогон цепочек обязательных рёбер и детекция замкнутого
  цикла длины < |U| — O(|U|) по тем же степеням.

### Этап 2 — сочленения (Tarjan), только если этап 0 показал спрос

- **Filter C (`articulation-3+`).** necessary condition: для любой вершины `v` графа
  `G[U]` удаление `v` оставляет не более 2 компонент (иначе гамильтов путь через `v`
  не проходит). Реализация — lowlink за один обход по битовым маскам, вызывается
  **один раз на форму** до перебора концов, а не на узел DP.
- Порог включения по `|U|` (например, только для форм от 12 клеток): на мелких формах
  полный DP дешевле проверки.

### Интеграция

- Точка входа — `Counter.CountShape` до создания/использования мемо: отказ по форме
  возвращает нулевой срез и **не** заводит memo-буфер (экономит и время, и память пула).
- Причины отказа считаются отдельно от pruning-статистики DP: новые счётчики в
  `types.Result` (`FilteredShapes`, при необходимости по видам) → разбивка в мониторе и
  метрика `filtered/op` в бенчмарке, чтобы видеть, сколько форм убито и сколько из них
  были бы нулями.

## Риски

- **Ложное отсечение.** Любой фильтр обязан иметь доказательство необходимости условия и
  тест против полного перебора; иначе ответ перестаёт совпадать с эталоном туров.
- **Стоимость Tarjan на больших формах** (d10–d14: |U| = 35–39): проверка может стоить
  дороже, чем DP с хорошим прунингом — отсюда порог по размеру и обязательные замеры.
- **Смешивание статистики.** Фильтр меняет смысл `prunedB/op` (часть ветвей не будет
  достигать прунера) — зафиксировать в мониторинге отдельно, чтобы исторические таблицы
  остались сопоставимы.

## Результаты этапа 0

Инструменты:

```bash
SHAPE_DUMP=/tmp/zeros.txt SHAPE_DUMP_SIZE=6 SHAPE_DUMP_DEPTH=13 \
  go test -run TestDumpZeroShapes ./counter/          # выгрузка нулевых форм
SHAPE_CLASSIFY=/tmp/zeros.txt SHAPE_CLASSIFY_SIZE=6 \
  go test -run TestShapeFeasibilityClassification -v ./shapecount/
```

Для 7×7 — `SHAPE_DUMP_SAMPLE` (держать выборку, файл от 45M нулей огромен).
Классификация: для каждой нулевой формы проверяется, чем убит каждый её конец:
root = текущий `ShouldPruneAfterVisit` на корневом состоянии DP; A — степени 1
в `G[shape]`; B — `forcedChainCut(end, shape∖{end})`; C — `articulationCut`.

6×6 (полные выгрузки; доли от всех нулевых форм):

| класс | d10 | d13 | d16 |
|---|---|---|---|
| dead-at-root | 0.0% | 0.0% | 0.2% |
| articulation-3+ (первый объясняющий) | 3.1% | 4.9% | 9.5% |
| endpoint-mismatch | 0.0% | 0.0% | 0.0% |
| forced-cycle | 52.9% | 48.9% | 57.5% |
| deep | 44.0% | 46.2% | 32.8% |

Кумулятивно (все концы убиты): root∨B = 55.2/52.8/66.1%, root∨C =
3.1/4.9/9.8%, root∨B∨C = 56.0/53.8/67.2%. Прирост C поверх B ≈ 1 п.п. при
полном Tarjan на каждый конец — не окупается, C остаётся опцией
(`SetShapeFilter`). A не срабатывает никогда: доказуемо покрыт корневым L1
(если A убивает конец, то deg-1 вершины `G[shape]` остаются deg≤1 и в
`G[shape∖{end}]`, и эвристика концов/изолированность режет тот же корень) —
измерение подтвердило 0.0% на всех глубинах.

Неожиданная находка: `dead-at-root` ≈ 0 — вопреки допущению «нулевые формы и
так дешевы» (shapecount.md), нули почти не ловятся корневым L1 и сейчас
платят полное DP. Именно поэтому B обещает большой выигрыш: верхняя граница
(доли классов 2–4) = 54–67% нулей, порог плана «≥ 20%» превышен многократно.

Замер 7×7 (d18–d22) оставлен на `bench-deep` стенде; распределение 6×6
стабильно по глубинам d10–d16.

Важное уточнение к «верхней границе»: она считается по ЧИСЛУ форм, а не по
времени. Классы 2–4 умирали бы в DP быстро (прунер догоняет их на первых же
состояниях), поэтому времяперекрытия заметно меньше доли форм — см. замеры.

## Реализация

- `pruner.ShapeFeasible(end, shape, mask)` — A (`L2Endpoints`, только для
  инструментов), B (`L2ForcedChain`), C (`L2Articulation`); specs/pruner.md.
- `shapecount.Counter.SetShapeFilter`, по умолчанию `DefaultShapeFilter =
  L2ForcedChain`; убитый конец не входит в DP, полностью убитая форма не
  заводит memo-буфер; учёт `types.Result.FilteredShapes` → мониторинг
  (`| filtered N`) и бенчмарк (`filtered/op`). Прокинуто сквозь
  `counter.Counter.SetShapeFilter`; A/B в своипе — env `SHAPE_FILTER=off`.
- Тесты: таблица причин + вырожденные формы, вероятностный «нет ложных
  отсечений» против bruteH (pruner), эквивалентность on/off на complements
  прунингованных префиксов и инвариант итогов 5×5/6×6 (shapecount/counter).

## Замеры (6×6, M4 Max, benchtime=3x)

cnt_ms on/off по глубинам: выигрыш 3–9% на d11–d16 и d18, провалы ≤6% на
d8–d10/d17 в пределах межсессионного шума; итог — без регресса, мягкий плюс.

## Вывод

Метрика успеха «≥40% нулей убито до DP» по ЧИЛУ форм перевыполнена (9–11%
всех форм — все нулевые цепочные, чьи концы не добирает корневой L1), но по
ВРЕМЕНИ фильтр даёт 2–3% counting: классы 2–4 гибнут в DP почти у корня и без
него (цепочное противоречие наследуется потомкам состояний). Цель «d22 ≤ 250 с»
недостигнута — время нулей сосредоточено в deep-классе (46–68% нулей), где
структурные проверки бесполезны по построению. Фильтр оставлен включённым по
умолчанию (плюс без регрессов, стоимость ~O(V+E) на конец против DP-спуска),
articulation/endpoint — только опции инструментов. Приоритет сокращения
counting смещается на план 03 (переиспользование подзадач: tail-мемо уже
показывает попадания именно на deep-формах).
