# workerpool: механика фиксированной команды воркеров

## Ответственность

Пакет даёт два примитива параллелизма для фаз конвейера. `Run` собирает команду горутин,
которые снимают индексы задач с общего атомарного счётчика, и не возвращается, пока все
не отработают. `Fanout[T]` передаёт значения от производителя потребителям через один
буферизованный канал и закрывает его после возврата производителя.

Пакет ничего не знает о предметной области: ни таблиц, ни путей, ни монитора. Он не
обрабатывает ошибки — на обслуживаемых путях их не бывает, единственный поток управления
отменён контекстом. Политики фаз остаются у вызывающего: размеры партий, ёмкость канала
и ограничения значений диапазоном. Пакет владеет только запуском горутин, счётчиком
индексов, каналом и барьерами ожидания.

## Публичный API

```go
// Pool — конфигурация команды воркеров: не более workers горутин на один вызов метода.
// Горутины живут внутри одного вызова; между вызовами сохраняется только размер команды.
type Pool struct{ /* workers int */ }

// New возвращает команду объёмом workers горутин на каждый вызов Run.
// workers ≥ 1 — обязательство вызывающей стороны, значение проверяется в main.go.
func New(workers int) *Pool

// Run запускает min(workers, max(n,0)) воркеров и ждёт их завершения (барьер). Каждый
// воркер однократно получает idx — итератор индексов 0..n-1, снятых с общего атомарного
// счётчика (один Add(1) на задачу). Перед каждым снятием проверяется ctx; цикл завершается,
// когда работа исчерпана или контекст отменён. Тело воркера шире тела задачи: подготовка и
// завершение каждой горутины живут в worker вокруг цикла по idx. Отменённый контекст
// прерывает выдачу индексов досрочно — это частичный прогон без паники, а отданный индекс
// повторно не выдаётся. При n ≤ 0 горутины не запускаются вовсе.
func (p *Pool) Run(ctx context.Context, n int, worker func(ctx context.Context, idx iter.Seq[int]))

// Fanout передаёт значения от produce потребителям через один канал ёмкостью max(bufSize,1)
// слотов. consumers горутин дочитывают канал до закрытия; produce выполняется на горутине
// вызывающего сразу после их старта, а по его возврате канал закрывается и Fanout ждёт
// полного дочитывания. Каждый отправленный элемент доставляется ровно один раз в порядке
// отправки (FIFO). Пакет не создаёт производных контекстов — семантика отмены живёт внутри
// produce и consume. T инстанцируется конкретно на фазу: элементы копируются по значению,
// интерфейсов на горячей границе нет. consumers ≥ 1 — обязательство вызывающего;
// bufSize < 1 трактуется как 1.
func Fanout[T any](ctx context.Context, consumers, bufSize int,
    produce func(ctx context.Context, out chan<- T),
    consume func(ctx context.Context, batch T))
```

## Инварианты

- **Run.** Каждый индекс `0..n-1` снят не более одного раза: счётчик на вызов один и общий.
  Контекст проверяется до снятия, поэтому отменённый прогон не забирает индекс, который
  никто не обработает. Барьер `Wait` даёт happens-before для всех побочных эффектов
  воркеров. Между вызовами `Run` состояние не накапливается — счётчик является локальной
  переменной вызова.
- **Fanout.** При соблюдении контракта дедлок невозможен. Производитель блокируется только
  на отправке, а потребитель ничего не ждёт от производителя и дочитывает канал до `close`;
  буфер не меньше одного слота делает это возможным всегда. Закрытие наступает строго после
  возврата `produce`, поэтому всё отправленное к тому моменту гарантированно будет доставлено.
- Пакет не порождает контекстов и не возвращает ошибок: ни один примитив не сообщает об
  ошибке через возвращаемое значение, отказ наблюдается только через переданный ctx.

## Ограничения и edge cases

- `Run` при `n ≤ 0`: горутин нет, `worker` не вызывается вовсе.
- Уже отменённый контекст: воркеры стартуют и сразу выходят — ноль снятых индексов, барьер
  не зависает.
- Досрочный `break` из цикла по `idx` легален: неснятые индексы остаются другим воркерам.
- Пустая продукция в `Fanout`: если `produce` ничего не отправил, потребители видят только
  закрытие канала.
- Отмена контекста не отменяет элементы, уже лежащие в буфере: они будут доставлены.
  Решение не обрабатывать их принимает `consume`, сам проверяя ctx.
- `workers ≤ 0` нарушает контракт: `Run` не запустит ни одной горутины. `Fanout` с нулём
  потребителей навсегда блокирует `produce` на первой отправке — читать каналу некому;
  отрицательное число потребителей паникует в `WaitGroup`.
- Элемент копируется в слот канала и ещё раз при выдаче. Поэтому `produce` не должен
  передавать ссылку на буфер, который потом переиспользует: получатель обязан видеть
  неизменяемую копию момента отправки.

## Тесты

`workerpool/workerpool_test.go` — синтетические тесты без доменных зависимостей, под `-race`.

Run:

- `TestRunClaimsEachIndexOnce` — каждый индекс снят и обработан ровно один раз при
  конкурентной работе (таблица: воркеров больше, меньше и примерно равных числу задач).
- `TestRunStartsClampedCrew` — команда ограничена `min(workers, max(n,0))`; стартовавших
  воркеров засчитываются ровно столько (пустой и отрицательный список задач — ноль).
- `TestRunTerminatedContextProcessesNothing` — таблица «отменён / дедлайн истёк»: частичный
  прогон без паники, ни одного обработанного индекса.
- `TestRunCancellationStopsClaims` — отмена внутри первой задачи: обработан ровно её индекс,
  новых снятий и повторной обработки нет.
- `TestRunBarrierAndCursorReset` — после возврата видны все побочные эффекты; повторный
  вызов на том же `Pool` начинает счёт с нуля.
- `TestRunEarlyBreakReturns` — досрочный `break` не вешает `Run`, остальные задачи остаются
  неснятыми.

Fanout:

- `TestFanoutDeliversExactOnce` — доставка ровно один раз при bufSize {1, 2, 64} и
  consumers {1, 4}; слот ёмкостью 1 создаёт противодавление без дедлока; пустая продукция —
  отдельный кейс. Совпадение проверяется как мультимножество: порядок прихода между разными
  потребителями вне контракта.
- `TestFanoutCancelInProduceDrainsSent` — ранняя отмена в `produce`: доставленное равно
  отправленному, буфер дочитан после закрытия, `Fanout` вернулся.
