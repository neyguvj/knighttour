# workerpool: механика фиксированной команды воркеров

## Ответственность

Два примитива параллелизма фаз конвейера: `Run` — команда горутин с атомарным курсором претензий
на индексы задач и барьером ожидания; `Fanout[T]` — продюсер→консьюмеры поверх одного
буферизованного канала с закрытием по возврате продюсера. Пакет не знает домена (таблиц, путей,
монитора) и не несёт error-обвязки: на обслуживаемых путях ошибок нет, единственный поток
управления — отмена контекста. Политики фаз (размер батча, ёмкость канала, clamp'ы консьюмеров)
остаются у вызывающего — пакет владеет только спавном, курсором, каналом и барьерами.

## Публичный API

```go
// Pool — конфигурация команды воркеров: не более workers горутин на вызов метода.
// Горутини живут внутри одного вызова; состояние между вызовами — только размер команды.
type Pool struct{ /* workers int */ }

// New возвращает команду из workers горутин; workers ≥ 1 — контракт вызывающей стороны
// (валидируется в main.go).
func New(workers int) *Pool

// Run запускает min(workers, max(n,0)) воркеров и ждёт их (барьер). Каждый воркер получает
// idx — итератор индексов 0..n-1, снимаемых общим атомарным курсором (один Add(1) на задачу);
// каждому снятию предшествует проверка ctx, итерация завершается при исчерпании работы или
// отмене. Тело воркера отделено от тела задачи: per-worker инициализация/завершение живёт
// в worker вокруг цикла по idx. Завершившийся ctx — досрочный выход без паники (частичный
// прогон); отданный индекс не выдаётся повторно. n ≤ 0 — воркеры не запускаются вовсе.
func (p *Pool) Run(ctx context.Context, n int, worker func(ctx context.Context, idx iter.Seq[int]))

// Fanout — продюсер→консьюмеры поверх одного буферизованного канала max(bufSize,1) слотов:
// consumers горутин дренируют канал до close; produce вызывается в горутине вызывающего сразу
// после старта консьюмеров; по возврате produce канал закрывается и Fanout ждёт дренажа.
// Каждый отправленный элемент доставляется ровно один раз в порядке отправки (FIFO).
// Пакет не создаёт производных контекстов — семантика отмены живёт внутри produce/consume.
// consumers ≥ 1 — контракт вызывающего (фазовый clamp остаётся у вызывающего); bufSize < 1
// трактуется как 1 — инвариант отсутствия дедлока. T инстанцируется конкретно на фазу:
// элементы канала копируются по значению, никаких интерфейсов на горячей границе.
func Fanout[T any](ctx context.Context, consumers, bufSize int,
    produce func(ctx context.Context, out chan<- T),
    consume func(ctx context.Context, batch T))
```

## Инварианты

- **Run**: каждый индекс `0..n-1` снят не более одного раза (общий атомарный курсор на вызов);
  проверка ctx — до снятия, поэтому отменённый прогон не потребляет индекс, который не будет
  обработан. Барьер Wait даёт happens-before на все побочные эффекты воркеров; состояние между
  вызовами `Run` не накапливается (курсор — локальная переменная вызова).
- **Fanout**: отсутствие дедлока при контракте — продюсер блокируется только на отправке,
  консьюмер ничего не ждёт от продюсера и всегда дренирует до `close`; буфер ≥ 1 слота делает это
  возможным всегда. `close` наступает строго после возврата `produce`, поэтому «каждая запись
  доставлена ровно один раз» при единственном продюсере — контракт, переносимый на фазу-вызывателя.
- Пакет не порождает контекстов и не возвращает ошибок: ни у одного примитива нет error-борн
  барьера; отмена наблюдается только через переданный ctx.

## Ограничения и edge cases

- `Run`: `n ≤ 0` — ноль горутин, `worker` не вызывается; завершившийся до вызова ctx — воркеры
  стартуют и сразу выходят (ноль снятых индексов, барьер не виснет). Досрочный выход воркера из
  цикла по `idx` (`break`) легален: неснятые индексы остаются другим воркерам.
- `Fanout`: пустая продукция (`produce` ничего не отправил) — консьюмеры получают только `close`;
  завершившийся ctx не отменяет уже лежащие в буфере элементы — они доставляются (дренаж), а
  «не считать их» решает consume проверкой ctx.
- `workers ≤ 0` нарушает контракт: `Run` не запустит ни одной горутины; `Fanout` при
  `consumers ≤ 0` может заблокировать `produce` навсегда (дренировать некому).
- Элемент канала копируется в слот и на выдаче — в T нельзя передавать ссылку на переиспользуемый
  продюсером буфер (получатель обязан видеть неизменяемую копию момента отправки).

## Тесты

`workerpool/workerpool_test.go` (синтетика без доменных зависимостей, под `-race`):
Run — clamp `min(workers,n)` (наблюдаемый максимум конкурентно работающих воркеров), каждый
индекс ровно один раз при конкурентном съёме, `n ≤ 0` — worker не вызывается, завершившийся ctx
(отмена и дедлайн — таблица) — досрочный выход без паники и без повторной обработки (префикс),
барьер (побочные эффекты видны после возврата; повторный вызов считает курсор с нуля), досрочный
`break` воркера не вешает `Run`. Fanout — exact-once доставка при bufSize {1,2,big} и
consumers {1,4} (bufSize = 1 — принудительный backpressure без дедлока), пустая продукция,
ранняя отмена ctx в produce: доставленное равно отправленному (дренаж буфера после close),
`Fanout` возвращается.
