# cache: единая таблица «ключ → вес», протокол «write → seal → read»

## Ответственность

Потокобезопасная аддитивная таблица весов `path.Path → uint64` — единственная реализация
«шардированного словаря» алгоритма. Один и тот же тип `Cache` играет обе роли пайплайна:
промежуточная таблица gen A (короткоживущая, после `Seal` обходом `View.All` материализуется в
worklist фазы B) и task-cache (живёт до конца count-фазы). Чтение — только через запечатанную
ручку `*View`, получаемую на фазовом барьере (`Seal`); второго типа таблицы нет (ADR-018).
Второй тип здесь — не таблица, а писатель: `Staging` — батч-ручка записи в `Cache` (ADR-031),
данных не хранит.

Нули не хранятся: запись создаётся только при положительном вкладе. Пакет ничего не знает о
симметриях — канонизацию выполняет писатель/читатель (ADR-005). Фаз пакет тоже не знает:
`Seal` вызывает контур-владелец в точке, где все писатели остановлены.

## Публичный API

```go
type Entry struct { Path path.Path; Weight uint64 } // одна запись таблицы; worklist-элемент фазы B

func NewCache() *Cache // 128 шардов map[path.Path]uint64 под Mutex (лок писателей)

// Sink — сторона записи таблицы; реализуют *Cache (прямая запись) и *Staging (батч-запись).
type Sink interface {
    Set(p path.Path, weight uint64) // аддитивный вклад data[k] += weight; weight == 0 — no-op
}

// Set — аддитивный вклад: data[k] += weight. weight == 0 — no-op (нулей в таблице нет).
func (c *Cache) Set(p path.Path, weight uint64)

// NewStaging — батч-писатель одной горутины поверх c (ADR-031): эмиссии буферизуются
// по шардам и сливаются под одним Lock задетого шарда на флеш. Не потокобезопасен:
// один Staging — одна пишущая горутина. limit ≥ 1 — авто-флеш при накоплении;
// Flush — явная граница видимости (вызывается на выходе писателя).
func (c *Cache) NewStaging(limit int) *Staging

func (s *Staging) Set(p path.Path, weight uint64) // в буфер по индексу шарда; weight == 0 — no-op
func (s *Staging) Flush()                         // сложенные вклады каждого непустого шарда под его Lock

// View — иммутабельная ручка чтения запечатанной таблицы; создаётся только Cache.Seal.
type View struct{ /* поля скрыты */ }

// Seal — барьер чтения «write → seal → read» (план 16): возвращает безлоковую ручку чтения.
// Предусловие (контракт вызывающего контура, не тип): на момент Seal и всё время жизни
// всех View писателей (Set/Flush) нет — они остановлены барьером, дающим happens-before
// (errgroup.Wait, завершающий Staging.Flush). Повторный Seal даёт независимую ручку той же
// таблицы. Нарушение предусловия — data race по контракту.
func (c *Cache) Seal() *View

// Get — прямой map-lookup без локов; miss → (0,false). Конкурентные View безопасны.
func (v *View) Get(p path.Path) (uint64, bool)

// Len — число записей таблицы; постоянно после `Seal` (писателей больше нет).
func (v *View) Len() int

// All — pull-обход всех записей без локов и без копирования таблицы: отдача идёт из живых
// map под предусловием Seal. Порядок — по номерам шардов 0..127 (внутри шарда — порядок Go
// map); ctx проверяется между шардами, отмена останавливает обход на следующей границе;
// break потребителя = частичный обход, не ошибка. Источника ошибок у итератора нет.
// Entry отдаётся копией по значению (24 Б).
func (v *View) All(ctx context.Context) iter.Seq[Entry]
```

## Экземпляры в пайплайне counter

- **Промежуточная таблица gen A** — отдельный `Cache`: ключ — D4-канон размещения префикса,
  вес — Σ orbitSize. Пишется фазой A напрямую через `Set`, затем на барьере errgroup — `Seal`,
  и worklist фазы B материализуется обходом `All(ctx)` в срез, предвыделенный по `View.Len()`;
  таблица затем выбрасывается (ADR-018).
- **Task-cache** — второй `Cache`: ключ — D4-канон префикса `(state, end)`, вес — Σ orbitSize;
  пишется фазой B через per-worker `Staging` (флеш по лимиту и на выходе воркера — ADR-031),
  живёт до конца count-фазы. Запечатывается один раз после барьера генерации: мемо раннего
  стопа читается `View.Get`, диспатч обходит `View.All`; никогда не дренируется (ADR-013).

## Инварианты

- **Хэш шарда — только от `State`** (`h = state * 0x9E3779B97F4A7C15 >> (64-7)`): записи одной
  маски не раскиданы по шардам, ключ шарды не смешивает (ADR-004).
- Сложение коммутативно — порядок записи на итог не влияет; `Set` складывает веса под одним
  ключом атомарно относительно своего шарда.
- `Set` с нулевым весом не создаёт запись (иначе нули появились бы в таблице).
- Записанные веса точны для своего ключа сразу после `Set`; барьер завершения писателей до
  `Seal` даёт happens-before, и все записи видны каждому View.
- `Staging`: эмиссия становится видимой только после флеша (авто по лимиту или явного `Flush`);
  нулевой вес отбрасывается на `Set` и не занимает буфер; флеш складывает дубликаты ключей внутри
  пачки в одно сложение под локом шарда — итог к барьеру идентичен прямым `Set` (коммутативность).
  Один `Staging` — одна горутина; конкурентные Staging'и разных горутин безопасны.
- Лок шарда — только писательский (`sync.Mutex`): берут его лишь `Set` и `Staging.Flush`;
  чтения View не берут локов вовсе.
- `View` читает иммутабельную таблицу без локов: данные после барьера не меняются, Go-map
  параллельно читается. `Set`/`Flush` после `Seal` — вне контракта (data race по предусловию).

## Ограничения и edge cases

- Пустая таблица: `Len() == 0`, `All` не отдаёт ни одной записи, `Get` — miss на любом ключе.
- Завершившийся ctx, переданный в `All`: обход останавливается на следующей границе шарда,
  потребитель получает префикс последовательности; отмена до первой итерации — ноль записей.
  Канала ошибок у итератора нет: частичный обход отличается от полного только числом отданных
  записей.
- `All` не аллоцирует на диспатч: записи отдаются из живых map, пик обхода — O(стек потребителя).
  Материализация всех записей в срез (24 Б × записей) допустима только для малой таблицы gen A
  и запрещена для task-cache (её high-water mark — пик процесса, ADR-014).
- Конкурентные `All`/`Get` нескольких View одной таблицы безопасны (писателей нет по
  предусловию); сам итератор однопоточный — параллелизм диспатча организуется потребителями,
  не обходом.

## Тесты

`cache/cache_test.go`: `Set` складывает веса под одним ключом и игнорирует нулевой; после `Seal`
`View.Get` видит сумму на hit, `(0,false)` на miss; `All` отдаёт полную таблицу без дублей и
потерь (сверка множеством: порядок внутри шарда — Go map), `Len` равен числу отданных записей;
ранний `break` даёт строгий префикс короче полного обхода без паники; отменённый ctx
останавливает обход на границе шарда (записей меньше полного обхода); одинаковый State → один
шард. `Staging`: до флеша вклады лежат в корзинах (проверка состояния писателя в пакете), после
`Flush` и `Seal` все эмиссии видны `View.Get`, дубликаты пачки схлопнуты в сумму, нулевой вес не
создаёт запись и не двигает лимит, авто-флеш на limit не теряет записей; несколько Staging'ей в
разные горутины под `-race` + Seal — точная сумма вкладов. `View`: веса совпадают с записанными;
несколько конкурентных View и параллельных обходов `All` под `-race` видят один и тот же снимок
(писателей нет по предусловию).

Материализация промежуточной таблицы gen A в worklist и сохранение суммарного веса покрыты
в `counter/counter_test.go` и `searcher/searcher_test.go`.
