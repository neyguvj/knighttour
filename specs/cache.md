# cache: таблица «маска → гистограмма классов концов», протокол «write → seal → read»

## Ответственность

Потокобезопасная аддитивная таблица весов `state.State → «класс конца → W»` — единственная
реализация шардированного словаря алгоритма. На каноническую маску приходится одна запись,
а классы концов этой маски живут внутри её значения (план 18). Тип `Cache` играет обе роли
конвейера: промежуточная таблица gen A живёт коротко — после `Seal` обход `View.All`
материализует из неё список работ (`worklist`) фазы B; второй экземпляр, task-cache, живёт
до конца count-фазы. Чтение возможно только через иммутабельный снимок `*View`, полученный
на фазовом барьере вызовом `Seal`; второго типа таблицы нет (ADR-018). Второй тип пакета —
это писатель, а не таблица: `Staging` батчем пишет в `Cache` (ADR-031) и собственных данных
не хранит.

Нули в таблице не появляются: ни запись, ни слот класса создаются только при положительном
вкладе. Пакет ничего не знает о симметриях: маску `K` и тег класса `rep` вычисляет писатель,
а читатель приводит конец к тому же тегу общей функцией канонизации (ADR-005,
specs/symmetry.md). Для cache тег `rep` непрозрачен, известен только его диапазон: `< 128`,
см. «Формат значения». О фазах конвейера пакет тоже не знает: контур-владелец вызывает
`Seal` в той точке, где все писатели уже остановлены.

## Формат значения (гистограмма)

- Ключ — чистая маска `K` (`state.State`, uint64). Конец в ключе не хранится: информативен
  только его класс, а он живёт тегом внутри значения; потерь нет, включая 8×8. Слот карты
  не содержит указателей ни с одной стороны пары: `uint64 → uint64`.
- Старший бит значения — тег формы; форм две:
  - **k = 1 — форма `inline`** (бит 63 = 0): слово `(rep:8 | W:56)`. Репрезентант класса —
    индекс клетки доски вплоть до 8×8, то есть `rep ≤ 63`, поэтому старший бит упакованной
    пары нулевой структурно. Один вес `W` класса помещается в 56 бит конструктивно для всех
    досок области проекта (ADR-034). Проверки переполнения в рантайме нет; упаковка
    внутренняя, наружу уходит только `uint64`.
  - **k ≥ 2 — ссылка на slab** (бит 63 = 1): `(k:7 | idx:56)` — число классов (структивно
    ≤ 64: классы делят между собой клетки маски) и стартовый индекс блока в slab шарда.
- Slab — это `[]uint64` того же шарда с дозаписью в конец, под его мьютексом. Он никогда
  не сжимается и не копируется целиком, а растёт стандартным удвоением среза: амортизация
  O(1) на слово. Ёмкость блока `cap(k) = 2^⌈log₂ k⌉`; живые пары занимают позиции
  `[idx, idx+k)` в порядке вставки. Хвост `[k, cap)` — свободный запас, который никто не
  читает; в блоке, взятом из корзины свободных, там может лежать мусор прежнего владельца.
- Рост записи при новом классе идёт тремя путями. Существующий класс — обновление слова на
  месте. Новый класс при незаполненной ёмкости (`cap(k+1) == cap(k)`) — допись пары в запас
  и инкремент `k` в теге, без переезда. Иначе срабатывает **copy-on-append**: в конец slab
  дописывается блок ёмкости `cap(k+1)`, в него переносятся k пар плюс новая, а старый блок
  отдаётся в корзину свободных своего класса ёмкости. Новый блок берётся сначала из корзины,
  и только при пустой корзине — из конца slab.
- Цена переездов. Если бы блок realloc'ался на каждый новый класс, переезды стоили бы
  Σⱼ₌₂^k j = O(k²/2) слов на запись; такой цены дизайн сознательно избегает. Запас
  `cap(k)` сдвигает переезды на границы степеней двойки, а освобождённый блок не пропадает:
  корзина возвращает его следующей записи того же размера. Поэтому расход slab лежит между
  Σ cap(k) (все запросы попали в корзины) и Σ (2·cap(k) − 2) слов (ни один не попал), то
  есть линеен по k. Каждое слово переезжает не более ⌈log₂ k⌉ раз за жизнь записи.

Плотность задаётся формулой, а не измерением: `18.3 + (k = 1 ? 0 : 8·cap(k))` Б/маску, где
18.3 — цена одного слота карты `(8+8+1)/0.93`. Сравнение этой раскладки с базой попарных
записей и числа выигрыша — в ADR-003, ADR-034.

## Публичный API

```go
type Entry struct { // развёрнутая запись таблицы: маска + тег класса + накопленный вес;
    Mask   state.State // всего 24 Б — на этот размер опираются формулы пакетной рассылки
    Rep    uint8
    Weight uint64
}

// NewCache — пустая таблица из 128 шардов: map + slab + корзины свободных блоков,
// каждый шард под своим мьютексом; хэш только от маски.
func NewCache() *Cache

// Sink — сторона записи таблицы; реализуют *Cache (прямая запись) и *Staging (батч).
type Sink interface {
    Set(K state.State, rep uint8, weight uint64) // аддитивный вклад data[K][rep] += weight; нулевой вес — no-op
}

// Set — аддитивный вклад в слот класса: data[K][rep] += weight. Нулевой вес не создаёт ни
// записи, ни слота; вклады одного (K, rep) копятся в одном слоте. Контракт аргумента rep:
// тег класса < 128, его гарантирует писатель через общую функцию канонизации; на этом
// диапазоне старший бит слова свободен под тег формы значения.
func (c *Cache) Set(K state.State, rep uint8, weight uint64)

// NewStaging — батч-писатель одной горутины поверх c (ADR-031). limit ≥ 1 (меньшее
// поднимается до 1): слияние пачки в таблицу происходит само при накоплении limit вкладов.
// Владелец обязан вызвать Flush на границе записи — на выходе писателя.
func (c *Cache) NewStaging(limit int) *Staging

func (s *Staging) Set(K state.State, rep uint8, weight uint64) // в буфер целевого шарда; нулевой вес — no-op
func (s *Staging) Flush() // сложенные вклады каждого непустого шарда под его мьютексом

// View — иммутабельный снимок для чтения; создаётся только методом Cache.Seal.
type View struct{ /* поля скрыты */ }

// Seal — барьер чтения протокола «write → seal → read» (план 16): возвращает снимок,
// чтение которого не берёт мьютексов. Предусловие — контракт вызывающего контура, а не
// типа: на момент вызова и всё время жизни всех снимков писателей (Set/Flush) нет — их
// остановил барьер с happens-before (завершение workerpool.Run/Fanout, финальный Flush
// каждого Staging). Повторный Seal даёт независимый снимок той же таблицы. Нарушение
// предусловия — data race по контракту.
func (c *Cache) Seal() *View

// Get — один поиск маски K без мьютексов; отсутствующая маска → (Value{}, false).
// Снимки одного барьера работают конкурентно. Горячий цикл читателя: один Get на маску,
// далее Weight по классам.
func (v *View) Get(K state.State) (Value, bool)

// Value — снимок гистограммы одной маски; создаётся только View.Get, нулевой Value
// означает отсутствие маски. Копия стоит дешёво и обращается к общему slab шарда:
// данные после барьера неизменяемы, поэтому разделять их можно.
type Value struct{ /* поля скрыты */ }

// Weight — накопленный W класса rep. Форма inline — сравнение одного слова, O(1); ссылка
// на slab — скан живых позиций блока [idx, idx+k), O(k), без аллокаций. Класс не хранится
// → (0, false).
func (val Value) Weight(rep uint8) (uint64, bool)

// Len — число записей таблицы: различных масок, а НЕ классов; постоянно после Seal,
// потому что писателей больше нет.
func (v *View) Len() int

// All — pull-обход всех записей без мьютексов и без копирования таблицы: значения читают
// живые map под предусловием Seal. Каждая запись разворачивается в поток по одной записи
// на класс: Entry{Mask, Rep, Weight}. Порядок: шарды 0..127 (внутри шарда — порядок Go
// map); классы записи идут в порядке хранения. ctx проверяется на границах шардов, отмена
// останавливает обход на следующей границе. break потребителя означает частичный обход и
// не является ошибкой; источника ошибок у итератора нет. Entry отдаётся копией по значению.
func (v *View) All(ctx context.Context) iter.Seq[Entry]
```

## Экземпляры в конвейере counter

- **Промежуточная таблица gen A** — отдельный `Cache`: ключ — каноническая маска размещения
  префикса, гистограмма — «класс конца → Σ orbitSize». Фаза A пишет в неё напрямую через
  `Set`; на барьере `Run` следует `Seal`, и обход `All(ctx)` материализует список работ
  фазы B в срез. Срез предвыделяют по `View.Len()`, но это только нижняя оценка: классов
  не меньше, чем масок. После материализации таблицу выбрасывают (ADR-018).
- **Task-cache** — второй `Cache`: ключ — каноническая маска префикса, гистограмма та же;
  вклады всех концов одного класса копятся в одном слоте. Фаза B пишет через собственный
  `Staging` каждой пишущей горутины: слияние пачки по лимиту и на выходе воркера (ADR-031).
  Таблица живёт до конца count-фазы и запечатывается один раз после барьера генерации.
  Счёт с ранней остановкой читает её через `View.Get` + `Value.Weight`, рассылка задач —
  обходом `View.All`; таблицу не вычитывают до конца ни разу (ADR-013).

## Инварианты

- **Хэш шарда — только от маски** (`h = K * 0x9E3779B97F4A7C15 >> (64-7)`): классы одной
  маски живут в одном шарде, `rep` в хэшировании не участвует (ADR-004).
- Сложение коммутативно, поэтому порядок записей на итог не влияет; `Set` складывает вес
  в слот класса атомарно относительно своего шарда.
- `Set` с нулевым весом не создаёт ни записи, ни слота класса — иначе нули появились бы в
  таблице. Отрицательных вкладов нет: слоты только растут. Хвост блока `[k, cap)` — не
  данные: после отдачи блока в корзину и повторного использования там лежит мусор прежнего
  владельца, и ни `Weight`, ни `All` его не читают.
- Тег формы не расходится с содержимым: `inline` ⟺ ровно один класс; ссылка на slab ⟺
  k ≥ 2, и блок по `idx` содержит ровно k живых пар. Классы одной маски лежат в одном
  блоке — частичного переноса между формами, заметного читателю, не бывает.
- Slab и корзины свободных блоков — писательское состояние шарда под его мьютексом: их
  трогают только `Set` и `Staging.Flush`. Снимок читает из slab лишь живые слова запечатанных
  записей и не трогает ни корзины, ни структуру slab.
- Записанный вес точен для своего `(K, rep)` сразу после `Set`; барьер остановки писателей
  перед `Seal` даёт happens-before, и все записи видны каждому снимку.
- `Staging`: вклад становится видимым только после слияния пачки — автоматического по
  лимиту или явного `Flush`. Нулевой вес отбрасывается на `Set`, не занимает буфер и не
  расходует лимит. При слиянии дубликаты `(K, rep)` внутри одной пачки складываются в ту же
  сумму под мьютексом шарда, поэтому итог к барьеру совпадает с прямыми `Set` по
  коммутативности. Один экземпляр `Staging` принадлежит горутине; конкурентные экземпляры
  разных горутин безопасны.
- Мьютекс шарда — писательский (`sync.Mutex`): его берут только `Set` и `Staging.Flush`;
  чтения снимка не берут мьютексов вовсе.
- `View` читает иммутабельную таблицу без блокировок: данные после барьера не меняются, а
  Go map допускает параллельные чтения. `Set`/`Flush` после `Seal` выходят за контракт —
  это data race по предусловию.

## Ограничения и edge cases

- Пустая таблица: `Len() == 0`, `All` не отдаёт ни одной записи, `Get` — промах на любом
  ключе.
- Число классов маски сверху API не ограничено (структивно ≤ 64): рост идёт дописью в запас
  ёмкости либо переездом блока с рециклингом старого. `Weight` и разворот `All` корректны
  при любом числе классов; их стоимость — линейный скан живых позиций.
- Вырожденные `idx`/`k` в теге невозможны: ссылка на slab создаётся только вместе с блоком
  из ≥ 2 пар. Маска с одним классом, который не рос, остаётся в форме `inline` навсегда.
- Уже завершившийся ctx, переданный в `All`: обход останавливается на следующей границе
  шарда, и потребитель получает префикс развёрнутой последовательности; отмена до первой
  итерации отдаёт ноль записей. Канала ошибок у итератора нет: частичный обход отличается
  от полного только числом отданных записей.
- `All` не аллоцирует для рассылки: развёрнутые записи идут из живых map, пик обхода —
  O(стека потребителя). Материализация всех записей в срез (24 Б × число классов)
  допустима только для малой таблицы gen A и запрещена для task-cache: её размер и так
  образует пик памяти процесса (ADR-014).
- Конкурентные `All`/`Get` нескольких снимков одной таблицы безопасны: писателей нет по
  предусловию. Сам итератор однопоточный — параллелизм рассылки организуют потребители, а
  не обход.

## Тесты

`cache/cache_test.go`:

- `TestEntrySize` — `Entry` занимает 24 Б; на этот размер опираются формулы пакетной
  рассылки.
- `TestCacheSetGetAndZeroWeight` — вес копится в слоте `(K, rep)`; нулевой вес не создаёт ни
  записи, ни слота; после `Seal` `Get` отдаёт сумму, отсутствующая маска → `(Value{}, false)`,
  отсутствующий класс → `Weight == (0, false)`; `Len` считает маски.
- `TestPackUnpackRoundTrip` — упаковка/распаковка на границах контракта: rep = 127 и вес
  полной ширины 56 бит сохраняются, старший бит остаётся нулевым.
- `TestValueEncoding` — `capacityFor` на всём структурном диапазоне, round-trip ссылки на
  slab, две формы значения не сталкиваются при rep < 128.
- `TestValuePromoteToSlab` — второй класс переводит запись из `inline` в блок на два класса;
  оба класса читаются точными суммами и разворачиваются в `All`.
- `TestGrowthAcrossCapacityBoundaries` — рост через все границы ёмкости (k = 2, 3, 5, 9, 17,
  33…) одинаково корректен при прямых `Set` и при слияниях пачек `Staging`: `Weight` точен
  по каждому классу, `All` разворачивает ровно по одному Entry на класс в порядке вставки —
  переезды не теряют, не дублируют и не переупорядочивают.
- `TestBasketReuseOnRelocation` — освобождённый переездом блок ложится в корзину своего
  класса ёмкости; перемежённый рост второй маски того же шарда забирает ровно эти блоки, и
  slab перестаёт расти. Мусор прежнего владельца в хвосте запаса невидим ни `Weight`, ни
  `All`; обе маски читаются точно.
- `TestViewAllCoversTable` — `All` покрывает таблицу ровно один раз без дублей и потерь;
  каждый класс получает свой Entry; `Len` считает маски и строго меньше числа отданных
  классов на таблице с многоклассовыми записями; повторный обход того же снимка отдаёт то
  же множество.
- `TestViewAllBreakGivesPrefix`, `TestViewAllBreakInsideRecord` — break даёт строгий
  префикс без паники, в том числе обрезку внутри записи: остальные классы этой записи не
  отдаются.
- `TestViewAllCtxCancelStopsWalk` — отмена посреди обхода отдаёт строго меньше записей,
  уже отменённый ctx — ноль.
- `TestShardIndexIsMaskOnly` — одинаковая маска всегда попадает в один шард при любом rep;
  разные маски распределены по шардам.
- `TestCacheConcurrentSet` — конкурентные `Set` в пересекающиеся слоты под `-race`; после
  барьера и `Seal` видны точные суммы.
- `TestStagingFlushBoundaries` — до слияния вклады лежат в буфере (проверка состояния
  писателя из пакета), после `Flush` и `Seal` видны через `Get`/`Weight`; дубликаты пачки по
  `(K, rep)` сложены в сумму; нулевой вес не попадает в буфер и не расходует лимит;
  авто-слияние на limit ничего не теряет; limit < 1 поднимается до слияния на каждом `Set`.
- `TestStagingConcurrentWriters` — несколько экземпляров `Staging` в разных горутинах под
  `-race`; после барьера и одного `Seal` вклады всех писателей сложены точно.
- `TestViewConcurrentHandlesAgree` — несколько независимых снимков и параллельных обходов
  `All` под `-race` видят один и тот же снимок таблицы: чтения не берут блокировок, потому
  что писателей нет.

Материализация промежуточной таблицы gen A в список работ (с разворотом классов) и
сохранение суммарного веса покрыты в `counter/counter_test.go` и `searcher/searcher_test.go`.
