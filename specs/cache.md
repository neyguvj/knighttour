# cache: единая таблица «маска → гистограмма классов концов», протокол «write → seal → read»

## Ответственность

Потокобезопасная аддитивная таблица весов `state.State → гистограмма «класс конца → W»` —
единственная реализация «шардированного словаря» алгоритма. Одна запись на каноническую
маску; классы концов одной маски живут в её значении (план 18). Один и тот же тип `Cache`
играет обе роли пайплайна: промежуточная таблица gen A (короткоживущая, после `Seal` обходом
`View.All` материализуется в worklist фазы B) и task-cache (живёт до конца count-фазы).
Чтение — только через запечатанную ручку `*View`, получаемую на фазовом барьере (`Seal`);
второго типа таблицы нет (ADR-018). Второй тип здесь — не таблица, а писатель: `Staging` —
батч-ручка записи в `Cache` (ADR-031), данных не хранит.

Нули не хранятся: запись и слот класса создаются только при положительном вкладе. Пакет
ничего не знает о симметриях: `K` и тег класса `rep` вычисляет писатель, читатель приводит
конец к тому же тегу общей функцией symmetry (ADR-005, specs/symmetry.md) — для cache `rep`
остаётся непрозрачным тегом класса с известным лишь диапазоном значений (< 128,
«Формат значения»). Фаз пакет тоже не знает: `Seal`
вызывает контур-владелец в точке, где все писатели остановлены.

## Формат значения (гистограмма)

- Ключ — чистая маска `K` (`state.State`, uint64): конец в ключе не хранится — информативен
  только его класс, он живёт тегом в значении (потерь нет, включая 8×8). Слот карты
  pointer-free: `uint64 → uint64`, ни одна сторона пары слота не содержит указателей.
- Значение — тегированное по старшему биту, две формы:
  - **k = 1 — inline** (бит 63 = 0): слово `(rep:8 | W:56)`. Репрезентант класса — индекс
    клетки доски до 8×8 (rep ≤ 63), поэтому старший бит упакованной пары нулевой структурно;
    один `W` класса помещается в 56 бит конструктивно для всех досок области проекта
    (ADR-034: W ≤ 8·writesB ≈ 2³³). Проверка в рантайме отсутствует; упаковка внутренняя,
    наружу отдаётся только `uint64`.
  - **k ≥ 2 — ссылка на slab** (бит 63 = 1): `(k:7 | idx:56)` — число классов (структивно
    ≤ 64: классы разбивают клетки маски) и стартовый индекс блока записи в slab шарда.
- Slab — append-only `[]uint64` того же шарда под его Mutex: никогда не сжимается, целиком
  не копируется, растёт стандартным удвоением среза (амортизация O(1) на слово). Ёмкость
  блока — `cap(k) = 2^⌈log₂ k⌉`; живые пары занимают позиции `[idx, idx+k)` в порядке
  вставки, хвост `[k, cap)` — свободный запас, который никто не читает (в блоке, взятом
  из корзины свободных, там может лежать мусор предыдущего владельца).
- Рост записи при новом классе: существующий класс — обновление слова на месте; новый класс
  при незаполненной ёмкости (`cap(k+1) == cap(k)`) — допись пары в запас и инкремент `k`
  в теге, без переезда; иначе **copy-on-append** — в конец slab дописывается блок ёмкости
  `cap(k+1)`, в него переносятся k пар плюс новая, старый блок отдаётся в корзину свободных
  шарда своего класса ёмкости. Аллокация блока — сначала из корзины нужного класса, иначе
  из конца slab.
- Оценка переездов словами: расти запись точным блоком на каждый новый класс — переезды
  стоили бы Σⱼ₌₂^k j = O(k²/2) слов на запись (при наблюдаемом максимуме k = 11 — 65 слов
  ≈ 0.5 КБ), на измеренном распределении классов это съедало бы бо́льшую часть выигрыша
  плотности. Выбранный запас `cap(k)` даёт переезды только через границы степени двойки, а
  рециклинг блоков того же класса ёмкости держит цену slab между Σ cap(k) (полное попадание
  в корзины) и Σ (2·cap(k) − 2) слов (полное промахивание), т.е. линеен по k; каждое слово
  переезжает не более ⌈log₂ k⌉ раз за жизнь записи.

Плотность (формула, не измерение): `18.3 + (k = 1 ? 0 : 8·cap(k))` Б/маску, где
18.3 = слот `(8+8+1)/0.93`. Против базы `27·k` (парные записи, ADR-003) раскладка не дороже
базы ни при каком k: при k = 1 это 18.3 против 27, при k ≥ 2 — `cap(k) < 2k`, поэтому
`18.3 + 8·cap(k) < 18.3 + 16k ≤ 27k`. Выигрыш растёт с k (на верхних границах ёмкости — до −60%).

## Публичный API

```go
type Entry struct { // развёрнутая запись таблицы: маска + тег класса + накопленный вес;
    Mask   state.State // worklist-элемент фазы B и элемент диспатча (копия по значению, 24 Б)
    Rep    uint8
    Weight uint64
}

func NewCache() *Cache // 128 шардов map[state.State]uint64 + per-shard slab и корзины свободных блоков под Mutex (лок писателей)

// Sink — сторона записи таблицы; реализуют *Cache (прямая запись) и *Staging (батч-запись).
type Sink interface {
    Set(K state.State, rep uint8, weight uint64) // аддитивный вклад data[K][rep] += weight; weight == 0 — no-op
}

// Set — аддитивный вклад в слот класса: data[K][rep] += weight. weight == 0 — no-op
// (нулей в таблице нет). Вклады одного (K, rep) накапливаются в одном слоте.
// Контракт аргумента rep: тег класса < 128 (индекс клетки доски до 8×8), его гарантирует
// писатель через общую функцию symmetry; на этом диапазоне старший бит inline-упаковки
// свободен под тег формы значения.
func (c *Cache) Set(K state.State, rep uint8, weight uint64)

// NewStaging — батч-писатель одной горутины поверх c (ADR-031): эмиссии буферизуются
// по шардам и сливаются под одним Lock задетого шарда на флеш. Не потокобезопасен:
// один Staging — одна пишущая горутина. limit ≥ 1 — авто-флеш при накоплении;
// Flush — явная граница видимости (вызывается на выходе писателя).
func (c *Cache) NewStaging(limit int) *Staging

func (s *Staging) Set(K state.State, rep uint8, weight uint64) // в буфер по индексу шарда; weight == 0 — no-op
func (s *Staging) Flush()                                      // сложенные вклады каждого непустого шарда под его Lock

// View — иммутабельная ручка чтения запечатанной таблицы; создаётся только Cache.Seal.
type View struct{ /* поля скрыты */ }

// Seal — барьер чтения «write → seal → read» (план 16): возвращает безлоковую ручку чтения.
// Предусловие (контракт вызывающего контура, не тип): на момент Seal и всё время жизни
// всех View писателей (Set/Flush) нет — они остановлены барьером, дающим happens-before
// (барьер workerpool.Run/Fanout, завершающий Staging.Flush). Повторный Seal даёт независимую
// ручку той же таблицы. Нарушение предусловия — data race по контракту.
func (c *Cache) Seal() *View

// Get — один map-lookup маски K без локов; маски нет → (Value{}, false). Конкурентные
// View безопасны. Горячий цикл читателя: один Get на маску, далее Weight по классам.
func (v *View) Get(K state.State) (Value, bool)

// Value — ручка чтения гистограммы значения одной маски; создаётся только View.Get,
// нулевой Value = отсутствие маски. Копия дёшева и разделяет slab-массив шарда —
// допустимо, данные после барьера иммутабельны.
type Value struct{ /* поля скрыты */ }

// Weight — накопленный W класса rep: inline — сравнение одного слова O(1); ссылка на
// slab — скан живых позиций блока [idx, idx+k), O(k), без аллокаций; класса нет → (0, false).
func (val Value) Weight(rep uint8) (uint64, bool)

// Len — число записей таблицы (= число различных масок, НЕ классов); постоянно после
// Seal (писателей больше нет).
func (v *View) Len() int

// All — pull-обход всех записей без локов и без копирования таблицы: значения идут из
// живых map под предусловием Seal. Каждая запись разворачивается в поток по одной на
// класс: Entry{Mask, Rep, Weight}. Порядок — шарды 0..127 (внутри шарда — порядок Go map),
// классы записи — порядок хранения (живые позиции блока в порядке вставки). ctx
// проверяется между шардами, отмена останавливает обход на следующей границе; break
// потребителя = частичный обход (обрезок возможен и внутри записи — остальные классы
// этой записи не отдаются), не ошибка. Источника ошибок у итератора нет. Entry отдаётся
// копией по значению.
func (v *View) All(ctx context.Context) iter.Seq[Entry]
```

## Экземпляры в пайплайне counter

- **Промежуточная таблица gen A** — отдельный `Cache`: ключ — каноническая маска
  размещения префикса, гистограмма — «класс конца → Σ orbitSize». Пишется фазой A напрямую
  через `Set`, затем на барьере `Run` — `Seal`, и worklist фазы B материализуется обходом
  `All(ctx)` в срез, предвыделенный по `View.Len()` (число классов ≥ числа масок, поэтому
  ёмкость — только нижняя оценка); таблица затем выбрасывается (ADR-018).
- **Task-cache** — второй `Cache`: ключ — каноническая маска префикса, гистограмма —
  «класс конца → Σ orbitSize» (вклады всех концов одного класса копятся в одном слоте);
  пишется фазой B через per-worker `Staging` (флеш по лимиту и на выходе воркера — ADR-031),
  живёт до конца count-фазы. Запечатывается один раз после барьера генерации: мемо раннего
  стопа читается `View.Get` + `Value.Weight`, диспатч обходит `View.All`; никогда не
  дренируется (ADR-013).

## Инварианты

- **Хэш шарда — только от маски** (`h = K * 0x9E3779B97F4A7C15 >> (64-7)`): классы одной
  маски живут в одном шарде, `rep` в хэше не участвует (ADR-004).
- Сложение коммутативно — порядок записи на итог не влияет; `Set` складывает вес в слот
  класса атомарно относительно своего шарда.
- `Set` с нулевым весом не создаёт ни записи, ни слота класса (иначе нули появились бы в
  таблице). Отрицательных вкладов нет — слоты только растут. Хвост блока `[k, cap)` не
  данные: после отдачи блока в корзину и повторного использования там лежит мусор
  прежнего владельца, и ни `Weight`, ни `All` его не читают.
- Тег формы не расходится с содержимым: inline ⟺ ровно один класс; ссылка на slab ⟺
  k ≥ 2 и блок по `idx` содержит k живых пар. Классы одной маски лежат в одном блоке —
  частичного переноса между формами, видимого читателю, нет.
- Slab и корзины свободных блоков шарда — писательское состояние под его Mutex (трогают
  только `Set` и `Staging.Flush`); View читает из slab лишь живые слова запечатанных
  записей и не трогает ни корзины, ни структуру slab.
- Записанные веса точны для своего `(K, rep)` сразу после `Set`; барьер завершения писателей
  до `Seal` даёт happens-before, и все записи видны каждому View.
- `Staging`: эмиссия становится видимой только после флеша (авто по лимиту или явного
  `Flush`); нулевой вес отбрасывается на `Set` и не занимает буфер; флеш складывает
  дубликаты `(K, rep)` внутри пачки в одно сложение под локом шарда — итог к барьеру
  идентичен прямым `Set` (коммутативность). Один `Staging` — одна горутина; конкурентные
  Staging'и разных горутин безопасны.
- Лок шарда — только писательский (`sync.Mutex`): берут его лишь `Set` и `Staging.Flush`;
  чтения View не берут локов вовсе.
- `View` читает иммутабельную таблицу без локов: данные после барьера не меняются, Go-map
  параллельно читается. `Set`/`Flush` после `Seal` — вне контракта (data race по предусловию).

## Ограничения и edge cases

- Пустая таблица: `Len() == 0`, `All` не отдаёт ни одной записи, `Get` — miss на любом
  ключе.
- Число классов маски сверху API не ограничен (структивно ≤ 64): рост идёт дописью в
  запас ёмкости либо переездом блока с рециклингом старого; `Weight` и разворот `All`
  корректны на любом числе классов (стоимость — линейный скан живых позиций).
- Вырожденные `idx`/`k` в теге невозможны: ссылка на slab создаётся только вместе с
  блоком из ≥2 пар; маска, у которой был один класс и он не рос, остаётся inline навсегда.
- Завершившийся ctx, переданный в `All`: обход останавливается на следующей границе
  шарда, потребитель получает префикс развёрнутой последовательности; отмена до первой
  итерации — ноль записей. Канала ошибок у итератора нет: частичный обход отличается от
  полного только числом отданных записей.
- `All` не аллоцирует на диспатч: развёрнутые записи отдаются из живых map, пик обхода —
  O(стек потребителя). Материализация всех записей в срез (24 Б × классов) допустима
  только для малой таблицы gen A и запрещена для task-cache (её high-water mark — пик
  процесса, ADR-014).
- Конкурентные `All`/`Get` нескольких View одной таблицы безопасны (писателей нет по
  предусловию); сам итератор однопоточный — параллелизм диспатча организуется потребителями,
  не обходом.

## Тесты

`cache/cache_test.go`: `Set` копит вес в слоте `(K, rep)` и игнорирует нулевой (ни записи,
ни слота); разные `rep` одной маски — разные слоты одной записи; после `Seal` `View.Get` —
hit с суммой, miss-маска → `(Value{}, false)`, отсутствующий класс → `Weight == (0,false)`.
Формат значения: promote k=1→2 — второй класс маски переводит значение в slab-форму, оба
класса читаются с точными суммами; рост через границы ёмкости (k = 2, 3, 5, 9…) повторными
`Set`/флешами Staging — `Weight` точен по каждому классу, `All` разворачивает ровно по одному
Entry на класс без дублей и потерь веса при переездах; рециклинг корзин: после переезда
освободившийся блок занимает другая запись (перемежённый рост нескольких масок через
ёмкость) — обе читаются корректно, хвостовые позиции старого владельца невидимы; множество
вкладов в один класс и в разные классы — точные суммы `Weight` и разворота. `All` отдаёт
ровно по одному Entry на класс без
дублей и потерь (сверка множеством), `Len` равен числу масок и строго меньше числа классов
на таблице с мультислотными записями; ранний `break` даёт строгий префикс (в т.ч. обрезку
внутри записи) без паники; отменённый ctx останавливает обход на границе шарда; одинаковая
маска → один шард. `Staging`: до флеша вклады лежат в корзинах (проверка состояния писателя
в пакете), после `Flush` и `Seal` все эмиссии видны `Get`/`Weight`, дубликаты пачки по
`(K, rep)` схлопнуты в сумму, нулевой вес не создаёт записи и не двигает лимит, авто-флеш
на limit не теряет записей; несколько Staging'ей в разные горутины под `-race` + Seal —
точная сумма вкладов. `View`: веса совпадают с записанными; несколько конкурентных View и
параллельных обходов `All` под `-race` видят один и тот же снимок (писателей нет по
предусловию).

Материализация промежуточной таблицы gen A в worklist (с разворотом классов) и сохранение
суммарного веса покрыты в `counter/counter_test.go` и `searcher/searcher_test.go`.
