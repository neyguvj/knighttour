# cache: единая разделяемая таблица «ключ → вес»

## Ответственность

Потокобезопасная аддитивная таблица весов `path.Path → uint64` — единственная реализация
«шардированного словаря» алгоритма. Один и тот же тип `Cache` играет обе роли пайплайна:
промежуточная таблица gen A (короткоживущая, материализуется в worklist фазы B обходом
`Each`) и task-cache (живёт до конца count-фазы). Контракты различаются только способом
чтения — `Get`/`Each`, никакого второго типа таблицы нет (ADR-018).

Нули не хранятся: запись создаётся только при положительном вкладе. Пакет ничего не знает о
симметриях — канонизацию выполняет писатель/читатель (ADR-005).

## Публичный API

```go
type Entry struct { Path path.Path; Weight uint64 } // одна запись таблицы; worklist-элемент фазы B

func NewCache() *Cache                        // 128 шардов map[path.Path]uint64 под RWMutex

// Set — аддитивный вклад: data[k] += weight. weight == 0 — no-op (нулей в таблице нет).
func (c *Cache) Set(p path.Path, weight uint64)

// Get — конкурентно-safe чтение поверх живущих писателей (RLock); miss → (0,false).
func (c *Cache) Get(p path.Path) (uint64, bool)

func (c *Cache) ItemsCount() int

// Диспатч обхода по всем записям без копирования таблицы.
// Горутина на шард (до workers одновременно; workers < 1 — кламп в число шардов):
// проверка ctx → RLock шарда → f по каждой записи → RUnlock. Данные НЕ изымаются:
// Get видит все шарды до конца обхода.
// Колбэк выполняется под RLock шарда — законен только при отсутствии писателей
// (инвариант фазы); разделяемый RLock конкурентен с Get любого шарда, включая свой.
// Первая ошибка f останавливает запуск новых шардов и возвращается из Each;
// отменённый ctx завершает обход перед следующим шардом и даёт ctx.Err().
func (c *Cache) Each(ctx context.Context, workers int,
    f func(ctx context.Context, p path.Path, weight uint64) error) error
```

## Экземпляры в пайплайне counter

- **Промежуточная таблица gen A** — отдельный `Cache`: ключ — D4-канон размещения префикса,
  вес — Σ orbitSize. Пишется фазой A напрямую через `Set`, затем материализуется в worklist
  фазы B обходом `Each` (писатели к этому моменту остановлены барьером errgroup) и выбрасывается;
  таблица мала (глубина ≤ `TwoPhaseBaseDepth`), поэтому освобождение — обычным GC, без
  пошардового дренажа (ADR-018).
- **Task-cache** — второй `Cache`: ключ — D4-канон префикса `(state, end)`, вес — Σ orbitSize;
  живёт до конца count-фазы и читается `Get`/`Each`, никогда не дренируется (ADR-013).

## Инварианты

- **Хэш шарда — только от `State`** (`h = state * 0x9E3779B97F4A7C15 >> (64-7)`): записи одной
  маски не раскиданы по шардам, ключ шарды не смешивает (ADR-004).
- Сложение коммутативно — порядок записи на итог не влияет; `Set` складывает веса под одним
  ключом атомарно относительно своего шарда.
- `Set` с нулевым весом не создаёт запись (иначе нули появились бы в таблице).
- Записанные веса точны для своего ключа сразу после `Set` (видимость под локом шарда);
  count-фаза читает то, что записала генерация до барьера.

## Ограничения и edge cases

- `Get` конкурентен с `Set` (RLock/RUnlock), но корректность подсчёта опирается на фазовый
  барьер вызывающего контура — до него записей нужной глубины может не быть (miss законен).
- `Each` не аллоцирует на диспатч: записи отдаются из живого map под RLock шарда, пик фазы
  обхода — O(стек воркеров). Предусловие: писателей нет (иначе ожидающий `Set` может
  заблокировать рекурсивный разделяемый RLock того же шарда внутри `f`). Проверка ctx — перед
  каждым шардом; `workers < 1` даёт максимальный параллелизм (кламп в число шардов внутри
  `Each`: `errgroup.SetLimit(0)` навешивает первый `Go`, «без лимита» у errgroup — только
  отрицательное значение).
- Материализация worklist gen A (`Each` → `[]Entry`) аллоцирует срез всех записей при живой
  таблице; это допустимо только для малой промежуточной таблицы gen A и запрещено для task-cache
  (её пик — high-water mark процесса, ADR-014) — обход task-cache идёт прямым `Each`.

## Тесты

`cache/cache_test.go`: `Set` складывает веса под одним ключом и игнорирует нулевой; Get hit
видит сумму, miss → `(0,false)`; `Each` отдаёт полную таблицу без дублей и потерь
(workers 0 — кламп, 1 и N), колбэк видит те же данные, что Get, отмена ctx останавливает обход
(отдано < полной таблицы), первая ошибка f возвращается; одинаковый State → один шард;
конкурентные Set/Get разных ключей под `-race` — все записи прочитаны.

Материализация промежуточной таблицы gen A в worklist и сохранение суммарного веса покрыты
в `counter/counter_test.go` и `searcher/searcher_test.go`.
