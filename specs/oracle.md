# Компонент Oracle: Мемоизация h(U,u) по классам форм

## Назначение

Мемоизированный оракул значения `h(U,u)` — числа путей коня, покрывающих ровно
множество `U` и заканчивающихся в `u ∈ U`. Используется searcher'ом для досрочного
завершения count-DFS (reversal early stop, см. searcher.md) вместо lookup'а в
префикс-кэше.

Ключевое отличие от префикс-кэша: ключом является **класс формы с точностью до
D4 ⋉ трансляции**, а не конкретная позиция на доске. Это даёт ~10–20× меньшую
таблицу (число размещений компактной формы размера D на доске N×N).

## Математическое обоснование

**Инвариантность h.** Все ходы пути, покрывающего `U`, идут по клеткам `U`;
смежность коня зависит только от разностей координат. Значит `h(U,u)` является
функцией изоморфизм-класса индуцированного подграфа `G[U]` с отмеченной клеткой
конца. В частности, `h` инвариантна к:

- D4-симметриям доски;
- **параллельным переносам формы** (даже у границы — продолжения не выходят за `U`,
  поэтому граница доски на значение не влияет).

**Неинвариантность f.** Число продолжений `f(M,e)` зависит от дополнения
`full &^ M`, форма которого при трансляции меняется. Поэтому корни подзадач
(префикс-кэш) через трансляции НЕ сливаются — трансляционная нормализация
применима только к oracle (и вообще ко всему, что зависит только от индуцированного
подграфа покрытого множества).

**Следствие для reversal.** Тождество `f(T,t) = Σ_{u∈U,u~t} h(U,u)` — точная
биекция с истинным (незашученным) значением h. Oracle отдаёт истинное h напрямую,
поэтому деление `W/orbitSize` из старой схемы не нужно; орбитальные размеры и
равномерность весов вообще выпадают из контура корректности.

## Ключ: нормализация формы

```go
// key — канонический представитель класса (mask,end) в группе D4 ⋉ трансляции.
type key struct {
    shape state.State // нормализованная маска: bbox прижат к (0,0)
    end   uint8       // позиция конца внутри нормализованной маски
}
```

Алгоритм `normalize(mask, end)`:

1. Для каждой из 8 ориентаций D4: трансформировать маску и конец
   (`symmetry.GetSymmetries`), результат сдвинуть так, чтобы min строка и min
   столбец стали нулевыми (bbox в угол системы координат).
2. Размер bbox ≤ N×N ⇒ нормализованная маска всегда помещается в uint64 при N≤8.
3. Канонический ключ — лексикографический минимум пар `(shape, end)` по всем
   8 ориентациям (tie-break по `end` обязателен: разные ориентации могут давать
   равные маски с разными отмеченными клетками).

Две пары лежат в одном классе ⟹ их нормализации совпадают (и наоборот — нормализация
инъективна на классах, т.к. это детерминированный выбор представителя).

## Вычисление h

`h(shape, end)` = число гамильтоновых путей в `G[shape]`, кончающихся в `end`.
Эквивалентно (реверс пути): число путей, начинающихся в `end` и покрывающих всю
форму. Рекурсия с мемо по подзадачам внутри одного вычисления:

```
f(cur, todo) = Σ_{n ∈ todo ∩ N(cur)} f(n, todo \ {n}),   f(cur, 0) = 1
h = f(end, shape \ {end})
```

- Ключ мемо — `(cur, todo)` (todo — uint64-маска в координатах нормализованной
  формы: bbox ≤ N×N ⇒ биты < totalCells).
- Состояний ≤ D·2^D; хранение — локальная map пересчёта (размер пропорционален
  достижимому множеству, обычно ≪ верхушки из-за связности).
- Ранний отсев: перед рекурсией в каждом состоянии `(cur, todo)` вызывается
  `pruner.AdvancedPruner.ShouldPruneAfterVisit(cur, todo)` (тот же прунер и то же
  представление состояния, что использует searcher): локальный dead-end, затем
  связность `G[todo]` и endpoint-эвристика (вершины степени ≤1 в `G[todo]`).
  Прунутая ветвь даёт 0 и мемоизируется как 0.

  Корректность: все проверки pruner'а sound — они отсекают только состояния без
  продолжений, что для `computeH` означает истинный ноль. Состояние `(cur, todo)`
  в `walk` — это ровно «после посещения `cur` осталось покрыть `todo`», т.е. тот же
  контракт, что у searcher'а. Работа над трансляционно-нормализованной формой
  безопасна: смежность коня инвариантна к переносу (см. выше), а клиппинг соседей
  у границы доски отсекает только вне-досочные клетки, которых в `todo` нет, —
  индуцированный подграф `G[todo]` pruner видит точно.

Стоимость одного вычисления ограничена O(D·2^D·deg); при D ≤ 16 это миллионы
операций, но каждое значение считается один раз на класс и далее только читается.

## Хранилище и потокобезопасность

```go
type Oracle struct { ... }

func New(g *graph.Graph) *Oracle
// Создаёт оракул: 16 шардов map[key]uint64 + атомарные метрики.

func (o *Oracle) Get(mask state.State, end int) uint64
// Истинное h(mask,end): нормализует ключ, читает под RLock; при промахе
// вычисляет вне блокировки и вставляет под Lock (double-check).
// Ноль — валидное значение: отсутствие записи означает «не вычислено»,
// а не «ноль» (в отличие от cache.Set, пропускающего нули).

func (o *Oracle) Stats() (lookups, computes, classes uint64)
```

- Параллельные промахи по одному ключу допускают дублирование вычисления
  (wasted work), но не влияют на корректность: значение детерминировано.
- `classes` — число записей; `computes/lookups` и `classes` дают фактический
  коэффициент трансляционного сжатия в рантайме.

## API для хот-патти (амортизация нормализации)

На stop-level узле одна и та же маска `U` опрашивается по каждому соседу `u ∈ U`.
Чтобы не трансформировать маску 8 раз на каждого соседа, предусмотрен подготовленный
контекст:

```go
type ShapeCtx struct { ... } // лениво: 8 нормализованных масок + смещения bbox по ориентациям

func (o *Oracle) Prepare(mask state.State, sc *ShapeCtx)
// Заполняет sc один раз для данной маски (стек вызывающего, без аллокаций).

func (o *Oracle) GetPrepared(sc *ShapeCtx, end int) uint64
// То же, что Get, но нормализованные маски переиспользуются; на конец уходит
// только перм + сдвиг + argmin по 8 ориентациям.
```

`Get` допустим как тонкая обёртка над Prepare+GetPrepared.

## Связь с Searcher/Counter

- `searcher.Reversal` строится фабрикой `newOracleReversal` и хранит `*Oracle` и
  `stopLevel = totalCells − oracleDepth`; на stop-level `Reversal.Completions`
  считает `Σ_{u ∈ N(end) ∩ U} o.GetPrepared(&sc, u)` (см. searcher.md).
- `counter.ParallelCountWithDepth` создаёт один Oracle на прогон; глубина oracle
  (`oracleDepth`) независима от глубины корней подзадач. Привязка `2d ≤ n²` снята:
  oracle работает для любого `1 ≤ oracleDepth < totalCells`; если stop-level лежит
  выше глубины корня, досрочное завершение просто не срабатывает (корректный полный DFS).

## Ограничения

- Память таблицы ограничена числом реально опрошенных классов форм размера
  `oracleDepth` и заведомо меньше числа конкретных пар (фактор — среднее число
  размещений формы на доске). Замер 8×8, root=10/oracle=16: ~35 lookups на класс.
- При очень больших `oracleDepth` растёт стоимость первого вычисления класса
  (O(D·2^D)) — дефолты ограничивать сверху ~16.

## Трейдофф против старой схемы с префикс-кэшем

Старый reversal читал h из уже построенного префикс-кэша (`W/orbitSize`) —
значение доставалось «бесплатно», но ценой экспоненциального кэша глубины d.
Oracle переносит стоимость на вычисление h по классу формы: при одинаковой
глубине это дороже lookup'а (замер 6×6: +17% … ×3.5 в зависимости от глубины),
зато память таблицы — классы вместо пар, а корни остаются мелкими. На досках,
где старая схема физически не помещается (8×8 d≥12), альтернативы oracle нет:
легаси d14 = 16.4 ГБ до начала подсчёта; новый режим root=10/oracle=16 —
десятки мегабайт корней + лениво растущий oracle (~1 ГБ на первые минуты).

## Тесты (эталонные требования)

- **Exhaustive property (5×5):** для всех масок размера ≤ 5 и всех `end ∈ mask`:
  `Oracle.Get ==` брутфорс-перечисление прогулок, покрывающих маску.
- Property на случайных связных масках размеров 6–14 (5×5/6×6) против того же
  брутфорса (маски — случайные self-avoiding walk'и + случайные связные подмножества).
- Инвариант нормализации: для любого допустимого `(mask,end)` и любой ориентации/трансляции —
  `normalize` даёт одинаковый ключ; на полном переборе форм размера ≤4 классы
  совпадают с орбитами явного действия группы D4 ⋉ трансляции.
- Нулевой h (несвязная форма) возвращается и мемоизируется как 0.
- `-race`: конкурентные Get по пересекающимся ключам.
- Предвычисления `New`: `perms[t]` — биекция `[0,total)` и совпадает с
  `symmetry.GetSymmetries(size)[t]` (порядок ориентаций согласован с таблицами
  `orR/orC` в `Prepare`); `rows/cols` консистентны. Для всех размеров 5–8.
- `shardIndex`: попадание в `[0, numShards)` и покрытие всех шардов на случайных ключах.
- Граничные формы `Prepare/keyOf` (без вычисления h): однобитная маска (ключ
  одинаков для всех позиций/ориентаций, `h==1`); полная маска доски
  (`n == maxCells`, без паники, инвариант по ориентациям); маски с bbox = вся
  доска — все 8 нормализованных масок сохраняют число бит и не выходят за
  границы (защита от underflow `orR/orC`); переиспользование одного `ShapeCtx`
  на разных масках (в т.ч. после полной) даёт корректные результаты.
