# Компонент Pruner: Отсечение тупиковых ветвей

## Назначение

Отсечение ветвей дерева поиска, которые заведомо не приведут к решению.
Один стейт-лесс компонент `Pruner` с ярусами проверок:

- **L0 — локальный dead-end**: изолированные клетки за O(deg(last));
- **L1 — глобальные проверки**: связность оставшихся клеток + анализ вершин
  степени ≤1 (эвристика концов гамильтова пути). Включены всегда.
- **L2 — усиленные необходимые условия** на состоянии `(cur, todo)`:
  сочленения (lowlink Тарьяна) и обязательные цепочки. Вызываются **только из
  финального DP** (`shapecount`) через `ShouldPruneState`, за порогом
  `minL2`; генерационный DFS L2 не видит (решение плана 04: удорожание узла
  окупается лишь при экспоненциальном сокращении дерева DP).

Исторически это были два типа (`DeadEndPruner` + `AdvancedPruner`-композиция);
слиты в одну структуру — локальная проверка остаётся первым (дешёвым) блоком
того же метода, отдельного типа больше нет.

## Pruner

```go
type Pruner struct {
    graph *graph.Graph // граф смежности (хранится ссылка, без копирования)
}

func New(g *graph.Graph) *Pruner
```

Прунер **не хранит статистику** — он стейт-лесс и вызывается конкурентно из
воркеров; учёт по видам прунинга ведёт вызывающий через возвращаемую причину
(`types.Result.CountPrune`). Так сохраняется точная атрибуция по подзадачам без
атомиков на горячем пути.

### Reason — вид прунинга

```go
type Reason uint8

const (
    NoReason        Reason = iota // ветвь не отсечена
    DeadEnd                       // локальный dead-end: изолированная клетка / одиночная недоступная
    NoContinuation                // у last нет непосещённых соседей
    Disconnected                  // G[unvisited] не одна компонента
    Endpoints                     // эвристика концов: >2 degree-1 либо обе недосяжны от last
    Articulation                  // L2: вершина H распадает на ≥3 компоненты (или ≥2 при известном конце)
    ForcedChain                   // L2: обязательные рёбра требуют степень >2 или дают цикл
)
```

`Articulation`/`ForcedChain` возвращает только `ShouldPruneState` (см. ниже).

### ShouldPruneAfterVisit(last int, unvisited state.State) (bool, Reason)

Горячий метод. Возвращает признак отсечения и **причину** (первое сработавшее);
при `false` причина — `NoReason`. Вызывается сразу после посещения клетки `last`
родителем, который сам прошёл проверку (инвариант: среди непосещённых нет
изолированных, кроме случая одной оставшейся клетки).

**Инвариант/корректность:** посещение `last` может изолировать только непосещённых
соседей самой клетки `last`, поэтому полный скан всех клеток не требуется.

**Алгоритм (дешёвое сначала):**
1. Если непосещённых нет → `(false, NoReason)`
2. Если осталась одна клетка: отсечь с причиной `DeadEnd`, если она не соседняя
   к `last` (текущему концу пути)
3. Локальный dead-end: для каждого непосещённого соседа `u` клетки `last`
   проверить `neighborMask(u) & unvisited == 0`; нашёлся → `(true, DeadEnd)`
4. Глобальные проверки (`globalCheck`, только при `|unvisited| > 1`) — см. ниже

Маски соседей прунер не копирует — каждый вызов `GetNeighborMask` читает предвычисленную
маску графа за O(1).

### globalCheck и причины

```go
func (p *Pruner) ShouldPruneAfterVisit(last int, unvisited state.State) (bool, Reason)
```

Композиция проверок (все — на битовых масках, включены всегда):

1. **Dead-end** — локальный блок (дешёвая проверка сначала).
2. **Глобальные проверки** (`globalCheck`, только при `|unvisited| > 1`):
   - **нет продолжения** (причина `NoContinuation`) — у `last` нет непосещённых
     соседей → prune;
   - **связность `G[unvisited]`** (причина `Disconnected`) — оставшийся путь живёт
     только в непосещённых клетках, поэтому они обязаны образовывать одну связную
     компоненту. Проверка — bitset flood-fill от младшего бита: расширение фронта
     ИЛИ-ем предвычисленных масок соседей; если покрыты не все → prune. По ходу
     флуда считается степень каждой клетки в `G[unvisited]` (popcount по
     unvisited); изолированная вершина внутри флуда — причина `DeadEnd`;
   - **эвристика концов** (причина `Endpoints`) — гамильтов путь на `G[unvisited]`
     имеет ровно 2 конца, причём стартовый обязан быть соседом `last`. Вершины
     степени 1 обязаны стать концами, поэтому: ≥3 вершин степени 1 → prune; ровно
     2 и ни одна не соседна `last` → prune.

Замеры на M4 Max (`-benchtime=3x`, время полного подсчёта):

| доска | только dead-end | advanced (порог K=20) | advanced (всегда) |
|-------|-----------------|----------------------|-------------------|
| 5×5   | 3.20 мс         | 0.69 мс              | ~0.7 мс           |
| 6×6   | 16.7 с          | 2.09 с               | ~1.0 с            |

Порог по остатку (K=20) ускорял 5×5 на ~8%, но на 6×6 проигрывал ~2×; выбран
вариант «всегда» — он же соответствует решению не иметь переключателей.

Корректность: ни одна проверка не отсекает ветвь, содержащую полный маршрут —
связность обязательна (путь не может покинуть компоненту без возврата в
посещённые), эвристика концов — необходимое условие существования гамова пути.

## L2: ShouldPruneState (только финальный DP)

```go
type L2Checks uint8

const (
    L2None        L2Checks = 0
    L2Articulation L2Checks = 1 << iota - 1 // 1
    L2ForcedChain                           // 2
    L2All = L2Articulation | L2ForcedChain
)

func (p *Pruner) SetL2(mask L2Checks, minTodo int) // конфигурация до старта воркеров
func (p *Pruner) ShouldPruneState(cur int, todo state.State) (bool, Reason)
```

Область применения — **только** рекурсия `f(cur, todo)` пакета `shapecount`
(начало пути зафиксировано: это `cur`). Из searcher'а вызывается по-прежнему
только `ShouldPruneAfterVisit`. Порядок: сначала весь L0/L1
(`ShouldPruneAfterVisit`), затем при включённом маске и `todo.CountBits() >= minL2`
(`DefaultMinL2 = 10`, подбирается этапом 0 плана 04) — проверки L2 над
графом `H = G[todo ∪ {cur}]`. Обе O(V+E), без аллокаций (стек и UF — фиксированные
массивы `[64]` на стеке вызова).

### Сочленения (причина `Articulation`)

Итеративный lowlink Тарьяна на битовых масках по связному `H` (связность
`G[todo]` и соседство `cur` с `todo` гарантирует L1). Для вершины `v` число
компонент `comp(H − v) = (v — корень DFS ? детей : 1 + число детей c с low[c] ≥ disc[v])`.

Необходимые условия (гамильтов путь из `cur` покрывает `H`):

- `comp(H − v) ≥ 3` для любой `v ∈ todo` → prune: удаление вершины пути
  делит его не более чем на два куска;
- если **конец зафиксирован** (`t` — единственная вершина `todo` со степенью 1
  в `H`; тогда она обязана быть концом пути):
  - `comp(H − t) ≥ 2` → prune: удаление конца пути оставляет один кусок;
  - `comp(H − v) = 2` и `cur`, `t` лежат в одной компоненте `H − v` → prune:
    вторую компоненту путь смог бы покрыть только повторно через `v`.

### Обязательные цепочки (причина `ForcedChain`)

Работает только при зафиксированном конце `t` (тот же критерий: ровно одна
вершина `todo` со степенью 1 в `H`). Тогда все прочие вершины `todo` —
внутренние (ровно 2 ребра пути), `cur` — начало (ровно 1 ребро). Обязательные
рёбра: у каждой внутренней вершины степени 2 в `H` оба инцидентных ребра;
единственное ребро `t`; единственное ребро `cur` при `deg_H(cur) = 1`.

Проверки (union-find по рёбрам, счётчики вершин/рёбер на компоненту):

- обязательная степень `> 2` у вершины `todo` или `> 1` у `cur` → prune;
- обязательные рёбра содержат цикл (`|E| ≥ |V|` компоненты) → prune: путь
  ацикличен, а все перечисленные рёбра обязаны входить в него.

При незафиксированном конце (`≠1` вершины степени 1 в `H`) форсинг **не
корректен**: единственная «жертва» — сам неизвестный конец — может разорвать
любую цепочку, поэтому проверка пропускается (доказательство контрпримера —
в плане 04). Замечание: уточнение п.3 плана 04 («при двух degree-1 одна обязана
быть началом») эквивалентно уже работающей эвристике `Endpoints` и отдельной
причины не заводит.

Конфигурация по умолчанию: **L2 выключён** (`New` даёт `L2None`, `minL2 = DefaultMinL2`).
Решение этапа 0 (план 04, замеры 6×6 на реальном пайплайне): artic удорожает фазу
counting в ×2.3, chain — в ×1.5 при сокращении состояний DP заметно меньшем, чем
окупает стоимость; порога, при котором проверки отбиваются, на досках ≤ 7×7 не
найдено. Механизм (счётчики причин, бенчмарк `BenchmarkCountShapeL2`, свип
уровней) оставлен для будущих экспериментов: включение — `SetL2`/`Counter.SetL2`.

## Shape-фильтр реализуемости (план 02)

```go
func (p *Pruner) ShapeFeasible(end int, shape state.State, mask L2Checks) (bool, Reason)
```

Отвечает «заведомо нет гамильтова пути, покрывающего `shape` и кончающегося в
`end`» — **до** входа в DP. Проверки выбирает `mask`; каждая — необходимое
условие, ложных отсечений нет:

- **A — endpoint-mismatch (`L2Endpoints`, по умолчанию выключен):** степени
  вершин в `G[shape]`: >2 вершин степени 1 → гамильтова пути нет вовсе; ровно
  две `{a,b}` → они обязаны быть концами пути, поэтому `end ∉ {a,b}` → ноль.
  Измерен на реальном распределении в 0 срабатываний сверх корневого L1 (если
  A убивает конец, deg-1 вершины остаются deg≤1 и в `G[shape∖{end}]` — режет
  тот же корень), оставлен только для инструментов этапа 0.
- **B — forced-cycle (`mask & L2ForcedChain`):** переиспользует
  `forcedChainCut(end, shape∖{end})` — семантика корневой DP-подзадачи та же
  (путь из `end`, покрывающий `shape`); корректность — как у L2 плана 04.
- **C — articulation (`mask & L2Articulation`):** `articulationCut(end,
  shape∖{end})`. Требование связности `G[shape]` не гарантировано (L1 не
  запускался): на несвязном графе Tarjan может как промолчать, так и отсечь —
  в обе стороны это корректно (несвязный ⇒ h=0).

Порядок дешёвое-сначала: A → B → C; возвращается первая сработавшая причина
(те же `Endpoints`/`ForcedChain`/`Articulation`). Вызывается из
`shapecount.CountShapeWithTail` **до** выделения memo-буфера; учёт — отдельным
счётчиком `types.Result.FilteredShapes` (формы, убитые до DP), чтобы не mixing с
`pruned*` статистикой DP (риск плана 02 «смешивание статистики»).

## Использование в Searcher

`Searcher` хранит прунер в поле `pruner *pruner.Pruner` (создаётся один раз в
`NewSearcher`). В горячем DFS (`dfs`) проверка выполняется сразу после попытки посещения
клетки `n`, до рекурсии — если остались непосещённые клетки и ветвь тупиковая, она
отсекается, а причина уходит в аккумулятор `*types.Result`:

```go
func (s *Searcher) dfsGen(ctx context.Context, st state.State, end, depth int, weight uint64, sink *cache.LocalSink, res *types.Result) {
    if ctx.Err() != nil {
        return
    }

    bits := st.CountBits()
    if bits >= depth { // достигнута глубина префикса — эмиссия канонической пары
        sink.Add(s.sym.Canonicalize(st, end), weight)
        res.CacheWrites++
        return
    }

    unvisited := st.Invert(s.graph.GetTotalCells())
    cand := s.graph.GetNeighborMask(end).Intersect(unvisited)

    found := 0
    for n := range cand.AllVisited() {
        newUnvisited := unvisited.Unvisit(n)
        if !newUnvisited.IsEmpty() {
            if pruned, reason := s.pruner.ShouldPruneAfterVisit(n, newUnvisited); pruned {
                res.CountPrune(reason)
                continue // пропускаем отсеченную ветвь
            }
        }
        found += s.dfs(ctx, st.Visit(n), n, depth, c, weight, res, rev)
    }
    return found
}
```

Проверка `!newUnvisited.IsEmpty()` вынесена в условие: если после посещения `n`
непосещённых не осталось — это завершённый маршрут, а не тупик.

## Примеры

### Изолированная клетка

```go
// Доска 5×5, только что посетили клетку 7
graph := graph.New(5)
p := pruner.New(graph)

// Непосещённые: 0, 2, 4, 6. Клетка 0 изолирована и является соседом 7.
unvisited := state.NewState(0, 2, 4, 6)
shouldPrune, reason := p.ShouldPruneAfterVisit(7, unvisited) // true, DeadEnd
```

### Одна оставшаяся клетка

```go
// Доска 5×5, осталась только клетка 12 (центр), последняя позиция 24
unvisited := state.Bit(12)
p.ShouldPruneAfterVisit(24, unvisited) // true, DeadEnd — 12 не соседняя к 24
```

## Тесты (`pruner/pruner_test.go`)

Локальный dead-end (миграция прежних `deadend_test.go` кейсов):

- `TestShouldPruneAfterVisit_NoUnvisited` — нет непосещённых клеток → не отсекать
- `TestShouldPruneAfterVisit_SingleUnvisitedReachable` / `..._Unreachable` — одна оставшаяся клетка (соседняя / недоступная)
- `TestShouldPruneAfterVisit_IsolatedVertexCorner` / `..._Center` / `..._TwoIsolatedVertices` — изолированные клетки
- `TestShouldPruneAfterVisit_ValidPathNotPruned` — валидные продолжения не отсекаются

Эквивалентность локальной проверки полному скану всех непосещённых клеток
(`fullScanShouldPrune`) проверяется вероятностным тестом
`TestShouldPruneAfterVisit_MatchesFullScan` (2000 случайных путей, seed 42).
После слияния прунеров тест учитывает глобальные проверки: полный скан «режет»
⟹ объединённый прунер режет с причиной `DeadEnd`; обратное не обязано
(глобальные проверки могут отсечь сверх скана, но никогда — с причиной
`DeadEnd` при целости инварианта).

### Глобальные проверки и причины

- `TestAdvancedConnectivity` — табличные кейсы: несвязный unvisited → prune с
  причиной `Disconnected`, связный → нет; одиночная клетка-остров в другой компоненте.
- `TestAdvancedDegreeHeuristic` — 3 вершины степени 1 → prune (`Endpoints`); 2 и обе не соседни
  `last` → prune (`Endpoints`); 2 и одна соседняя → не prune.
- `TestAdvanced_SingleCellSkipsGlobalCheck` — при `|unvisited| <= 1` глобальная
  проверка не выполняется (одинокая соседняя клетка — завершающий ход).
- `TestAdvancedMatchesNaive` — вероятностный equivalence: наивная реализация
  (BFS по спискам соседей + явный подсчёт степеней) против битсет-версии,
  2000 случайных состояний, seed 42.
- `TestPruneReasons` — табличные кейсы «ситуация → ожидаемая причина» для всех
  четырёх причин; не отсечённая ветвь даёт `NoReason`.

### L2 (`ShouldPruneState`)

- `TestShouldPruneState_MatchesBaseBelowThreshold` — при `|todo| < minL2`
  результат совпадает с `ShouldPruneAfterVisit` (L2 не участвует).
- `TestShouldPruneState_Articulation` — табличные кейсы: «звезда» (центр даёт
  ≥3 компоненты) → `Articulation`; цепочка без сочленений → нет; распад на 2
  компоненты при известном конце в одной из них с `cur` → `Articulation`.
- `TestShouldPruneState_ForcedChain` — обязательная степень >2 и обязательный
  цикл → `ForcedChain`; тот же граф без зафиксированного конца не отсекается.
- `TestShouldPruneState_MatchesBaseOnRandom` — вероятностный: на случайных
  состояниях отсечение L2 ⟹ наивный перебор подтверждает нулевой вклад
  (главная корректность: L2 не режет ветвь с ненулевым значением), seed 42.

## Эффективность

- **Поздние этапы поиска**: высока (когда осталось мало клеток)
- **Ранние этапы поиска**: низкая (мало изолированных клеток)

## Заключение

DeadEndPruner — простой и эффективный метод отсечения, который проверяет доступность всех непосещенных клеток. Ключевое преимущество — быстрая реализация с использованием битовых масок.
