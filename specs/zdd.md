# zdd: подсчёт гамильтоновых путей и циклов нуль-супрессированной диаграммой решений

> **Статус: измерительный инструмент (план 23 закрыт, ADR-040 «отклонено»; план 27 закрыт,
> ADR-044 «отклонено»).** Спека эталонна для пакета как инструмента ценза: standalone-построитель
> редуцированной диаграммы гамильтонова семейства плюс точки ценза `BenchmarkZDDCensus` и
> `BenchmarkZDDHalfCensus`. Пакет не импортируется в конвейер подсчёта (`counter`) и CLI;
> направление счёта 8×8 целодосочной диаграммой закрыто числами ADR-040, направление
> «произведение диаграмм половин через шов» — числами ADR-044, инструмент остаётся.

## Ответственность

Строит редуцированную нуль-супрессированную диаграмму решений (ZDD) семейства множеств рёбер
заданного графа, образующих гамильтонов путь (`Paths`) или гамильтонов цикл (`Cycles`), и считает
их весами DAG. Построение фронтьерное: переменные — рёбра в фиксированном линейном порядке, узел
кодирует степени и связность активных вершин границы; одинаковые остаточные подфункции сливаются
через уникальную таблицу (план 23).

Дополнительно пакет строит диаграмму **половины доски с открытым швом** (`HalfSession.BuildHalf`,
план 27): семейство фрагментных покрытий половины, терминалы которого — пеньки шва и локальные
глобальные концы; распределение `Sigmas()` даёт числа N_H(σ) по формализму интерфейсных состояний
(канон — `specs/split.md` и план 26), а `Glue` собирает итог доски суммой произведений таблиц двух
половин со связностью по композиции спариваний.

Пакет автономен: потребительские применения — точки ценза `BenchmarkZDDCensus` (`zdd/census_test.go`)
и `BenchmarkZDDHalfCensus` (`zdd/halfcensus_test.go`, методология — `specs/benchmarks.md` §«Ценз
живых узлов ZDD» и §«Ценз ZDD половин»); в конвейер подсчёта (`counter`) и CLI он не импортируется.
Пакет НЕ делает: параллелизма (построение однопоточное и детерминированное), интеграции с CLI и
конвейером reversal, знания о симметриях `D4` (отражение ρ для варианта `mirror` — забота обвязки
ценза), отсечений сверх точного кодирования семейства, подбора геометрии разреза (половинный граф
или обвязка ценза).

## Публичный API

```go
type Family int

const (
    Paths  Family // гамильтоновы пути: степени ≤ 2, связно, ровно две вершины степени 1
    Cycles Family // гамильтоновы циклы: степени = 2 у всех вершин
)

// ErrOverCap — сигнал, что построение превысило мягкий байтовый потолок и остановлено.
// Проверка errors.Is; счётчики момента обрыва — в OverCapError.
var ErrOverCap error

// OverCapError — ошибка обрыва при превышении потолка: Nodes — живые узлы, Bytes —
// зарезервированные байты структур построения на момент обрыва, Cap — потолок,
// действовавший при остановке (снимок, а не текущее значение рычага).
type OverCapError struct{ Nodes, Bytes, Cap int }

// OrderNarrow возвращает детерминированный порядок рёбер (перестановка индексов [0,m))
// с малой шириной разреза: подбор по ширине пересечения фронтьеры, связи разрываются
// детерминированно. Тот же вход — тот же порядок в любом процессе.
func OrderNarrow(nVerts int, edges [][2]int) []int

// Build строит редуцированную ZDD семейства fam на графе из nVerts вершин и списка рёбер;
// order — перестановка индексов рёбер, nil означает строчный порядок (как перечислены).
// Невалидный вход (неизвестное fam, nVerts больше 64 — ограничение кодировки состояния,
// выход конца ребра за [0,nVerts), петля, дубликат ребра, order не перестановка) — ошибка.
// Превышение потолка — OverCapError, не OOM.
func Build(nVerts int, edges [][2]int, fam Family, order []int) (*Diagram, error)

type Diagram struct{ /* узловая арена, уникальная таблица; содержимое не экспортируется */ }

// Count — число множеств в семействе (множества рёбер; направленные туры — умножением на 2).
func (d *Diagram) Count() uint64

// LiveNodes — число узлов арены; после успешного построения равно итоговому и пику.
func (d *Diagram) LiveNodes() int

// LevelPeak — максимум узлов на одном уровне диаграммы (измеренная ширина разреза).
func (d *Diagram) LevelPeak() int

// All перебирает множества семейства отсортированными индексами рёбер; только для тестов
// и малых графов.
func (d *Diagram) All() iter.Seq[[]int]
```

Режим открытого шва (план 27). Сборка обеих половин идёт в одной сессии: арена, уникальная
таблица и реестр байтов общие, поэтому остаточные подфункции переиспользуются между постройками.

```go
// HalfSession — сессия построек половин одного семейства: общая арена узлов, уникальная таблица
// и один реестр зарезервированных байтов на все постройки сессии.
type HalfSession struct{ /* арена, уникальная таблица, реестр; содержимое не экспортируется */ }

func NewHalfSession(fam Family) *HalfSession

// BuildHalf строит диаграмму половины доски с открытым швом. edges — рёбра половины:
// внутренние и пеньковые; stubOf[k] ≥ 0 помечает ребро k пеньком шва №stubOf[k], −1 —
// внутреннее. Пеньковое ребро обязано иметь ровно один конец с другими инцидентными
// рёбрами (реальный); второй конец — виртуальная вершина, она освобождена от требования
// покрытия и при взятии помечает компоненту терминалом, не увеличивая счётчик концов;
// виртуальные вершины не засчитываются в верх 64 реальных вершин. edgeIds[k] — глобальный
// индекс ребра k в нумерации всей доски: им именована переменная узла, поэтому переиспользование
// узлов между постройками разных половин корректно (требуются различные edgeIds внутри вызова).
// Остальной вход и ошибки — как у Build; превышение потолка сессии — OverCapError, не OOM.
func (s *HalfSession) BuildHalf(nVerts int, edges [][2]int, stubOf []int32, edgeIds []int32, order []int) (*HalfDiagram, error)

type HalfDiagram struct{ /* диаграмма половины плюс σ-таблица; содержимое не экспортируется */ }

// Sigma — каноническое интерфейсное состояние половины (S, M, ε) формализма плана 26:
// маска использованных пеньков, отсортированные слова спаривания терминалов, число
// глобальных концов. Значение сравниваемо и пригодно в качестве ключа map.
type Sigma struct{ /* каноническая упаковка: маска S, слова пар, ε */ }

// Sigmas — распределение N_H(σ) по построенной диаграмме половины: прямой проход с
// накоплением выпущенных пар; детерминировано, вызывается после успешной BuildHalf,
// вычисляется один раз и кэшируется вместе с ошибкой обрыва. Превышение мягкого потолка
// структурами прохода (промежуточные отображения уровня и таблица σ) обрывает его:
// (nil, *OverCapError) со счётчиками прогресса, сессия закрывается.
func (h *HalfDiagram) Sigmas() (map[Sigma]uint64, error)

// LiveNodes, LevelPeak — тот же контракт, что у Diagram, для половины.
func (h *HalfDiagram) LiveNodes() int
func (h *HalfDiagram) LevelPeak() int

// Glue — итог доски суммой Σ N_L(σ)·N_R(σ̄) по совместимым состояниям: равные S, для
// Paths ε_L + ε_R = 2, связность G_σ композицией спариваний (план 26). Возвращает число
// множеств рёбер (сравнение с направленными эталонами — умножением на 2) и число
// проверенных пар. Пустая таблица любой половины — итог 0, это не ошибка.
func Glue(left, right map[Sigma]uint64, fam Family) (total uint64, joins uint64)
```

Мягкий потолок — внутренний рычаг пакета, измеряемый суммарными зарезервированными байтами
структур построения: арены узлов, уникальной таблицы и послойных таблиц мемоизации.
Значение по умолчанию выведено из измеренного отношения пика резидента к зарезервированным байтам
на обрыве (калибровка ADR-042): `DefaultArenaCap = min(24, ⌊32 / r̂⌋) << 30` байт с нижней границей
`16<<30` — сейчас `22<<30`. Построение, израсходовавшее весь потолок, удерживает прогон ценза в пределах
машины 36 ГБ с запасом на перераспределение массивов при росте и на нужды рантайма; тесты изменяют
рычаг напрямую. Ручек окружения и флагов нет (ADR-020). В режиме открытого шва тот же потолок
ограничивает прогон сессии целиком: структуры построения (общие арена и уникальная таблица,
послойные таблицы мемоизации обеих половин) учитываются зарезервированными байтами на каждом шаге;
структуры σ-прохода (`Sigmas`: промежуточные отображения уровней и итоговая таблица) — оценкой
зарезервированных байтов go-отображений (payload при загрузке бакетов runtime), проверяемой на
границах уровней и по мере заполнения таблицы. Обрыв любой фазы — `OverCapError` со счётчиками
прогресса (`Nodes` — живые узлы диаграммы, `Bytes` — реестр плюс оценка, `Cap` — действовавший
потолок). После любого обрыва сессия закрыта: повторный `BuildHalf` возвращает ошибку, процесс
жив и остальные точки прогоняются.

## Инварианты

- Представляемое семейство — в точности все множества рёбер графа, образующие гамильтонов путь
  (`Paths`) или цикл (`Cycles`): связность, степень каждой вершины ≤ 2, у пути ровно две вершины
  степени 1, у цикла все степени 2. Каждое множество входит один раз независимо от направления
  обхода; сравнение с направленными эталонами — умножением на 2 (конвенция плана 23 и ADR-038).
- Редукция сохраняет семейство: никакие два узла не имеют одинаковой пары `(переменная, low, high)`;
  узла с `high`, равным нулевому терминалу, нет (нуль-супрессирование); в отличие от BDD, узел с
  `low == high` сохраняется.
- Вес узла — число множеств, представляемых подграфом этого узла; точный `uint64` без насыщения и
  переполнения на досках 5×5–8×8 (итог заведомо ниже `2^64`, вес узла не превосходит итога).
- Детерминизм: фиксированные граф и порядок дают одинаковую диаграмму (число узлов, веса, уровни)
  между прогонами и процессами; плавает только wall-время.
- Рост любой структуры построения проверяется против потолка суммарными байтами; превышение
  возвращает `OverCapError` до исчерпания памяти процесса.
- Таблица мемоизации послойная (ADR-041): уровень задаёт таблицу и тем самым длину ключа,
  поэтому в ключе нет байтов уровня, а в слоте — поля длины; пустой слот помечен `idNil`, который
  `dfs` никогда не возвращает, так что заполненность видна по одному слову id. Хранимое множество
  записей и все счётчики ценза от раскладки не зависят.
- Построенная `Diagram` неизменяема и безопасна для конкурентного чтения; `Build` — однопоточный,
  рычаг потолка во время построения не трогают. То же для `HalfDiagram`: `Sigmas()` вычисляется
  один раз после успешной постройки и кэшируется вместе с ошибкой обрыва (повторный вызов отдаёт
  тот же результат).
- Семейство открытого шва — в точности множества рёбер половины, покрывающие каждую реальную
  вершину степенями ≤ 2 без преждевременных циклов; фрагменты — дизъюнктные пути, терминалы которых
  суть пеньки и локальные глобальные концы. Для `Paths` принимается покрытие с ε ≤ 2 (для целого
  поля связность проверяется склейкой, а не половиной); для `Cycles` — строгое покрытие реальными
  степенями ровно 2, ε = 0, замкнувший цикл через шов собирается на склейке.
- Список выпущенных пар спариваний НЕ входит в ключи состояния и таблицы мемоизации; пометка
  закрытого терминала каждой живой метки компоненты входит. Два состояния с разными будущими
  выпусками пар не сливаются, поэтому `Sigmas()` точен: Σ_σ N_H(σ) равен числу множеств половинного
  семейства.
- Переменная узла уникальной таблицы — глобальный индекс ребра доски: арена и уникальная таблица
  общие для обеих построек половин, переиспользование узлов между ними корректно. Для одной
  постройки это биекция позиции порядка и ребра, поэтому целодосочная `Diagram` от перехода не
  меняется (якоря ADR-041/042 воспроизводятся бит-в-бит).
- Итог `Glue` ровно равен числу множеств рёбер доски, образующих гамильтонов путь (`Paths`) или
  цикл (`Cycles`): половины разделяют одно S, для `Paths` ε_L + ε_R = 2, объединение — единственный
  путь/цикл тогда и только тогда, когда G_σ связен (формализм плана 26).

## Ограничения и edge cases

- Граф без членов семейства → пустая диаграмма: `Count() == 0`, диаграмма сводится к нулевому
  терминалу.
- Нечётные доски для `Cycles`: граф коня двудольный с разными долями, семейство пусто; специального
  шортката не требуется — построение приходит к нулю само (шорткат допустим как оптимизация,
  результат тот же).
- `1 ≤ nVerts ≤ 64`: верх задаёт кодировка состояния — степень и метка компоненты вершины
  упакованы в один байт слота, метки выше 31 не помещаются; больше — ошибка `Build`. Рёбра без
  петель и дубликатов, концы в `[0, nVerts)`; изолированная вершина делает семейство пустым
  (её нечем покрыть).
- `order == nil` — строчный порядок; ненулевой `order` обязан быть перестановкой `[0, m)`, иначе ошибка.
- Диапазон применения в проекте — доски 5×5–8×8 (`m ≤ 168` рёбер); на произвольных графах ядро
  корректно и используется тестами с перебором.
- Режим открытого шва: половина без пеньковых рёбер вырождается в целодосочное семейство своей
  половины (σ = (∅, ∅, ε)); удвоенный пеньковый id, пеньковое ребро без реального конца, повтор
  edgeIds — ошибка `BuildHalf`. Изолированная реальная вершина делает половинное семейство пустым.
  Шорткат чётности для `Cycles` в режиме шва не применяется: половина — не целая доска, к нулю
  приходит построение.

## Тесты

- Эквивалентность перебору на малых графах (табличные, до ~12 вершин): семейство, перечисленное
  `All()`, точно совпадает с DFS-перебором множеств рёбер; точные счётчики по замкнутым формулам —
  полные графы (`K_n`: путей `n!/2`, циклов `(n−1)!/2` множеств), простой путь и простой цикл как
  графы, лес без гамильтоновых семейств; граф Петерсена — негамльтонов (ноль циклов) при ненулевом
  числе путей (число путей закрепляется оракулом).
- Сверка с эталонами `docs/requirements.md` на досках коня: `Paths × 2` и `Cycles` точно равны
  эталону. В юнит-бюджет под `-race` гарантированно входят 5×5 (`864 × 2 = 1728`), чётные и нечётные
  `Cycles` (6×6 — `9 862 × 2 = 19 724`, 7×7 — 0); сборка 6×6 `Paths` закрепляется юнит-тестом, если
  её время по итогу замера помещается в бюджет, иначе она проверяется точкой ценза с `b.Fatalf`.
- Аудит редукции: внутренний обход проверяет отсутствие пар `(переменная, low, high)`-дубликатов,
  узлов с `high` равным нулевому терминалу и недостижимых от корня узлов.
- Детерминизм: два построения одного входа — одинаковые `LiveNodes`, `LevelPeak`, `Count`.
- Потолок: намеренно заниженный рычаг даёт `ErrOverCap` со счётчиками момента обрыва (`Nodes`,
  `Bytes`) и снимком действовавшего потолка (`Cap`) на точке, которая его превышает; процесс жив,
  остальные точки прогоняются. В открытом шве так же обрывается σ-проход: когда постройка половин
  в потолок укладывается, а структуры прохода — нет, `Sigmas` возвращает `ErrOverCap`, сессия
  закрыта. Порядок рёбер `OrderNarrow` остаётся перестановкой `[0, m)` на любом
  входе, включая графы без рёбер у части вершин.
- Открытый шов — валидация входа `BuildHalf` (табличная): двойной пеньковый id, повтор глобального
  индекса ребра, пеньковое ребро без реального конца, внутреннее ребро с виртуальным концом,
  рассогласование длин массивов, отрицательный или запредельный (`≥ maxHalfEdges`) `edgeIds` —
  каждое даёт ошибку, а не панику и не безграничную аллокацию.
- Открытый шов — эквивалентность перебору на малых половинах (табличные): σ-таблица `Sigmas()`
  точно совпадает с независимым перечислением покрытий половины и классификацией σ; склейка двух
  половин малой доски даёт точный оракул пути/цикла.
- Открытый шов — эталоны на досках коня: `Glue × 2` точно равен эталону `docs/requirements.md` на
  точках, дошедших до склейки; в юнит-бюджет `-race` входят 5×5 (оба семейства) и 6×6 `Cycles`.
  Тождество вариантов: σ-таблица одной постройки с отражением ρ даёт тот же итог, что две постройки
  на чётных досках. Контроль полноты: Σ_σ N_H(σ) совпадает с числом множеств половинного семейства.
- Открытый шов — регрессия целодосочного пути: `Build` после расширения ядра даёт диаграммы и
  счётчики, бит-в-бит равные якорям ADR-041/042 (формат ключа целодосочного режима не менялся).
- Детерминизм открытого шва: две одинаковые сессии — одинаковые узлы, записи мемоизации, σ-таблицы
  и итоги `Glue`.
