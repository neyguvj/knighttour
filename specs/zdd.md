# zdd: подсчёт гамильтоновых путей и циклов нуль-супрессированной диаграммой решений

> **Статус: измерительный инструмент (план 23 закрыт, ADR-040 «отклонено»).** Спека эталонна для
> пакета как инструмента ценза: standalone-построитель редуцированной диаграммы гамильтонова
> семейства плюс бенчмарк `BenchmarkZDDCensus`. Пакет не импортируется в конвейер подсчёта
> (`counter`) и CLI; направление счёта 8×8 диаграммой закрыто числами ADR-040, инструмент остаётся.

## Ответственность

Строит редуцированную нуль-супрессированную диаграмму решений (ZDD) семейства множеств рёбер
заданного графа, образующих гамильтонов путь (`Paths`) или гамильтонов цикл (`Cycles`), и считает
их весами DAG. Построение фронтьерное: переменные — рёбра в фиксированном линейном порядке, узел
кодирует степени и связность активных вершин границы; одинаковые остаточные подфункции сливаются
через уникальную таблицу (план 23).

Пакет автономен: единственное потребительское применение — точки ценза `BenchmarkZDDCensus`
(`zdd/census_test.go`, методология — `specs/benchmarks.md` §«Ценз живых узлов ZDD»); в конвейер
подсчёта (`counter`) и CLI он не импортируется. Пакет НЕ делает: параллелизма (построение
однопоточное и детерминированное), интеграции с CLI и конвейером reversal, знания о симметриях `D4`,
отсечений сверх точного кодирования семейства.

## Публичный API

```go
type Family int

const (
    Paths  Family // гамильтоновы пути: степени ≤ 2, связно, ровно две вершины степени 1
    Cycles Family // гамильтоновы циклы: степени = 2 у всех вершин
)

// ErrOverCap — сигнал, что построение превысило мягкий байтовый потолок и остановлено.
// Проверка errors.Is; счётчики момента обрыва — в OverCapError.
var ErrOverCap error

// OverCapError — ошибка обрыва при превышении потолка: Nodes — живые узлы, Bytes —
// зарезервированные байты структур построения на момент обрыва, Cap — потолок,
// действовавший при остановке (снимок, а не текущее значение рычага).
type OverCapError struct{ Nodes, Bytes, Cap int }

// OrderNarrow возвращает детерминированный порядок рёбер (перестановка индексов [0,m))
// с малой шириной разреза: подбор по ширине пересечения фронтьеры, связи разрываются
// детерминированно. Тот же вход — тот же порядок в любом процессе.
func OrderNarrow(nVerts int, edges [][2]int) []int

// Build строит редуцированную ZDD семейства fam на графе из nVerts вершин и списка рёбер;
// order — перестановка индексов рёбер, nil означает строчный порядок (как перечислены).
// Невалидный вход (неизвестное fam, nVerts больше 64 — ограничение кодировки состояния,
// выход конца ребра за [0,nVerts), петля, дубликат ребра, order не перестановка) — ошибка.
// Превышение потолка — OverCapError, не OOM.
func Build(nVerts int, edges [][2]int, fam Family, order []int) (*Diagram, error)

type Diagram struct{ /* узловая арена, уникальная таблица; содержимое не экспортируется */ }

// Count — число множеств в семействе (множества рёбер; направленные туры — умножением на 2).
func (d *Diagram) Count() uint64

// LiveNodes — число узлов арены; после успешного построения равно итоговому и пику.
func (d *Diagram) LiveNodes() int

// LevelPeak — максимум узлов на одном уровне диаграммы (измеренная ширина разреза).
func (d *Diagram) LevelPeak() int

// All перебирает множества семейства отсортированными индексами рёбер; только для тестов
// и малых графов.
func (d *Diagram) All() iter.Seq[[]int]
```

Мягкий потолок — внутренний рычаг пакета, измеряемый суммарными зарезервированными байтами
структур построения: арены узлов, уникальной таблицы, ключей и слотов таблицы мемоизации.
Значение по умолчанию удерживает прогон ценза в пределах машины 36 ГБ с запасом на перераспределение
массивов при росте; тесты изменяют рычаг напрямую. Ручек окружения и флагов нет (ADR-020).

## Инварианты

- Представляемое семейство — в точности все множества рёбер графа, образующие гамильтонов путь
  (`Paths`) или цикл (`Cycles`): связность, степень каждой вершины ≤ 2, у пути ровно две вершины
  степени 1, у цикла все степени 2. Каждое множество входит один раз независимо от направления
  обхода; сравнение с направленными эталонами — умножением на 2 (конвенция плана 23 и ADR-038).
- Редукция сохраняет семейство: никакие два узла не имеют одинаковой пары `(переменная, low, high)`;
  узла с `high`, равным нулевому терминалу, нет (нуль-супрессирование); в отличие от BDD, узел с
  `low == high` сохраняется.
- Вес узла — число множеств, представляемых подграфом этого узла; точный `uint64` без насыщения и
  переполнения на досках 5×5–8×8 (итог заведомо ниже `2^64`, вес узла не превосходит итога).
- Детерминизм: фиксированные граф и порядок дают одинаковую диаграмму (число узлов, веса, уровни)
  между прогонами и процессами; плавает только wall-время.
- Рост любой структуры построения проверяется против потолка суммарными байтами; превышение
  возвращает `OverCapError` до исчерпания памяти процесса.
- Построенная `Diagram` неизменяема и безопасна для конкурентного чтения; `Build` — однопоточный,
  рычаг потолка во время построения не трогают.

## Ограничения и edge cases

- Граф без членов семейства → пустая диаграмма: `Count() == 0`, диаграмма сводится к нулевому
  терминалу.
- Нечётные доски для `Cycles`: граф коня двудольный с разными долями, семейство пусто; специального
  шортката не требуется — построение приходит к нулю само (шорткат допустим как оптимизация,
  результат тот же).
- `1 ≤ nVerts ≤ 64`: верх задаёт кодировка состояния — степень и метка компоненты вершины
  упакованы в один байт слота, метки выше 31 не помещаются; больше — ошибка `Build`. Рёбра без
  петель и дубликатов, концы в `[0, nVerts)`; изолированная вершина делает семейство пустым
  (её нечем покрыть).
- `order == nil` — строчный порядок; ненулевой `order` обязан быть перестановкой `[0, m)`, иначе ошибка.
- Диапазон применения в проекте — доски 5×5–8×8 (`m ≤ 168` рёбер); на произвольных графах ядро
  корректно и используется тестами с перебором.

## Тесты

- Эквивалентность перебору на малых графах (табличные, до ~12 вершин): семейство, перечисленное
  `All()`, точно совпадает с DFS-перебором множеств рёбер; точные счётчики по замкнутым формулам —
  полные графы (`K_n`: путей `n!/2`, циклов `(n−1)!/2` множеств), простой путь и простой цикл как
  графы, лес без гамильтоновых семейств; граф Петерсена — негамльтонов (ноль циклов) при ненулевом
  числе путей (число путей закрепляется оракулом).
- Сверка с эталонами `docs/requirements.md` на досках коня: `Paths × 2` и `Cycles` точно равны
  эталону. В юнит-бюджет под `-race` гарантированно входят 5×5 (`864 × 2 = 1728`), чётные и нечётные
  `Cycles` (6×6 — `9 862 × 2 = 19 724`, 7×7 — 0); сборка 6×6 `Paths` закрепляется юнит-тестом, если
  её время по итогу замера помещается в бюджет, иначе она проверяется точкой ценза с `b.Fatalf`.
- Аудит редукции: внутренний обход проверяет отсутствие пар `(переменная, low, high)`-дубликатов,
  узлов с `high` равным нулевому терминалу и недостижимых от корня узлов.
- Детерминизм: два построения одного входа — одинаковые `LiveNodes`, `LevelPeak`, `Count`.
- Потолок: намеренно заниженный рычаг даёт `ErrOverCap` со счётчиками момента обрыва (`Nodes`,
  `Bytes`) и снимком действовавшего потолка (`Cap`) на точке, которая его превышает; процесс жив,
  остальные точки прогоняются. Порядок рёбер `OrderNarrow` остаётся перестановкой `[0, m)` на любом
  входе, включая графы без рёбер у части вершин.
