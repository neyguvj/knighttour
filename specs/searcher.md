# searcher: DFS по битовым маскам и генерационные фазы

## Ответственность

Чистый слой обхода: DFS с возвратом по битовым маскам, отсечения, генерационные фазы
конвейера (specs/counter.md) и count-DFS с ранней остановкой счёта в общий task-cache.
Пакет не держит собственных таблиц мемоизации — они принадлежат вызывающему контуру.
Задача передаётся между фазами как `cache.Entry{Mask, Rep, Weight}`: каноническая маска
плюс тег класса конца (specs/cache.md, план 18). Своих типов для ключей пакет не заводит.

## Публичный API

```go
func NewSearcher(g *graph.Graph, sym *symmetry.Symmetry) *Searcher

// Единственный спуск «от старта»: DFS от канонического начала до глубины depth. Лист,
// прошедший фильтр записей (см. ниже), пишется класс-формой размещения:
// CanonicalClass(state,end) → Set(K, rep, weight), где weight — размер орбиты стартовой
// группы. Куда писать, решает вызывающий контур: sink принимает и таблицу напрямую,
// и промежуточный буфер записи Staging (cache.Sink). Так пишутся обе таблицы —
// и промежуточная таблица фазы A (малая глубина), и task-cache (ADR-018).
// Для старта с ShouldSkip(start) не пишется ничего.
func (s *Searcher) GenerateTasks(ctx context.Context, c cache.Sink,
    start int, orbitSize uint64, depth int) types.Result

// Продолжение генерации задач от записи e промежуточной таблицы — она уже является
// канонической формой «маска + класс конца» — с весом e.Weight до глубины depth.
// Запись, находящаяся уже на depth или глубже, пишется как есть в тот же слот
// (e.Mask, e.Rep) без фильтра: это вырождённый случай фазы B.
func (s *Searcher) ExtendTask(ctx context.Context, c cache.Sink,
    e cache.Entry, depth int) types.Result

// Число полных дополнений задачи (task.Mask, конец task.Rep) с ранней остановкой счёта
// на уровне totalCells−d. Остаток U = full \ T не спускается до полной доски: его закрывает
// сумма по соседям f(T,t) = Σ_{u∈N(t)∩U} W(K)[rep(u)] / orbitSize(u), снятая с таблицы
// мемоизации. task.Weight здесь не используется — взвешиванием вклада занят контур.
// Чтение идёт через безлоковый снимок cache.View: count-фаза стартует после барьера
// генерации и Seal, писателей уже нет (ADR-031, план 16). Если c == nil или
// 2d > totalCells — полный спуск без обращения к таблице.
func (s *Searcher) CountPathsWithCacheReversal(ctx context.Context, task cache.Entry,
    c *cache.View, d int) types.Result
```

## Горячий DFS: рекурсивные методы

Логика спуска общая: кандидаты, отсечения, проверка `ctx.Err()`. Различие — только
**в базовом случае**:

| | `dfsTask` (генерация таблицы) | `dfsCount` (счёт с обращением) |
|---|---|---|
| Условие стопа | Срабатывает при `CountBits(st) >= depth`. | При `bits == stopLevel` ответ даёт `completions`; при полном покрытии (`bits >= totalCells`) возврат 1. |
| Действие на стопе | Если лист прошёл фильтр, пишет класс-форму: `CanonicalClass(st,end)` → `c.Set(K, rep, weight)`. | Делает один `Get(K)` на вызов и суммирует по `u ∈ N(end)∩U`: попадание в слот класса добавляет `W/orbitSize`, промах добавляет 0. |
| Статистика | `CacheWrites` считает фактические записи `Set`; отсечения фильтра попадают в `CountPrune`. | `TotalPathsFound` — число найденных дополнений; `CacheHits`/`CacheMisses` считают каждую проверку-конец. |

**Фильтр записей** стоит в базовом случае `dfsTask`: перед канонизацией вызывается
`pruner.ShouldPruneState(end, st.Invert(totalCells))`. Если лист отсечён, выполняется
`res.CountPrune(reason)`, а записи нет — отсечённый лист не платит за канонизацию. Спуск
один, поэтому один хук покрывает обе таблицы: и промежуточную `gen A`, и task-cache.
Вырождённый случай `ExtendTask` (`e.Mask.CountBits() >= depth`) фильтр обходит: это ровно
тот же слот `(K, rep)`, что лист фазы A, уже прошедший ту же проверку.

Каноническая форма при записи вычисляется одним вызовом общей функции писателя и читателя
`symmetry.CanonicalClass(st, end) → (K, rep, ·)` (specs/symmetry.md). Размер орбиты
писателю не нужен — вес вклада приходит параметром. Лишней работы по проверке уникальности
на листе не выполняется: писатель и читатель вызывают одну и ту же функцию, поэтому
согласование канонических форм гарантировано конструктивно.

`dfsTask` — единственный генерационный спуск: через него пишутся и промежуточная таблица
фазы A, и task-cache (ADR-018). С `dfsCount` он не объединяется колбэком: рекурсия
с функциональным параметром не инлайнится, а базовый случай — единственное различие
спусков. Дублировать цикл дешевле.

Метод `completions` корректен по дуальности обращения тура. Каждое дополнение `(T,t)`
обращается в суффикс, который покрывает ровно `U = full \ T` и кончается соседом `t`
клетки конца, поэтому `f(T,t) = Σ_{u∈U, u~t} h(U,u)`.

Каноническая форма считается один раз на маску: `CanonicalMaskFrame(U) → (K, frame, stab)`.
На весь вызов приходится ровно один `Get(K)` — все концы этого остатка делят одну маску.
Каждого кандидата `u ∈ N(t)∩U` переводят в систему координат `K` преобразованием `frame`
(`TransformCell`) и сводят к тегу класса (`ClassRep`). Ответ берут из слота гистограммы
`Weight(rep)`, а слагаемое равно `W / CellOrbitSize(stab, rep)`. Деление точное: вес класса —
сумма размеров орбит префиксов этого класса, что обобщает ADR-011 с пары на класс.

Промахи устроены так: если маски нет в таблице, все проверки вызова считаются промахами
и дают нулевой вклад; если маска есть, а слота класса нет — промах засчитывается только
этой проверке. Писатель и читатель вызывают одни функции symmetry, поэтому совпадение
канонизации обеспечено конструктивно — расхождение tie-break исключён (specs/symmetry.md).

Общее для обоих спусков: на входе проверка `ctx.Err()`; далее маска непосещённых клеток
`unvisited := st.Invert(totalCells)` и кандидаты `GetNeighborMask(end).Intersect(unvisited)`,
перебираемые через `AllVisited()`. Перед спуском в кандидата прунер проверяет ветку —
`ShouldPruneAfterVisit(n, newUnvisited)` с записью причины в `res.CountPrune(reason)`;
пустой остаток не проверяется. Горячий цикл не аллоцирует: фильтр записей — проверка
прунера без сохранения состояния, порядка O(V+E), с его стековым рабочим массивом,
а канонизация сводится к обращениям к таблицам подстановки.

## Лемма безопасности фильтра записей

Запись-класс `(K, rep)` с весом `W` (маска глубины `depth`, конец — клетка той же маски)
участвует в итоге двояко: как задача `W·f(K,rep)` и как ответ на запросы к мемоизации задач
с остатком `K`. Фильтр проверяет необходимое условие существования дополнения
(specs/pruner.md). Если условие не выполнено, класс отвергается, и пропуск записи не меняет
итог `Σ W·f`:

1. **Собственный вклад.** У отвергнутого класса `f(K,rep) = 0`, поэтому слагаемое
   `W·f(K,rep)` нулевое. Функция `f` постоянна на классе: смена репрезентанта конца её
   не меняет.
2. **Запросы к мемоизации.** Count-фаза запрашивает слот `(K, rep(U,u))` только на уровне
   стопа, из достигнутого состояния `(full\U, t)` при `t ∈ N(u)`. Значит запрос происходит,
   только когда существует путь, покрывающий `full\U` и кончающийся соседом `u`. По дуальности
   обращения это в точности `f(U,u) > 0`. Мёртвый класс не запрашивается никогда — отсутствие
   его записи не добавляет ни промаха, ни потерянного слагаемого.
3. **Согласованность с канонизацией.** Предикат эквивариантен относительно D4, поэтому
   мёртвость — свойство класса (всей орбиты пары), и решение не зависит от выбранного
   представителя. Фильтр вычисляется до канонизации — на самом состоянии листа.

## Инварианты и корректность

- `dfsTask` считает **размещения**: сколько раз встретился префикс с точностью до D4.
  Аддитивный `Set(K, rep, ·)` объединяет совпадающие классы размещений в один вес слота.
  Концы одной маски, не связанные стабилизатором, живут разными слотами одной записи.
- `GenerateTasks` и `ExtendTask` пишут канонические префиксы глубины `depth`. Если у
  `ExtendTask` выполнено `e.Mask.CountBits() >= depth`, он пишет запись `e` как есть в слот
  `(e.Mask, e.Rep)`; иначе вырождённая фаза B (precomputeDepth ≤ base) теряла бы записи.
  Ниже порога спуск продолжается от клетки `e.Rep`, а листья пишутся в канонической форме.
  Спуск легален: `rep` — реальная клетка маски, минимум её орбиты стабилизатора
  (specs/symmetry.md). Выбор представителя класса итог не меняет: `f` и D4-образия спуска
  постоянны на классе. `ShouldSkip` в `ExtendTask` не проверяется — корни отфильтрованы
  фазой A.
- Тождество count-фазы: `total = Σ_tasks W(task) · f(task)`. Задачи — развёрнутые записи
  таблицы, по одной на класс (specs/cache.md); `f` — count-DFS со стопом на уровне
  `totalCells − d`. Мемоизация отвечает по точной маске и слоту класса, деление
  `W/orbitSize` точно (ADR-011 в форме «маска + класс», план 18). Фильтр записей сокращает
  множество задач только классами с нулевым `f` (лемма выше), поэтому тождество сохраняет
  силу.

## Ограничения и edge cases

- `depth = 0` в `GenerateTasks`: одна запись — сам старт. Фильтр выполняется и на ней:
  на пустом остатке его условие может оказаться ничего не запрещающим, но по безопасности
  отсечения живые старты он не режет.
- Отклонённые эвристики (цветовое отсечение, эвристика Варнсдорффа) не реализованы — ADR-009.

## Тесты

`searcher/searcher_test.go`:

- `TestNaiveBruteForceMatchesKnownTotal` — независимый перебор даёт 1728 на доске 5×5.
- `TestFullCountViaGenerateTasksMatchesKnownTotal` — при `depth = totalCells` сумма весов
  по группам равна эталону; на пустом остатке фильтр ничего не режет.
- `TestGenerateTasksEmitsCanonicalPrefixes` — записи есть класс-слоты глубины `depth`,
  вес каждого кратен размеру орбиты группы.
- `TestGenerateTasksDepthZeroEmitsStart` — при `depth = 0` ровно одна запись, сам старт.
- `TestGenerateTasksSkipsWrongColor` — старт с `ShouldSkip` не пишет ничего.
- `TestReversalMatchesBruteForceAllDepths` — таблично по всем допустимым d на 5×5:
  `Σ W · CountPathsWithCacheReversal(task)` по задачам, развёрнутым `View.All` из таблицы
  `GenerateTasks`, равен перебору; сверяется и итог, и каждая задача отдельно.
- `TestExtendTaskWritesEntryAsIsAtTargetDepth` — вырожденный `ExtendTask` при
  `bits == depth` пишет запись как есть в слот `(K, rep)`, без спуска и повторной
  канонизации.
- `TestCountPathsWithCacheReversalFullDescentIdentities` — при `c == nil` и при
  `2d > totalCells` результат тождествен полному спуску, таблица не затрагивается
  (нули в hits/misses).
- `TestReversalStopLookupsHappenAtStopLevel` — сумма hits и misses равна числу
  проверок-концов на уровне стопа: по одной на каждый `u ∈ N(t)∩U`. Hit — найденный слот
  класса; hits бывают только на уровне стопа.
- `TestWriterReaderCanonicalizationAgree` — на случайных парах (seed фиксирован)
  `CanonicalClass(st,end)` совпадает с композицией читателя `CanonicalMaskFrame →
  TransformCell → ClassRep`; результат не зависит от выбранного argmin-кадра.
- `TestWriteGateRejectsOnlyDeadClasses` — тест леммы: на 5×5 внутренним обходом всех
  листьев фиксированной глубины собирается множество классов, отвергнутых фильтром, и для
  каждого перебором проверяется `f = 0`.
- `TestExtendTaskViaStagingMatchesDirect` — `ExtendTask` через промежуточный буфер
  `Staging` даёт ту же таблицу, что прямая запись (ADR-031).
