# Компонент Searcher: Основной алгоритм поиска

## Назначение

DFS backtracking по битовым маскам для подсчёта всех открытых маршрутов коня с
прунингом (dead-end + связность + эвристика концов) и две генерационные фазы
единого class-mode пайплайна (counter.md, shapecount.md).

Исторически здесь жили legacy-механизмы (`Reversal`/prefix-cache, `GenerateSubtasks`,
`ExtendSubtask`, `CountPaths*`) — после унификации через классы форм они удалены:
кеширование продолжений целиком вынесено в эмиссию классов и DP финального прохода.

## Структура данных

```go
type Searcher struct {
    graph  *Graph         // граф смежности
    sym    *Symmetry      // D4-канонизация префиксов, нормализация форм
    pruner *pruner.Pruner // отсечение тупиков + связность + эвристика концов
}

func NewSearcher(graph *Graph, sym *Symmetry) *Searcher
```

## Публичные методы

### 1. GenerateRoots(ctx, sink *cache.LocalSink, start int, orbitSize uint64, depth int) types.Result

Фаза A (gen A): DFS от канонического старта до глубины `depth`; на достижении —
эмиссия канонической пары в промежуточный аккумулятор:

```go
sink.Add(s.sym.Canonicalize(st, end), orbitSize) // res.CacheWrites++
```

1. Если `SholdSkip(start)` — пустой результат (фильтр чётности для нечётных досок).
2. Спуск с прунингом; ниже `depth` не идёт.
3. Статистика: `CacheWrites` (число эмиссий), разбивка прунинга по видам.

### 2. ExtendToClasses(ctx, sink *cache.LocalSink, p path.Path, weight uint64, depth int) types.Result

Фаза B (gen B): спуск от записи `p` до целевой `depth`; на листьях вместо
префиксной записи — эмиссия классов дополнений в аккумулятор M (shapecount.md):
для листа `(T,t)`, `U = full \ T` и каждого `u ∈ N(t) ∩ U`:

```go
sink.Add(s.sym.KeyFromPrepared(&sc, u), weight) // маска U нормализуется один раз на лист
```

Эмиссия происходит при `CountBits(st) >= depth`, включая вырожденный вход
`CountBits(p.State()) == depth` (глубина `precomputeDepth ≤ base`: генерация
останавливается уже на промежуточных записях, продолжений нет — M строится
прямо из них). `SholdSkip` не проверяется: корни отфильтрованы фазой A.

**Корректность перегруппировки.** `total = Σ_листьев weight·Σ_u h(U,u) =
Σ_C h(C)·M(C)` — точная перегруппировка суммы, размещения учтены эмиссией по
фактическим листьям (shapecount.md «Математика»).

## Горячий DFS

Два рекурсивных метода; спуск (кандидаты, прунинг, `ctx.Err()`, условие
`CountBits(st) >= depth`) у них общий, различие — **в базовом случае**: что
именно кладётся в sink на листе.

```go
// Спуск фазы A: на bits >= depth — sink.Add(Canonicalize(st,end), weight).
func (s *Searcher) dfsGen(ctx context.Context, st state.State, end, depth int, weight uint64, sink *cache.LocalSink, res *types.Result)

// Спуск фазы B: на bits >= depth — нормализация U = full\st и эмиссия
// KeyFromPrepared(U, u) по всем u ∈ N(end) ∩ U; sink.Add(..., weight).
func (s *Searcher) dfsEmit(ctx context.Context, st state.State, end, depth int, weight uint64, sink *cache.LocalSink, res *types.Result)
```

### Чем принципиально отличаются `dfsGen` и `dfsEmit`

| | `dfsGen` (фаза A) | `dfsEmit` (фаза B) |
|---|---|---|
| Смысл листа | префикс — готовая запись аккумуляторA | префикс — только заготовка; считывается его **дополнение** |
| Ключ эмиссии | само размещение: `Canonicalize(st, end)` — D4-канон пары `(T, t)` | класс формы дополнения: `U = full \ T`, для каждого `u ∈ N(t) ∩ U` — `KeyFromPrepared(&sc, u)` (D4 ⋉ трансляции) |
| Эмиссий на лист | ровно 1 | `|N(t) ∩ U|` (0…8), все с одним весом |
| Стоимость нормализации | `Canonicalize` на каждый лист (один ключ) | `PrepareShape(U, &sc)` **один раз на лист** + дешёвый `KeyFromPrepared` на каждый конец — амортизация по степеням |
| Источник веса | `orbitSize` стартовой группы (симметрия старта, приходит сверху) | накопленный вес `W` промежуточной записи (пришёл из фазы A / чанка) |
| Пустой `cand` на листе | префикс эмится всё равно (он корректен сам по себе) | **ноль эмиссий**: дополнение не замыкается ни в один тур, вклад в M равен 0 — семантически верно, а не потеря |
| Порядок проверок | глубина проверяется до вычисления `unvisited`/`cand` (на листе они не нужны) | `unvisited`/`cand` вычисляются до проверки глубины: они нужны в базовом случае |

Инвариант, связывающий фазы: `dfsGen` отвечает за **размещения** (сколько раз
встретился префикс с точностью до D4 старта), `dfsEmit` — за **формы дополнений**
(скольким размещениям служит продолжение данный хвост). Именно поэтому веса в
них нельзя переставлять, а эмиссии `dfsEmit` умножаются на степень конца.

Оба: `ctx.Err()` на входе; `unvisited := st.Invert(totalCells)`; кандидаты —
`graph.GetNeighborMask(end).Intersect(unvisited)`, перебор итератором
`AllVisited()`; прунинг `ShouldPruneAfterVisit(n, newUnvisited)` с
`res.CountPrune(reason)`. Без аллокаций в горячем цикле (`ShapeCtx` — на стеке).

Спуски не объединяются колбэком: рекурсия с function-параметром не инлайнится,
а базовый случай — единственная разница, дублирование цикла дешевле.

## Result — аккумулятор статистики подзадачи

```go
type Result struct {
    TotalPathsFound int // сейчас никто не заполняет (внутренний dfs полного счёта удалён)
    CacheWrites     int // эмиссии в аккумуляторы (обе генерационные фазы)
    Pruned          int // сумма разбивки ниже (Finalize)
    PrunedDeadEnd, PrunedNoCont, PrunedDisconn, PrunedEndpoints int
}
```

Поля `CacheHits/CacheMisses` удалены вместе с reversal-lookup'ами. Публичные
методы вызывают `Finalize()` перед возвратом; внутри DFS `Pruned` не
поддерживается (лишний store на каждом prune).

## Прунинг

`pruner.ShouldPruneAfterVisit(last, unvisited)`: локальный dead-end за O(deg),
затем связность `G[unvisited]`, обязательный сосед у `last`, эвристика концов —
подробности в `pruner.md`. Эквивариантен D4 (безопасен для канонизации).

## Экспериментальные прунинги (замерены на 5×5/6×6, НЕ реализованы)

- **Цветовой (бипартитный)** — 0 срабатываний: инвариант выполняется автоматически
  вдоль любого DFS-пути, старты нужного чёта фильтрует `SholdSkip`.
- **Warnsdorff-порядок кандидатов** — число узлов не меняется, время +10–20%.

## Тесты

Внутренний `dfs` полного счёта удалён; полный счёт в тестах сверяется тремя
независимыми способами:

- Независимый brute-force (обычная рекурсия по спискам смежности, без прунинга
  и битбордов): сумма по всем стартам 5×5 == 1728.
- `GenerateRoots` с `depth = totalCells`: листья — полные туры, сумма весов по
  каноническим группам == 1728 (D4-инвариантность числа туров + нулевые вклады
  `SholdSkip`-стартов).
- `ExtendToClasses` с `depth = totalCells-1`: каждый полный путь эмитит ровно
  один одноклеточный класс дополнения, `h({u},u) == 1`, поэтому `Σ weight·h(C)`
  — точный «простой» счёт; им проверяется тождество `Σ h(C)·M(C)` на средних
  глубинах (дополнительно — сверка с brute-force на малой выборке корней).
- `GenerateRoots`: эмиссии = префиксы глубины depth, веса кратно орбите;
  `depth=0` — одна запись (сам старт).
- вырожденный вход `bits == depth` в `ExtendToClasses` эмитит сразу.

## Заключение

Searcher — чистый слой обхода: генерационные фазы пишут веса в аккумуляторы,
подсчёт живёт в shapecount DP. Никаких мемо-таблиц и reversal-тождеств внутри.
