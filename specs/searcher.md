# searcher: DFS по битовым маскам и генерационные фазы

## Ответственность

Чистый слой обхода: DFS backtracking по битмаскам с прунингом, генерационные фазы конвейера
(specs/counter.md) и count-DFS с ранним стопом в общий task-cache. Сам внутри мемо-таблиц не
держит — таблицы принадлежат вызывающему контуру. Носитель задачи между фазами —
`cache.Entry{Mask, Rep, Weight}`: каноническая маска плюс тег класса конца (specs/cache.md,
план 18); пакет не конструирует ключей своих типов.

## Публичный API

```go
func NewSearcher(g *graph.Graph, sym *symmetry.Symmetry) *Searcher

// Единственный спуск «от старта»: DFS от канонического начала до глубины depth; на листьях —
// если лист прошёл гейт записи (см. ниже) — класс-форма размещения в переданный sink
// (cache.Sink: таблица напрямую или батч-Staging — выбор за вызывающим контуром):
// CanonicalClass(state,end) → Set(K, rep, weight), weight = orbitSize стартовой группы.
// Пишет и промежуточную таблицу фазы A (малая глубина), и task-cache (ADR-018).
// ShouldSkip(start) → пустой результат (фильтр чётности нечётных досок).
func (s *Searcher) GenerateTasks(ctx context.Context, c cache.Sink,
    start int, orbitSize uint64, depth int) types.Result

// Продолжение task-генерации от записи промежуточной таблицы e (уже каноническая форма
// «маска + класс конца») с весом e.Weight до depth; запись уже на depth (или глубже)
// пишется как есть в тот же слот (e.Mask, e.Rep) без гейта (вырожденная фаза B).
func (s *Searcher) ExtendTask(ctx context.Context, c cache.Sink,
    e cache.Entry, depth int) types.Result

// Число полных дополнений задачи (task.Mask, конец task.Rep) с ранним стопом на уровне
// totalCells−d: остаток U = full\T answering'ется суммой W(K)[rep(u)]/orbitSize по
// u ∈ N(t)∩U из мемо-ридера. task.Weight не используется — взвешивание вклада делает
// контур. Мемо читается безлоковым cache.View (ADR-031, план 16): count-фаза идёт после
// барьера генерации и Seal, писателей нет. c == nil или 2d > totalCells → полный спуск
// без обращения.
func (s *Searcher) CountPathsWithCacheReversal(ctx context.Context, task cache.Entry,
    c *cache.View, d int) types.Result
```

## Горячий DFS: рекурсивные методы

Спуск общий (кандидаты, прунинг, `ctx.Err()`); различие — **в базовом случае**:

| | `dfsTask` (генерация таблицы) | `dfsCount` (count с reversal) |
|---|---|---|
| Стоп | `CountBits(st) >= depth` | `bits == stopLevel` — ответ через `completions`; `bits >= totalCells` → 1 |
| Действие на стопе | гейт → `CanonicalClass(st,end)` → `c.Set(K, rep, weight)` | один `Get(K)` на вызов + Σ по `u ∈ N(end)∩U`: `Weight(rep(u))`, hit → `+ W/orbitSize`, промах → 0 |
| Статистика | `CacheWrites` — фактические эмиссии `Set` (вклады классов), прунинг гейта в `CountPrune` | `CacheHits`/`CacheMisses` на каждую проверку-конец, `TotalPathsFound` — число дополнений |

**Гейт записи** в базовом случае `dfsTask`: перед канонизацией вызвать
`pruner.ShouldPruneState(end, st.Invert(totalCells))`; прунуто → `res.CountPrune(reason)` и
записи нет (отсечённый лист канонизацию не платит). Один хук покрывает обе таблицы
(промежуточную gen A и task-cache gen B) — спуск общий. Degenerate self-write `ExtendTask`
(`e.Mask.CountBits() >= depth`) гейта не проходит: это ровно тот же слот `(K, rep)`, что лист
фазы A, уже пропустивший гейт той же проверкой.

Канонизация на записи — один вызов общей функции писателя и читателя
`symmetry.CanonicalClass(st, end) → (K, rep, ·)` (specs/symmetry.md): `orbitSize` писателю не
нужен (вес вклада приходит параметром), cycle уникальности с листа уходит.

`dfsTask` — единственный генерационный спуск: пишут им и промежуточную таблицу фазы A, и
task-cache (ADR-018). Он не объединяется колбэком с `dfsCount`: рекурсия с function-параметром
не инлайнится, а базовый случай — единственная разница; дублирование цикла дешевле.

`completions` корректен из дуальности обращения тура: каждое дополнение `(T,t)` обращается в
суффикс, покрывающий ровно `U = full\T` и кончающийся соседом `t`, поэтому
`f(T,t) = Σ_{u∈U, u~t} h(U,u)`. Каноническая форма считается один раз на маску:
`CanonicalMaskFrame(U) → (K, frame, stab)`; далее **один `Get(K)` на вызов** — все концы этого
остатка делят одну маску. По каждому `u ∈ N(t)∩U`: конец переводится в систему координат `K`
преобразованием `frame` (`TransformCell`) и сводится к тегу класса (`ClassRep`); ответ берётся
из слота гистограммы `Weight(rep)`, слагаемое — `W / CellOrbitSize(stab, rep)`, деление точное
(вес класса — сумма размеров орбит префиксов класса, обобщение ADR-011 с пары на класс).
Промахи: маски нет в таблице → все проверки вызова промахи (слагаемых 0); маска есть, слота
класса нет → промах этой проверки. Писатель и читатель вызывают одни и те же функции symmetry,
поэтому совпадение канонизации гарантировано конструктивно (tie-break исключён, specs/symmetry.md).

Общее: `ctx.Err()` на входе; `unvisited := st.Invert(totalCells)`; кандидаты
`GetNeighborMask(end).Intersect(unvisited)`, перебор `AllVisited()`; прунинг
`ShouldPruneAfterVisit(n,newUnvisited)` с `res.CountPrune(reason)`. Без аллокаций в горячем
цикле (гейт — стейт-лесс O(V+E)-проверка pruner'а со стековым scratch; канонизация — только
подсмотры в LUT).

## Лемма звукосности гейта записи

Запись-класс `(K, rep)` с весом `W` (маска глубины `depth`, конец класса `rep`) участвует в
итоге двояко: как задача `W·f(K,rep)` и как ответ мемо задачам с остатком `K`. Если предикат
гейта ложен (он — необходимое условие существования дополнения, specs/pruner.md), то пропуск
записи итог `Σ W·f` не меняет:

1. **Собственный вклад**: `f(K,rep) = 0` ⟹ слагаемое `W·f(K,rep)` нулевое (f постоянна на
   классе — конец-репрезентант representative не важен).
2. **Мемо-запросы**: count-фаза запрашивает слот `(K, rep(U,u))` только на уровне стопа из
   достигнутого состояния `(full\U, t)` с `t ∈ N(u)`, т.е. тогда и только тогда, когда
   существует путь, покрывающий `full\U` и кончающийся соседом `u`. По дуальности обращения
   это в точности `f(U,u) > 0`. Значит **мёртвый класс не запрашивается никогда** — отсутствие
   записи не добавляет ни промаха, ни потери.
3. **Согласованность с канонизацией**: предикат D4-эквивариантен, поэтому «мёртвость» —
   свойство класса (всей орбиты пары), и решение не зависит от выбранного представителя;
   гейт вычисляется до канонизации — на самом состоянии листа.

## Инварианты и корректность

- `dfsTask` отвечает за **размещения** (сколько раз встретился префикс с точностью до D4):
  аддитивный `Set(K, rep, ·)` схлопывает совпадающие классы размещений в один вес слота;
  концы одной маски, не связанные стабилизатором, живут разными слотами одной записи.
- `GenerateTasks`/`ExtendTask` пишут канонические префиксы глубины `depth`; `ExtendTask` при
  `e.Mask.CountBits() >= depth` пишет саму запись `e` как есть в слот `(e.Mask, e.Rep)` —
  иначе вырожденная фаза B (precomputeDepth ≤ base) теряла бы записи; ниже порога спуск
  продолжается от клетки `e.Rep` и листья пишутся канонизованными. Спуск легален: `rep` —
  реальная клетка маски (минимум stab-орбиты, specs/symmetry.md), а выбор представителя
  класса не меняет итога — f и D4-образия спуска постоянны на классе. `ShouldSkip` в
  `ExtendTask` не проверяется: корни отфильтрованы фазой A.
- Тождество count-фазы: `total = Σ_tasks W(task) · f(task)`, где задачи — развёрнутые записи
  таблицы (по одной на класс, specs/cache.md), `f` — count-DFS со стопом на уровне
  `totalCells − d`; мемо отвечает по точной маске и слоту класса, деление `W/orbitSize` точно
  (ADR-011 в форме «маска + класс», план 18). Гейт записи множество задач сокращает только
  нулевыми по `f` классами (лемма выше) — тождество сохраняет силу.

## Ограничения и edge cases

- `depth = 0` в `GenerateTasks` — одна эмиссия (сам старт): гейт на ней выполняется без
  предусловия L0/L1 (звукó, но может быть пустым) и живые старты не режет.
- Отклонённые эвристики (цветовой прунинг, Warnsdorff) не реализованы — ADR-009.

## Тесты

`searcher/searcher_test.go`: независимый brute-force == 1728 на 5×5; `GenerateTasks` с
`depth=totalCells` → сумма весов по группам == эталон (гейт на пустом остатке ничего не режет);
записи = класс-слоты глубины depth (веса кратно орбите), `depth=0` — одна эмиссия,
`ShouldSkip`-старт не пишет ничего. Reversal: таблично по всем допустимым d на 5×5 —
`Σ W·CountPathsWithCacheReversal(task)` по задачам, развёрнутым `View.All` из таблицы
`GenerateTasks`, == brute-force (эквивалентность итогов в класс-форме). Вырожденный
`ExtendTask(bits==depth)` пишет запись как есть в слот `(K, rep)`; `c == nil` и
`2d > totalCells` → тождество полному спуску; hits+misses == числу проверок-концов на уровне
стопа (по одной на `u ∈ N(t)∩U`; hit — найденный слот класса, hit'ы только на уровне стопа).
Tie-break единства функции: таблично на случайных парах (seed фиксирован) —
`CanonicalClass(st,end)` совпадает с композицией читателя `CanonicalMaskFrame → TransformCell →
ClassRep` (форма писателя = форма читателя); плюс независимость от выбора argmin-кадра. Гейт:
отдельный тест леммы — на 5×5 собрать множество классов, отказанных гейтом (внутренний обход
всех листьев фиксированной глубины), и brute-force проверить `f(класс) = 0` для каждого.
`ExtendTask` через батч-Staging sink даёт ту же таблицу, что прямая запись (ADR-031).
