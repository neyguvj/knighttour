# pairs: попарный счёт гамильтоновых путей между фиксированными клетками

## Ответственность

Считает матрицу `N(s,t)` — число направленных гамильтоновых путей графа коня из клетки `s` в клетку
`t`. Строка матрицы — анкерёванный спуск от старта до полного покрытия с гистограммой последней
клетки; полная матрица строится по каноническим представителям D4-орбит стартов и доопределяется
эквивариантностью. Пакет — самостоятельный контур поверх `graph`, `state`, `pruner`, `symmetry`,
`workerpool`; он не импортируется в конвейер подсчёта (`counter`) и CLI, и сам не трогает ни
`searcher`, ни `cache`. Контракт введён планом 28 как инструмент независимых проверок счётчика.

## Публичный API

```go
// Row возвращает распределение концов направленных гамильтоновых путей из клетки start:
// out[t] = N(start,t). Полный спуск с отсечениями прунера; мемоизации и симметрийного
// сокращения внутри строки нет — фиксированный старт ломает D4. Предусловие:
// 0 <= start < g.GetTotalCells(). Детерминирован; завершившийся ctx даёт частичный вектор
// без паники.
func Row(ctx context.Context, g *graph.Graph, start int) []uint64

// Matrix — таблица N(s,t) для всех пар клеток доски. Непрозрачна; доступ через At и Total.
type Matrix struct{ /* поле-срез row-major значений и размер доски; раскладка не экспортируется */ }

// Compute считает матрицу: строки — для канонических представителей орбит стартов
// (symmetry.GetCanonicalGroups), параллельно через workerpool.Pool.Run; остальные клетки
// доопределяются последовательно формулой N(σs, σt) = N(s,t). Итог детерминирован и не
// зависит от workers. Завершившийся ctx даёт частичную матрицу без паники.
func Compute(ctx context.Context, g *graph.Graph, workers int) *Matrix

// At — число направленных гамильтоновых путей из s в t; вне диапазона клеток — panic.
func (m *Matrix) At(s, t int) uint64

// Total — сумма всех клеток матрицы: направленный итог доски как множество путей.
func (m *Matrix) Total() uint64
```

Неэкспортируемый `mitmRow(ctx, g, start, m)` — независимый зонд той же строки meet-in-the-middle.
Префиксы длины `m` из старта складываются в карту `(маска, конец) → вес`; затем для каждой
клетки-конца строится таблица обращённых суффиксов, и зонд склеивает стороны по дополняющей маске
со смежностью концов. Используется тестами и зондовым бенчмарком того же пакета; в публичный API
не входит.

Неэкспортируемый `rowCensus(ctx, g, start, hooks)` — инструментированный цензом двойник `Row`
(план 29): тот же спуск и побитово та же гистограмма (счётчики узлов и листьев — наблюдатели), плюс
отметки прогресса через колбэк. Проверка ctx живёт на рабочем тике (`hooks.tickNodes` узлов), а не
на каждом узле; завершившийся ctx даёт частичную гистограмму без паники, детерминизм счётчиков
между прогонами сохраняется. Публичный API (`Row`, `Compute`) от его появления не изменился;
используется только тестами и цензовыми бенчмарками того же пакета
(`BenchmarkPairsCensus`, методология — specs/benchmarks.md).

## Инварианты

- `Row` точна по определению: каждый направленный путь даёт ровно один лист спуска, его последняя
  клетка получает единицу. Отсечения прунера — необходимое условие дополняемости (specs/pruner.md),
  итог не меняют.
- Матрица симметрична: `At(s,t) = At(t,s)` (обращение пути).
- Матрица эквивариантна относительно D4: `N(σs, σt) = N(s,t)` для любого преобразования; строки
  представителей доопределяют все клетки без потери точности.
- Сумма строки равна счёту туров из старта: `Σ_t Row(s)[t]` совпадает с суммой весов таблицы,
  записанной `searcher.GenerateTasks(..., start, 1, totalCells)` (тест на существующем API).
- `Total()` равен направленному итогу доски того же размера: тем же эталонам, что и конвейер
  (docs/requirements.md).
- Детерминизм: один вход даёт бит-в-бит одинаковую матрицу при любом `workers` и между прогонами.

## Ограничения и edge cases

- Область контракта — доски проекта 5×5–8×8; на меньших досках ядро корректно и проверяется
  оркул-тестами.
- `N(s,s) = 0`: гамильтонов путь длиннее одной клетки не может кончиться стартом.
- Цветовой паритет: на чётной доске ненулевые клетки — только для пар противоположных цветов, на
  нечётной — только для пар большинства; нули возникают естественно спуском, отдельного шортката нет.
- Завершившийся ctx (отмена или deadline) останавливает спуск строки и выдачу задач пулом:
  `Row`/`Compute` возвращают частичный результат без паники — тот же контракт, что у конвейера.
- Пакет не ведёт мониторинг фаз и статистику `types.Result`: это внеконвейерный инструмент.

## Тесты

`pairs/pairs_test.go` (имена фиксируются при реализации):

- Оркул на 5×5: независимый наивный перебор пар `(s,t)` совпадает с `Compute` по всем клеткам;
  он же сверяет `Row` против перебора строки.
- Якоря сумм: `Σ_{s,t} = 1728` (5×5) и `= 6 637 920` (6×6); сумма строки против счёта туров из
  старта через `searcher.GenerateTasks` полной глубины (5×5 — все клетки, 6×6 — выборка).
- Симметрия обращения и D4: матрица симметрична; восстановленные строки сверяются с прямым `Row`
  на всех клетках 5×5 и на выборке членов орбит 6×6.
- Цветовой паритет: нулевые клетки матрицы совпадают с классификацией цветов.
- Инвариантность к числу воркеров и детерминизм между прогонами; завершившийся ctx — частичный
  результат без паники (таблица: отмена, deadline).
- MITM-зонд на 5×5: `mitmRow` совпадает с `Row` по всем строкам; на 6×6 — по правилу плана 28
  (обычный тест одной строки либо gated-бенчмарк `BenchmarkPairsProbe`, методология —
  specs/benchmarks.md).
- Инструментированный спуск (план 29): гистограмма совпадает с `Row` на 5×5 и 6×6, счётчики
  детерминированы между прогонами, отметки на степенях узлов воспроизводимы; завершившийся ctx
  останавливает спуск ровно на тике и даёт частичную гистограмму без паники. Ценз полупутей
  воспроизводит колонки `walksP`, `walksT`, `entries` зонда плана 28: на 5×5 живьём, на 6×6
  префиксная сторона прибита историческим числом.
