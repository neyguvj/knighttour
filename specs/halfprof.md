# halfprof: ценз счёта открытых туров половинными профилями Чернова–Маккея

> **Статус: измерительный инструмент (план 30).** Пакет считает число открытых
> туров (гамильтоновых путей) доски N×N методом половинных профилей: половины
> перечисляются поиском с возвратом с линейной памятью, профиль шва извлекается
> на выходе половины, количества агрегируются по профилю, склейка и проверка
> внутренних циклов идут один раз по агрегированным таблицам. Пакет не
> импортируется в конвейер подсчёта (`counter`) и CLI; роль — как у `split`,
> `zdd`, `pairs` (прецедент ADR-040). Тяжёлые точки (7×7, 8×8) исполняются
> бенч-харнессом пакета, не юнит-бюджетом.
>
> В ветке плана 31 к пакету добавлен внутренний слой профиль-DP половин
> (ценз состояний, шаг 0): публичный API и поведение существующих точек
> неизменны; склейка и формат профиля — общий контракт двух движков.

## Ответственность

Для фиксированной пары концов `{s,t}` считает число неориентированных
гамильтоновых путей между ней разрезом доски пополам: верхняя половина
покрывается лесом дизъюнктных путей, нижняя — лесом плюс выбранные пересекающие
рёбра; профиль шва (маска дефектов двух шовных строк верхней половины плюс
парность концов с «нулевым») даёт ключ агрегации; склейка сортировкой и
слиянием находит совпадения масок, для пар парностей проверяется отсутствие
внутренних циклов обходом чередующихся ссылок (`cc = 0` — корректно), итог
группы — сумма произведений счётчиков. Публично отдаёт перечисление групп
D4-орбит пар концов с коэффициентами, счёт одной группы со снимком метрик и
суммарный итог доски.

Пакет обслуживает тяжёлые группы двумя способами урезать пик памяти: многопроходным
бакетированием Чернова (перечисление повторяется, в таблицах остаётся одна корзина) и
внешним слиянием (перечисление однократное, агрегатная таблица сбрасывает отсортированные
прогоны на диск). Оба — режимы вызова, не переключатели сборки.

Пакет НЕ делает: интеграцию с CLI и конвейером reversal; подбор нестандартных разрезов;
отсечения сверх точного кодирования профилей.

## Публичный API

```go
// Group — канонический представитель орбиты неориентированных пар концов:
// S < T — клетки-концы (нумерация пакета graph), K — размер орбиты D4
// (коэффициент 2, 4 или 8).
type Group struct{ S, T, K int }

// Groups перечисляет представителей D4-орбит неориентированных пар различных
// клеток доски n×n, отсортированных по (S,T); всего орбит 49/93/171/278 на
// досках 5–8 (включая пары с нулевым числом туров; таблица Чернова 6×6 —
// только ненулевые классы, 45 строк).
func Groups(n int) []Group

// CountGroup считает неориентированные гамильтоновы пути между клетками s и t
// доски n×n половинными профилями. Невалидный вход (n вне [5,8], клетки вне
// доски, s == t) — ошибка; превышение мягкого байтового потолка —
// OverCapError, не OOM; завершившийся ctx даёт ошибку ctx.Err() без паники.
func CountGroup(ctx context.Context, n, s, t int) (uint64, error)

// Census — снимок метрик прогона группы: ProfilesU/ProfilesL — число различных
// профилей верхней/нижней таблицы; Joins — число пар профилей с совпавшей
// маской, прошедших проверку циклов и давших вклад; MaxProfileCount —
// наибольший счётчик одного профиля в обеих таблицах (свидетельство
// достаточности ширины счётчика: шаг 0 сверяет его с int32).
type Census struct {
    ProfilesU, ProfilesL int
    Joins                uint64
    MaxProfileCount      uint64
}

// CountGroupWithCensus — тот же счёт со снимком метрик.
func CountGroupWithCensus(ctx context.Context, n, s, t int) (uint64, Census, error)

// CountGroupWithPasses считает группу в многопроходном бакетном режиме Чернова:
// passes независимых проходов 0..passes-1, каждый перечисляет обе половины и
// оставляет в таблицах только профили своего бакета (см. инварианты); итог —
// сумма частичных сумм проходов в фиксированном порядке. passes ≥ 1 — контракт
// вызывающего (меньше — ошибка); passes == 1 эквивалентен CountGroupWithCensus.
// Параметр passes — обычный аргумент вызова (харнесс/оператор выбирает его по
// бюджету памяти), не переменная окружения и не флаг. Снимок Census агрегирует
// проходы: профили и джойны суммируются, MaxProfileCount — максимум по проходам.
func CountGroupWithPasses(ctx context.Context, n, s, t, passes int) (uint64, Census, error)

// CountBoard считает итог доски: 2·Σ k·count по всем группам-представителям
// — ориентированный итог (конвенция опубликованных чисел и конвейера).
// Группы независимы, считаются через workerpool.Pool.Run; workers ≥ 1 —
// контракт вызывающего. Итог детерминирован и не зависит от числа воркеров.
// Ошибка любой группы останавливает счёт.
func CountBoard(ctx context.Context, n, workers int) (uint64, error)

// CountBoardWithPasses — тот же итог доски, каждая группа считается
// бакетным режимом с указанным числом проходов (политику выбора passes
// держит вызывающий).
func CountBoardWithPasses(ctx context.Context, n, workers, passes int) (uint64, error)

// ExternalOptions задаёт внешний путь счёта — однократное перечисление половин
// со сбросом агрегатной таблицы отсортированными прогонами на диск и слиянием
// с ограниченным числом входных потоков. SpillBytes — порог сброса в байтах
// (контракт > 0; меньше — ошибка); это верх на живую агрегатную таблицу, память
// сверх него уходит в дисковые прогоны. Dir — рабочий каталог прогонов, пустая
// строка означает os.TempDir. Preserve оставляет прогоны после счёта (отладка);
// по умолчанию каталог удаляется целиком. Внешний путь не совмещается с passes:
// оба урежут пик памяти, но избыточно вместе (см. инварианты).
type ExternalOptions struct {
    SpillBytes int
    Dir        string
    Preserve   bool
}

// ExternalStats — снимок внешнего прогона: метрики профилей и склейки (Census)
// плюс число записанных дисковых прогонов (Spills, по обеим половинам) и пик
// суммарного размера живых прогонов на диске в байтах (DiskPeakBytes).
type ExternalStats struct {
    Census
    Spills        int
    DiskPeakBytes uint64
}

// CountGroupExternal считает группу внешним путём с указанным порогом сброса.
// Итог побитово равен CountGroup при любом SpillBytes (сквозная эквивалентность
// закреплена тестами). Невалидный вход и завершившийся ctx дают ошибку так же,
// как CountGroup; ошибки ввода-вывода с рабочим каталогом возвращаются как есть.
func CountGroupExternal(ctx context.Context, n, s, t int, opts ExternalOptions) (uint64, ExternalStats, error)

// CountBoardExternal — итог доски внешним путём: каждая группа считается своим
// временным подкаталогом рабочего каталога; результат не зависит от workers и
// совпадает с CountBoard.
func CountBoardExternal(ctx context.Context, n, workers int, opts ExternalOptions) (uint64, error)
```

Направление: группа считает множество рёбер один раз (как таблицы Чернова);
сверка с направленными эталонами — `CountGroup == pairs.At(s,t)` без домножения
(ориентация пути фиксируется началом s), итог доски отдаётся уже умноженным
на 2.

## Инварианты

- Геометрия разреза: `h = ⌊n/2⌋`, верхняя половина — строки `[0, h)`, нижняя —
  `[h, n)`; рёбра коня, пересекающие границу (Δrow ∈ {1,2} через неё),
  принадлежат нижней половине (конвенция источника). Верхние клетки шва —
  строки `h−2, h−1`, нижние — `h, h+1`; любое пересекающее ребро касается
  верхней клетки только из строк `h−2, h−1`.
- Конфигурация половины — остовный линейный лес половины (степени ≤ 2, циклов
  нет, одиночные вершины разрешены); дефект клетки `x = tgt − deg`, где
  `tgt = 2` кроме концов `{s,t}` (у них `tgt = 1`). Ненулевой дефект разрешён
  только на шовных клетках; нижняя половина выбирает и сами пересекающие рёбра.
- Каждое множество рёбер половины порождается ровно один раз: канонический
  порядок решений по клеткам (ребро решается у конца с меньшим номером) плюс
  инкрементальная проверка циклов union-find. Порядок обхода клеток внутри
  половины — по возрастанию степени в половине: проектное решение для ранней
  отсечки, извлечение профиля от порядка независимо.
- Пересечений приземляется на верхнюю шовную клетку не более двух: третье
  дало бы ей степень ≥ 3, такое отсекается уже при выборе пересекающих рёбер
  (маска при этом не переполняет 2-битное поле).
- Профиль = (маска K дефектов двух шовных строк, 2 бита на клетку: `00` пусто /
  `01` конец / `11` занято соединением; каноническая упаковка парности концов).
  Узлы парности — вхождения шовных дефектов (клетка, слот) в каноническом
  порядке плюс «нулевые» концы `⊥s`, `⊥t` для путей, упирающихся в конец доски.
  Верхняя таблица хранит пару `(K, P)` с числом покрытий; нижняя — пару
  `(K, Q)`, где `Q` — парность, индуцированная обходом через нижнюю половину по
  выбранным пересекающим рёбрам (слоты клетки с двумя рёбрами нумеруются по
  номеру нижней клетки партнёра — канонично).
- Склейка: таблицы сортируются по профилю; слиянием за `O(n+m)` находятся прогоны
  одинаковой маски K; для каждой пары `(P, Q)` прогон проверяется обходом
  чередующихся ссылок от `⊥s`: корректно, когда посещены все вхождения ровно
  один раз и путь оборвался на `⊥t` (`cc = 0` листинга источника). Вклад пары —
  произведение счётчиков. Итог группы точен: тур доски даёт ровно одну
  совместимую пару конфигураций с корректной склейкой.
- Арифметика: счётчики и итог — точный uint64 без насыщения; переполнение в
  рантайме не проверяется. Свидетельство достаточности ширины счётчика профиля —
  `Census.MaxProfileCount` (шаг 0 сверяет его с int32), а точность итога — жёсткая
  сверка с оракулами. Итог 8×8 (1,96·10¹⁶) влезает с запасом.
- Детерминизм: фиксированные входные данные дают бит-в-бит одинаковый итог
  между прогонами и процессами; `CountBoard` не зависит от числа воркеров
  (группы аддитивны, порядок суммирования канонический). Плавает только
  wall-время.
- Память группы ограничена мягким байтовым потолком (`entryReserve` на профиль);
  превышение возвращает `OverCapError` со счётчиками прогресса вместо OOM
  (механика ADR-038/040): таблица залипает ошибку, перечисление замечает её
  на следующем шаге DFS и разворачивается. Ручек окружения нет (ADR-020),
  тесты двигают рычаг напрямую.
- Бакетный многопроходный режим (аварийный путь тяжёлых групп, компонент 5
  дизайна плана 30; in-memory 7×7 не проходит — ADR-046). Группа считается за
  `passes` независимых проходов; проход `p` перечисляет обе половины и пишет в
  таблицы только профили своего бакета `bucket(K) == p`, где `bucket(K) =
  splitmix64(K) mod passes`. Хеш стабилен (чистая функция маски, одно и то же
  значение в любом проходе, процессе и сборке) и дёшев (один финализатор на
  слово маски).
- Бакет берётся по одной лишь маске K, а не по всему ключу профиля: верхняя и
  нижняя половины склеиваются по совпадению маски, но несут разные парности
  (`P` против `Q`), и хеш полного ключа разошёлся бы у двух половин одной пары —
  склейка рвалась бы между проходами. По маске обе стороны любой корректной
  пары попадают в один бакет, поэтому склейка внутри прохода полная и частичный
  итог точен; каждый тур доски попадает ровно в один проход.
- Итог группы — сумма частичных сумм проходов `0..passes-1` в фиксированном
  порядке; режим детерминирован бит-в-бит и совпадает с однопроходным счётом
  при любом `passes` (сквозная эквивалентность закреплена тестами на 5×5 и
  таблице Чернова 6×6). Потолок памяти применяется к таблицам одного прохода
  (≈ `1/passes` профилей); wall растёт пропорционально `passes`, потому что
  перечисление половин повторяется целиком каждый проход.
- Проход, чьи таблицы превысили потолок, возвращает ошибку с явной подсказкой
  увеличить `passes`; она опознаётся через `errors.Is(err, ErrOverCap)` и
  `errors.As` в `*OverCapError`. Выбор `passes` — политика вызывающего (харнесс
  или оператор по бюджету памяти), пакет её не назначает и не хранит.
- Внешний путь (компонент «внешнее слияние» плана 30; in-memory тяжёлых групп
  нарушает порог резидента — ADR-046). Каждая половина перечисляется ОДИН раз;
  агрегатная таблица накапливает счётчики в памяти, а при пересечении порога
  `SpillBytes` сортирует её по полному ключу профиля и дописывает один отсортированный
  прогон в рабочий каталог, после чего очищается. Живая таблица ограничена порогом
  плюс одна запись; мягкий байтовый потолок `softCap` внешнему пути не применяется —
  память накрывает порог сброса.
- Формат прогона двоичный и версионированный: заголовок (магическое число и версия
  формата), далее записи `(K, P, вес)` компактной переменной длины. Ширина записи
  равна `8 + ⟨длина P⟩ + ⟨вес varint⟩` плюс байт длины ключа; диск на группу —
  `Σ_половин N_профилей × ширина`, пик слияния не превышает этой суммы более чем на
  один выходной прогон текущего уровня. Порог `~100 ГБ` (план 30) проверяется по
  сумме записанных прогонов.
- Слияние сводит прогоны одной половины в один глобально отсортированный поток и по
  ходу объединяет равные ключи в одну запись суммой весов; входной поток ограничен
  сверху, при большем числе прогонов слияние идёт уровнями (частичные прогоны
  перетираются). Порядок прогонов фиксирован, сортировка по полному ключу тотальная,
  поэтому итог детерминирован бит-в-бит.
- Склейка внешнего пути потребляет два отсортированных потока навстречу, группирует
  записи по маске `K` и для каждой группы вызывает ту же проверку чередующихся ссылок
  (`singlePathOK`) и то же произведение счётчиков, что in-memory путь; совпадение
  итога с `CountGroup` побитовое. Память склейки ограничена записями одной маски, а
  не всей таблицей. ctx проверяется на границах групп масок и внутри длинных групп,
  как в `joinTables`.
- Внешний путь не совмещается с бакетным `passes`: оба урежают пик памяти, но вместе
  избыточны (бакетный проход сам перечисляет половины заново). Комбинация не
  заведена; вызывающий выбирает один режим.

## Ограничения и edge cases

- Диапазон контракта — доски 5×5–8×8; вне его API возвращает ошибку. Нечётные
  половины несравненны (у 5×5 верх — 2 строки, низ — 3), это не требует
  специальных веток.
- Концы группы могут лежать в любой половине и на шовных клетках; «нулевые»
  узлы парности заводятся только за фактические концы. Пустая таблица профилей
  половины → итог 0 (не ошибка).
- Завершившийся ctx останавливает перечисление и склейку: `CountGroup`/
  `CountBoard` возвращают `ctx.Err()`, без паники; то же для многопроходного
  счёта — отмена в середине последовательности проходов даёт `ctx.Err()`.
- Внутренний цикл на склейке (двойной тур) не проходит обход чередующихся
  ссылок и не входит в итог — закреплено тестами на искусственных парностях.
- Внешний путь: `SpillBytes ≤ 0` — ошибка контракта вызова; пустая `Dir` ведёт в
  `os.TempDir`. Рабочий подкаталог одной группы удаляется целиком по завершении
  счёта, если не задан `Preserve`; ошибки ввода-вывода возвращаются как есть.
  Отмена ctx в середине внешнего счёта (перечисление или слияние) даёт `ctx.Err()`
  без паники и без оставленных прогонов при unset `Preserve`.

## Тесты

- Оракул 5×5: `CountBoard = 1728`; попарно — точное совпадение `CountGroup`
  с матрицей `pairs.Compute` по всем 600 упорядоченным парам (независимый
  движок).
- Полная таблица Чернова 6×6 (`testdata/chernov6x6.csv`, 45 ненулевых строк
  y1,x1,y2,x2,k,count): каждая строка совпадает с `CountGroup`; сумма
  `k·count = 3 318 960`; направленный итог `6 637 920` — в юнит-бюджете `-race`.
- Эквивалентность бакетного режима: для `passes ∈ {1,2,3,8}` счёт каждой
  ненулевой группы 5×5 и каждой строки таблицы Чернова 6×6 совпадает с
  однопроходным результатом (table-driven); детерминизм многопроходного счёта;
  отмена ctx в середине многопроходного прохода даёт `ctx.Err()`; заниженный
  потолок отличим через `ErrOverCap`/`*OverCapError`.
- Эквивалентность внешнего пути: счёт каждой ненулевой группы 5×5 и каждой строки
  таблицы Чернова 6×6 побитово совпадает с `CountGroup` при трёх порогах сброса —
  заведомо огромный (ни одного сброса), средний и минимальный (много прогонов);
  формат прогона переживает цикл записи-чтения на контрольных ключах; рабочий
  каталог пустеет после счёта без `Preserve`; отмена ctx в середине слияния даёт
  `ctx.Err()`.
- Группы: 49/93/171/278 представителей на досках 5–8 (сверено с леммой
  Бёрнсайда); коэффициенты ∈ {2,4,8}; суммы коэффициентов покрывают все
  неупорядоченные пары.
- Проверка циклов: обход чередующихся ссылок на контрольных примерах —
  корректная склейка проходит, внутренний цикл (двухцикловая склейка) отвергается.
- Детерминизм: два прогона одной группы совпадают бит-в-бит; `CountBoard` при
  workers = 1 и > 1 совпадает.
- Отмена ctx: завершившийся контекст даёт `ctx.Err()` без паники.
- Потолок: заниженный рычаг даёт `OverCapError` со счётчиками; процесс жив.
