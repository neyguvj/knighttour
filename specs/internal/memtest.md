# internal/memtest: зонды памяти процесса для тестов

## Ответственность

Даёт бенчмаркам и цензовым тестам два показания памяти процесса: пик резидентной памяти
(`rusage maxrss`) и накопленный счётчик аллокаций с момента старта. Пакет импортируется только
из тестовых файлов и не входит в состав продакшн-двоичного файла. Оценок он не строит и
ничего не знает о предметной области подсчёта туров.

## Публичный API

```go
// PeakRSSBytes возвращает максимум резидентной памяти процесса в байтах. Внутри одного
// процесса величина не убывает: при нескольких точках в одном тестовом процессе она
// отражает самую прожорливую из них.
func PeakRSSBytes() uint64

// TotalAllocBytes возвращает накопленное число байт, выделенных процессом с момента старта
// (монотонно). Разность двух показаний воспроизводимо измеряет объём сделанных выделений,
// в отличие от пика резидента.
func TotalAllocBytes() uint64
```

## Инварианты

- Единица измерения — байты на всех платформах: linux сообщает `maxrss` в килобайтах, и
  платформенный слой домножает его на 1024.
- Платформенных реализаций две — darwin и linux; других нет.
- Обе функции не имеют побочных эффектов и безопасны из любой горутины.

## Ограничения и edge cases

- Вне darwin и linux пакет не собирается — ровно как прежняя реализация внутри тестов `counter`.
- Сбой `Getrusage` возвращает 0: неудача зонда не считается падением теста.
- Пик резидента включает память рантайма и всех тестов того же процесса, поэтому честные
  точки запускают по одной на процесс (`make bench-size`, `make bench-zdd-census`).

## Тесты

- `TestPeakRSSUnits` — дочерний процесс тестового запуска выделяет 64 МБ и требует от своего
  пика попадания в коридор [64 МБ, 8 ГБ]: ошибка единиц ×1024 выходит из коридора в обе
  стороны, а мёртвый зонд — вниз. Внутри общего тестового процесса `maxrss` — исторический
  максимум других тестов, поэтому проверка требует отдельного процесса.
