# ADR-008. Pre-DP shape-фильтр реализуемости включён по умолчанию (`L2ForcedChain`)

## Статус

Принято (план 02). Порога по |shape| нет: в class mode `|U| = s²−d ≥ s²/2 ≥ 12`.

## Контекст

В финальном проходе ~87% форм дают `h == 0` по всем концам (ADR-001). Часть нулей
доказуема дешёвыми необходимыми условиями **до** входа в DP и до выделения memo-буфера.
План 02 исследовал три проверки: A endpoint-mismatch, B forced-cycle, C articulation.

## Решение

`Pruner.ShapeFeasible(end, shape, mask)` вызывается из `shapecount.CountShapeWithTail`
до выделения memo-буфера; отсечённый конец получает `h = 0` без DP. Если отсечены все
концы — форма возвращает нулевой срез, memo не заводится. Маска конфигурируется
`SetShapeFilter`; по умолчанию `DefaultShapeFilter = L2ForcedChain` (только B).

- **A endpoint-mismatch** — выключен: 0 срабатываний сверх корневого L1 (покрыт им).
- **B forced-cycle (`L2ForcedChain`)** — включён: убивает 53–67% нулевых форм дёшево.
- **C articulation** — выключен: даёт ~1 п.п. сверх B за полный Tarjan на каждый конец.

Учёт — отдельный счётчик `types.Result.FilteredShapes`, не смешивается с `pruned*`
(исторические метрики прунинга сопоставимы). Фильтр даёт только доказуемые нули —
итог `Σ h·M` инвариантен.

## Последствия

- Дешёвое отсечение нулей до аллокации memo; статистика не смешана с DP-прунерами.
- В живой строке/финале — отдельный сегмент `filtered N`.

## Замеры

По формам (`filtered/op`): d22 — 7.3M/68.4M, d20 — 4.2M/44.6M; 6×6 d13 — 3.1k/36k.
По времени counting заметно меньше: убитые цепочкой формы и так умирали в DP на первых
состояниях (M4 Max, 14 ядер):

| стенд | cnt on | cnt off | total on | total off |
|---|---|---|---|---|
| 7×7 d22 | 361.7 с | 372.4 с (−2.9%) | 583.8 с | 593.1 с (−1.6%) |
| 7×7 d20 | 528.1 с | 539.9 с (−2.2%) | 612.1 с | 623.4 с (−1.8%) |

6×6 по свипу: +3..9% на глубинах d11–d16/d18, проседания ≤6% на части глубин — в пределах
шума. Цель плана «counting ≤ 250 с» фильтром не достигнута (время нулей живёт в deep-классах,
приоритет — план 03).
