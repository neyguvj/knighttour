# ADR-008. Фильтр реализуемости формы перед DP включён по умолчанию (`L2ForcedChain`)

## Статус

Принято (план 02). Порога по |shape| нет: в классовом режиме — подсчёте через
классы форм (ADR-001) — выполняется `|U| = s²−d ≥ s²/2 ≥ 12`.

## Контекст

В финальном проходе ~87% форм дают `h == 0` по всем концам (ADR-001). Часть
этих нулей доказывается дешёвыми необходимыми условиями ещё до входа в DP — до
выделения буфера мемоизации. План 02 исследовал три такие проверки: A —
несовпадение концов (`endpoint-mismatch`), B — обязательный цикл (`forced-cycle`),
C — сочленения (`articulation`).

## Решение

Метод `Pruner.ShapeFeasible(end, shape, mask)` вызывается из
`shapecount.CountShapeWithTail` до выделения буфера мемоизации. Конец, отсечённый
фильтром, получает `h = 0` без запуска DP. Если отсечены все концы, форма
возвращает нулевой срез, и буфер мемоизации не заводится вовсе. Маску проверок
задаёт `SetShapeFilter`; по умолчанию стоит `DefaultShapeFilter = L2ForcedChain` —
только проверка B.

- **A — несовпадение концов** — выключена: 0 срабатываний сверх корневого
  отсечения L1, которое её полностью покрывает.
- **B — обязательный цикл (`L2ForcedChain`)** — включена: дешёвая проверка
  отсекает 53–67% нулевых форм.
- **C — сочленения** — выключена: даёт ~1 п.п. сверх результата B ценой полного
  прохода Тарьяна для каждого конца.

Результаты фильтр пишет в отдельный счётчик `types.Result.FilteredShapes` и не
смешивает их с полями `pruned*`: исторические метрики отсечения должны оставаться
сопоставимыми. Фильтр даёт только доказуемые нули, поэтому итоговая сумма `Σ h·M`
не меняется.

## Последствия

- Нули отсекаются дёшево до выделения буфера мемоизации, и их статистика не
  смешана со счётчиками отсечений внутри DP.
- В строке прогресса и в итоговом отчёте у фильтра есть отдельный сегмент
  `filtered N`.

## Замеры

По числу форм (`filtered/op`): d22 — 7.3M/68.4M, d20 — 4.2M/44.6M; на 6×6 d13 —
3.1k/36k. Выигрыш по времени count-фазы заметно скромнее этой доли: формы, убитые
цепочкой, и так погибали в DP на первых состояниях (M4 Max, 14 ядер):

| стенд | cnt on | cnt off | total on | total off |
|---|---|---|---|---|
| 7×7 d22 | 361.7 с | 372.4 с (−2.9%) | 583.8 с | 593.1 с (−1.6%) |
| 7×7 d20 | 528.1 с | 539.9 с (−2.2%) | 612.1 с | 623.4 с (−1.8%) |

На 6×6 по проходу всех глубин: ускорение +3..9% на глубинах d11–d16/d18,
проседания ≤6% на части глубин — в пределах шума. Цель плана «counting ≤ 250 с»
фильтром не достигнута: время нулей сосредоточено в глубоких классах, и приоритет
смещён к плану 03.
