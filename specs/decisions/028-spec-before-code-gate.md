# ADR-028. Гейт G12 «спеки до кода»: git-состояние спек как условие, обход — хуком `command.execute.before`

## Статус
Принято; реализация — элемент списка гейтов в `.opencode/plugins/gates.ts`. Процессное решение,
замеры n/a (стоимость git-вызовов — ниже). При кодировании скорректирован механизм обхода:
с события шины `command.executed` на хук `command.execute.before` — probe-прогон в opencode 1.18.31
показал, что событие публикуется только после завершения всего хода команды
(`before` → tool-вызовы модели → `executed` вместе с `session.idle`), т.е. первая правка внутри
самого `/quick` ложно блокировалась бы — нарушение приоритета «ноль ложных блоков на легальных
путях». Хук срабатывает до хода модели; ядро регистрирует один дополнительный обработчик
`command.execute.before` (интерфейс `Gate` получает наблюдателя `onCommand`).

## Контекст
Порядок «спека пакета обновлена до любого изменения его Go-кода» обязателен текстом (AGENTS.md
«Mandatory workflow», ШАГ 1 `/task`, Фаза 1 `/feature`), но нарушается «по инерции»: кодер стартует
с кода, ревьюер ловит постфактум (`SPEC_OK: no`), цикл review→исправление там, где нужен механизм.
Permission-слой выразить «если спека не изменена» не может — у паттернов нет отрицания и нет знания
о git-состоянии (прецеденты ADR-025/027) → plugin-слой (ADR-022). Одновременно `/quick` легально НЕ
меняет спеки — нужен точечный обход, иначе гейт выродится в шум, который агент начнёт обходить.
Гейт заявлен самым шумным в серии: приоритет контракта — ноль ложных блоков на легальных путях
(`/quick`, чисто-спековые правки, тесты к уже описанному поведению).

## Решение
Контракт целиком — `specs/gates.md` «Гейт G12»; здесь обоснование выборов:

- **Условие — git-состояние на момент вызова** (спека грязная в рабочем дереве/индексе ИЛИ изменена
  от merge-base ветки), а не сессионное наблюдение и не mtime. Отклонено:
  - *mtime спеки vs первая правка кода* — checkout нового worktree выставляет mtime всех файлов
    временем создания (спека «обновлена» до любой правки — ложный проход на пустом месте), а
    `cp`/`rsync`/stash ломят сравнение в обе стороны; плюс зависимость от времени сессии, которого
    у stateless-проверки нет;
  - *штамп «спеку трогали» как у G7* — живёт в памяти процесса, умирает при рестарте сервера и не
    различает деревья worktree; git-состояние читается с диска и переживает рестарты;
  - *только merge-base-diff без грязной проверки* — дал бы ложный блок на горячем пути «спеку
    только что отредактировали, коммита нет». Грязная проверка — один вызов `git status`, history —
    резерв для контрольного коммита середины ветки.
- **База — `merge-base HEAD origin/main`** (канон A/B-базы из skill `workflow`), fallback `main`;
  ни одна не резолвится → проверка пропускается. **Сбой git = проход** (fail-open): для шумного гейта
  ложный блок дороже пропуска, это согласуется с правилом ядра «баг гейта не ломает инструмент».
- **Кэш позитивов, негативы не кэшируются.** Замер при написании спеки: `git status --porcelain` ≈
  8.0 мс, `git merge-base` ≈ 7.3 мс (darwin, этот репозиторий) — на частоте edit-инструмента цена
  вторична; кэш по паре (корень дерева, путь спеки) снимает спавн процессов на повторных правках.
  Инвалидация — событие шины `vcs.branch.updated` (целиком, best-effort): избыточный сброс дёшев,
  а протухший позитив после смены ветки вне сессии — принятый класс G7/G8 («снять забыл, не
  перехватить злоумышленника»). Некэширование негатива гарантирует: появившаяся спека пропускается
  следующим же вызовом без всякой инвалидации.
- **Обход — хук `command.execute.before`** (`{command, sessionID, arguments}`; срабатывает до хода
  модели): `command == "quick"` помечает сессию, `task`/`feature` снимают метку; время жизни —
  память процесса. Отклонены:
  - *событие шины `command.executed`* (первоначальный выбор этой спеки) — в opencode 1.18.31 оно
    публикуется в конце `SessionPrompt.command`, после полного прогона хода (`prompt → loop` до
    завершения): probe-замер зафиксировал порядок `command.execute.before` → tool-вызовы правки →
    `command.executed`+`session.idle`. Первая правка `/quick` блокировалась бы, а снятие метки
    `/task`/`/feature` опаздывало бы на весь их ход — ложные блоки и ложные проходы на легальных
    путях; хук даёт ровно тот же факт запуска команды, но до первого tool-вызова;
  - *ветка `chore/*` как сигнал* — git-процесс на каждый edit (или свой кэш с той же проблемой
    инвалидации), «сидит на chore вручную» само выдаёт обход, сигнал дрейфует при смене ветки вне
    сессии; хук же срабатывает ровно на факт запуска команды;
  - *глобальный на процесс флаг `/quick`* — утёк бы в последующие `/feature` долгоживущего процесса
    оркестратора (ADR-024: один процесс, много фич). Пометка по `sessionID` точна: `/quick` не
    порождает субагентов и правит в своей сессии, а сессии `coder`/`spec` имеют другие `sessionID` и
    обхода не получают.
- **`_test.go` вне субъекта.** Добавление/правка тестов к уже описанному поведению легальны без
  изменения спеки — включать тесты значило бы кормить ложными блоками приоритетный легальный путь;
  «тесты нового поведения» в `/task`/`/feature` идут вместе со свежей спекой и проходят и так.
  Контратрами гейт бьёт по исходникам. Аналогично вне субъекта `work/**` (scratch, обратная сторона
  G11) и `testdata/`.
- **Спеки нет — блок, а не свобода.** Новый пакет без `specs/<pkg>.md` — ровно то нарушение, ради
  которого гейт заведён (AGENTS.md workflow шаг 2: «create it if it does not exist»); инструкция
  указывает сначала создать спеку. Корневой пакет маппится на существующую `specs/main.md`.
- **Режима warn нет.** Предупреждение — текст; гейты существуют потому, что текст не снимает
  «забыл» (ADR-022). Переключатель — ветка (ADR-021): зашумит — ветка закрывается как rejected.
  Шум гасится точностью субъекта, обходом `/quick` и инструкцией с двумя легальными выходами.

## Последствия
- (+) «код без спеки» становится физически невозможен видимыми путями edit/write/patch в
  `/task`/`/feature`; `/quick`, чисто-спековые правки, тесты и работа `spec`/`benchmarker` (только
  `.md`) не затронуты вовсе;
- (+) переживает рестарты сервера и контрольные коммиты: состояние читается из git, а не из памяти;
- (-) чистый рефакторинг внутри `/task` требует хотя бы пояснительной строки в спеке — намеренное
  трение, инструкция подсказывает формулировку;
- (-) bash-правки Go невидимы (принятый класс G7/G8); смена ветки вне поля зрения плагина может
  оставить протухший позитив кэша (лишний проход, не ложный блок);
- (-) плагин порождает git-подпроцессы на правку кода (до трёх вызовов, ≤ ~24 мс без кэша).

## Замеры
n/a (процессное решение). Стоимость механизма: `git status --porcelain -- specs/<pkg>.md` ≈ 8.0 мс,
`git merge-base HEAD origin/main` ≈ 7.3 мс — среднее по 5 вызовам, darwin, рабочее дерево feature-
ветки; полная проверка без кэша ≤ ~24 мс на edit. Тайминг обхода (probe-плагин, scratch-репозиторий,
opencode run 1.18.31): `command.execute.before` — t0; tool-вызовы хода — t0+…; `command.executed` —
вместе с `session.idle` после последнего tool хода (разрыв ~единицы минут на длинном ходе) —
событие для обхода непригодно.
