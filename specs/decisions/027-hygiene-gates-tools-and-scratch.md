# ADR-027. Гейты гигиены G10/G11: карточка тула и транзитные артефакты — stateless-хуками

## Статус
Принято; реализация — ветка `06-tools-hygiene` (два элемента списка гейтов в
`.opencode/plugins/gates.ts`). Процессное решение, замеры n/a.

## Контекст
Два правила репозитория обязательны текстом, но систематически нарушаются «по забывчивости»:
туль в `tools/` заводится с карточкой и строкой индекса (AGENTS.md «Shared tools», skill `tools`,
`specs/tools/README.md`: «инструмент без карточки в индексе не считается существующим»), а все
транзитные артефакты — логи, статусы, бинарники — живут в `work/<task>/` (AGENTS.md «Working
scratch space», `work/README.md`). Ревьюер режет обе вещи (MAJOR/MINOR), но постфактум: цикл
review→исправление там, где нужен механизм. Permission-слой выразить правила не может: у паттернов
нет отрицания (прецедент ADR-025 — «блокировать, если карточка отсутствует» незаписуемо), а
наличие парного файла и подавно не факт пути. Значит plugin-слой (ADR-022), по образцу stateless G9.

## Решение
Контракты целиком — `specs/gates.md` «Гейт G10» и «Гейт G11»; здесь обоснование выборов:

- **Два гейта, а не один «гигиенический».** Разные субъекты (G10 — только создание `.py` под
  `tools/`; G11 — произвольная цель по расширению) и разные инструкции; инвариант ядра «новый
  гейт = новый элемент списка» соблюдается дважды.
- **Statelessness обоих.** Требование «код + карточка в одном изменении» ненаблюдаемо stateless-хуком:
  эмуляция транзакции (запомнить записанный `.py`, требовать карточку в течение N вызовов) добавила бы
  состояние, гонок и ложных блоков на повторах — отклонено. Вместо порядка записей — состояние на
  момент записи `.py`: нет карточки/упоминания → `GateError` с инструкцией создать их сначала.
  Промежуток «карточка уже, код ещё нет» безвреден и допустим.
- **Индекс проверяется, но как состояние, а не формат.** Упоминание основы имени тула подстрокой в
  `specs/tools/README.md`: строку таблицы нельзя завести, не назвав тул, при этом шаблонный ряд skill
  `tools` (колонки «Тул | Путь | …») не обязан линковать файл карточки — проверка по `<имя>.md`
  ломала бы соответствующих шаблону. Отклонена альтернатива «только карточка, индекс на ревьюере»:
  полу-состояние «тул + карточка без строки» проходило бы гейтом, тогда как `specs/tools/README.md`
  определяет существование тула именно связкой код+карточка+индекс.
- **Card-name: обе орфографии.** Python-файлы snake_case, карточки kebab-case (`bench_table.py` ↔
  `bench-table.md`); гейт принимает любое написание имени карточки — требование строго kebab дало бы
  ложный блок соответствующему агенту, а орфографический дрейф и так правится ревьюером.
- **Новый vs правка — по существованию файла** (existsSync в `before`): stateless-определение;
  переименование тула = создание нового пути и требует переименованной карточки тем же усилием.
  Отклонено: анализ `git status`/diff для различения «новый/переименованный» — тянет git в гейт.
  Обратный порядок (удалён тул, осталась карточка) сознательно вне гейта — чистка документов,
  территория ревьюера.
- **Структурная привязка к дереву записи** (`<X>/tools/… ↔ <X>/specs/tools/…`), а не к корню сессии:
  WORKTREE-контракт (ADR-024) пишет субагентам абсолютными путями активного worktree; карточка ищется
  там же, где создаётся код. Хук получает аргументы до permission-преобразований, формы subject'а
  ADR-026 недоступны — поэтому цель резолвится самим гейтом (механика G8).
- **G11: класс по расширению, без content-sniffing.** edit/write несут текст; «бинарность по
  содержанию» под ними бессмысленна, сборочные артефакты приходят через bash — перенаправления и
  сборки остаются принятым непрозрачным классом G7/G8. Список: `.log` (его нет в `.gitignore` — он
  грязит `git status`) плюс артефактные `.exe`, `.dll`, `.so`, `.dylib`, `.test`, `.out`, `.pyc`.
  Отклонено чтение `.gitignore` динамически: правило «транзит живёт в work/», игнорирование git его не
  отменяет, а парсер добавляет ложные пропуски на правках конфига. Не покрыто: headless-файл без
  расширения (`./prog`) — неприменимо к write/edit-инструментам; прочие текстовые расширения
  (`.status`, `.csv`) — расширять списком решением, не матчером.
- **G11 — правка без исключения** (в отличие от G10): существование мусорного файла вне `work/` не
  легитимирует его редактирование; у G10 exemption правок, наоборот, обязателен — иначе гейт встал бы
  на пути к существующим тулам.
- Feature-flag отсутствует (ADR-021): переключатель — ветка.

## Последствия
- (+) туль без карточки/индекса и лог в корне становятся физически невозможны видимыми путями
  edit/write/patch; вместо молча заведённого мусора — `GateError` с инструкцией.
- (-) bash (`make bench > root.log`, `go build -o prog`) невидим — принятый класс G7/G8; цель гейтов —
  снять «забыл», не перехватить злоумышленника.
- (-) текстовое упоминание имени тула в README вне строки таблицы выводит G10 из блока; обратный
  порядок G10 (карточка без тула) не проверяется — оба края остаются на ревьюере.
- (-) список расширений G11 статичен: новые классы транзита (.status и т.п.) требуют решения, не
  патча матчера.
- (-/+) проверка индекса/карточки читает файлы с диска на каждую новую запись `.py` под `tools/` —
  частота операции (единицы за фичу) делает стоимость нерелевантной.
