# ADR-027. Гейты гигиены G10/G11: карточка тула и транзитные артефакты — хуками без состояния

## Статус
Принято; реализация — ветка `06-tools-hygiene` (два элемента списка гейтов в
`.opencode/plugins/gates.ts`). Процессное решение, замеры n/a.

## Контекст
Два правила репозитория обязательны текстом, но систематически нарушаются по забывчивости. Тул в
`tools/` должен заводиться вместе с карточкой и строкой индекса (AGENTS.md «Shared tools», skill
`tools`; `specs/tools/README.md`: «инструмент без карточки в индексе не считается существующим»). Все
транзитные артефакты — логи, статусы, двоичные файлы — должны жить в `work/<task>/` (AGENTS.md
«Working scratch space», `work/README.md`). Ревьюер и так режет обе вещи (MAJOR/MINOR), но постфактум;
там, где возможен механизм, полагаться на цикл «ревью → исправление» не нужно. Permission-слой выразить
эти правила не может: у паттернов нет отрицания (прецедент ADR-025 — правило «блокировать, если
карточка отсутствует» незаписуемо), а наличие парного файла вообще не является фактом пути. Поэтому
решение отнесено в plugin-слой (ADR-022), по образцу не хранящего состояния G9.

## Решение
Контракты целиком живут в `specs/gates.md`, секции «Гейт G10» и «Гейт G11»; здесь — обоснование выборов:

- **Два гейта, а не один «гигиенический».** Субъекты разные: G10 смотрит только на создание `.py` под
  `tools/`, а G11 — на произвольную цель по расширению. И инструкции агентам разные. Инвариант ядра
  «новый гейт = новый элемент списка» соблюдён дважды.
- **Оба гейта не хранят состояния.** Требование «код и карточка в одном изменении» ненаблюдаемо
  stateless-хуком. Эмуляция транзакции — запомнить записанный `.py` и требовать карточку в течение
  N вызовов — добавила бы состояние, гонки и ложные блокировки на повторах; она отклонена. Вместо
  порядка записей проверяется состояние на момент создания `.py`: нет карточки или упоминания —
  `GateError` с инструкцией создать их сначала. Промежуток «карточка уже есть, кода ещё нет» безвреден
  и допустим.
- **Индекс проверяется, но как содержимое, а не как формат.** Ищется подстрока — основа имени тула —
  в тексте `specs/tools/README.md`. Строку таблицы нельзя завести, не назвав тул, при этом шаблонный
  ряд skill `tools` (колонки «Тул | Путь | …») не обязан линковать файл карточки. Проверка по ссылке
  вида `<имя>.md` ложно блокировала бы агентов, следующих шаблону. Альтернатива «только карточка,
  индекс оставить ревьюеру» отклонена: промежуточное состояние «тул и карточка есть, строки в индексе
  нет» проходило бы гейт, тогда как `specs/tools/README.md` определяет существование тула именно
  связкой код + карточка + индекс.
- **Имя карточки принимается в обеих орфографиях.** Python-файлы пишутся в snake_case, карточки — в
  kebab-case (`bench_table.py` ↔ `bench-table.md`). Гейт принимает любое написание имени карточки:
  требование строгого kebab-case ложно блокировало бы агенту, следующую конвенции, а орфографический
  дрейф и так правится ревьюером.
- **Новый файл или правка — по существованию файла**: `existsSync` в аргументе `before`, это
  stateless-определение. Переименование тула означает создание нового пути, поэтому гейт требует
  переименованной карточки с тем же усилием. Различать «новый/переименованный» через `git status` или
  diff отклонено: это тянет git внутрь гейта. Обратная ситуация — тул удалён, карточка осталась —
  сознательно вне гейта; это чистка документов, территория ревьюера.
- **Поиск карточки структурно привязан к дереву записи** (`<X>/tools/… ↔ <X>/specs/tools/…`), а не к
  корню сессии. WORKTREE-контракт (ADR-024) обязывает субагентов писать абсолютными путями активного
  worktree, поэтому карточка ищется там же, где создаётся код. Хук получает аргументы инструмента до
  преобразований permission-слоя, формы subject из ADR-026 ему недоступны. Поэтому цель разрешается в
  абсолютный путь самим гейтом — механикой G8.
- **G11 определяет класс файла по расширению и не анализирует содержимое.** Инструменты edit/write
  несут текст, поэтому «бинарность по содержанию» под ними бессмысленна. Сборочные артефакты приходят
  через bash — перенаправления и сборки остаются принятым непрозрачным классом G7/G8. Список
  расширений: `.log` (его нет в `.gitignore`, и он грязит `git status`) плюс артефактные `.exe`,
  `.dll`, `.so`, `.dylib`, `.test`, `.out`, `.pyc`. Динамически читать `.gitignore` отклонено: правило
  «транзит живёт в work/» игнорирование git не отменяет, а парсер добавляет ложные пропуски при правках
  конфига. Не покрыто: исполняемый файл без расширения (`./prog`) — он недоступен инструментам
  write/edit; прочие текстовые форматы (`.status`, `.csv`) добавляются решением, а не правкой правила
  сопоставления.
- **G11 блокирует и правку, без исключения** — в отличие от G10. Существование мусорного файла вне
  `work/` не легитимирует его редактирование. Для G10 исключение для правок наоборот обязательно:
  иначе гейт встал бы на пути к уже существующим тулам.
- Feature-flag отсутствует (ADR-021): переключателем служит сама ветка.

## Последствия
- (+) Тул без карточки или строки индекса и лог в корне больше нельзя создать видимыми путями
  edit/write/patch. Вместо молча заведённого мусора агент получает `GateError` с инструкцией.
- (-) Вызовы через bash (`make bench > root.log`, `go build -o prog`) остаются невидимы — это принятый
  класс ограничений G7/G8. Цель гейтов — страховать от забывчивости, а не перехватывать
  злоумышленника.
- (-) Текстовое упоминание имени тула в README вне строки таблицы тоже выводит G10 из блокировки.
  Обратный порядок G10 — карточка есть, тула ещё нет — не проверяется. Оба краевых случая остаются на
  ревьюере.
- (-) Список расширений G11 статичен: новый класс транзитных файлов (`.status` и подобные) требует
  решения, а не правки правила сопоставления.
- (-/+) Проверка индекса и карточки читает файлы с диска при каждом новом создании `.py` под `tools/`.
  Операция встречается единицы раз за фичу, поэтому её стоимость нерелевантна.

## Замеры
n/a (процессное решение, не hot-path).
