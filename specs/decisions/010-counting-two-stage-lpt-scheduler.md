# ADR-010. Counting-фаза: два stage'а per-shard, LPT-стек батчей; группировка на чтении

## Статус

Принято (профиль 2026-09).

## Контекст

Финальная фаза разбирает аккумулятор M (десятки миллионов записей) и считает
`total += Σ h(C)·M(C)` по формам. Два вопроса: (1) где группировать концы в форму —
на записи или на чтении; (2) как планировать задачи-формы по воркерам, чтобы дорогой
шард не вызывал простоя и не держал лишней памяти.

## Решение

**(1) Группировка на чтении, а не на записи.** В аккумуляторе хранится плоская
`path.Path → weight`; форма собирается сортировкой разобранного шарда по `State`.
Соблазн хранить вложенное значение «State → концы» отклонён (см. замеры).

**(2) Два stage'а per-shard, без общего снимка M** (опирается на ADR-004):
- **Stage 1 — grouping.** `min(workers, NumShards())` горутин тянут индексы шардов
  атомарным курсором: `DrainShard(i)` → срез сортируется по `State` → режется на
  диапазоны форм → job `{entries, tasks}`. Все job'ы известны заранее и складываются
  в стек **по убыванию суммарного числа концов** (LPT — дорогие первыми).
- **Stage 2 — dispatch.** Воркеры берут батчи (`claimBatch = 16`) с вершины стека под
  мьютексом; внутри job'а — атомарный курсор; пустой стек = всё разобрано. Сна нет:
  новые задачи не появляются, прежние `sync.Cond` и счётчик дренирующих убраны.

## Последствия

- Памяти живёт ≈ по одному срезу на активного воркера; дорогой шард не оставляет
  остальных праздными.
- Внутри job задачи отсортированы по убыванию числа концов (прокси стоимости DP).
- Убрана сложность планировщика (Cond/счётчики) без потери утилизации.

## Замеры

6×6 d18 (профиль 2026-09): вся counting-фаза — ~8% CPU пайплайна, из них сортировка
группировки ~0.3% против ~20% у пути записи (`Accumulator.Add`/`LocalSink.Flush`).
Вложенное значение добавило бы аллокации на каждую форму (7×7 d20 — 44.6M форм ≈ 150M
мелких аллокаций + лишний указатель на форму в каждом GC-цикле) и merge-семантику под
локом шарда; `LocalSink` всё равно остался бы `map[Path]uint64`. Обход класса по плоскому
срезу локален, чего pointer-chasing по 44M бакетов не даёт.
