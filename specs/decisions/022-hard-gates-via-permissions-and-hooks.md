# ADR-022. Жёсткие гейты вместо текстовых инструкций (permission + plugin hooks)

## Статус
Принято; реализуется серией фич (первая — permission-слой, `chore/agent-permissions`).

## Контекст
Агенты систематически отступают от обязательных правил AGENTS.md (работали на `main`, коммитили
без зелёного `make check`, гоняли тяжёлые бенчи без flock). Текст инструкции — не механизм:
модель может его забыть или проигнорировать. Нужны проверки уровня инструмента, которые нельзя
обойти ответом модели.

## Решение
Двухслойная схема (реестр живых гейтов — `specs/gates.md`):

1. **permission-конфиг** — декларативный, нулевой код: глобальный `opencode.json` в репозитории
   (`git push*` → ask; `external_directory` — allow только рабочего дерева и соседних worktree
   `~/work/kt-*`) и frontmatter субагентов (минимальные права на edit по роли, `task: deny` —
   субагент не спавнит субагентов). `deny` держит даже в `--auto`.
2. **plugin-хуки** (`.opencode/plugins/*.ts`, `tool.execute.before`) — для stateful-правил,
   недоступных паттернам: работа не на `main`, обязательный зелёный `make check` перед
   `git commit`, flock для тяжёлых бенчей, запрет feature-flag/env-ручек (ADR-021), дисциплина
   `tools/`. Каждый такой гейт — отдельная фича и отдельная запись в реестре.

## Последствия
- Правила из «мягких рекомендаций» переезжают в конфигурируемые блокировки; текст в AGENTS.md
  остаётся объяснением, а не исполнителем.
- `ask` проходимо пользователем осознанно; там, где нужна абсолютность, ставится `deny`.
- Permission-слой не знает ветку/историю прогонов — это тянет второй слой (плагин), он же и
  самый шумный: каждое правило требует настройки false-positive.
- Смена конфига требует рестарта opencode-сессии; плагин исполняется на каждом вызове
  инструмента (стоимость — локальные проверки, не бенчмарк).

## Замеры
n/a (процессное решение, не hot-path).
