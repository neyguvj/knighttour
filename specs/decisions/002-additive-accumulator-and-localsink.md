# ADR-002. Единое хранилище: аддитивный Accumulator вместо кэша мемоизации; писатели через LocalSink

## Статус

Принято.

## Контекст

Исторически существовали два хранилища. Первое — кэш подзадач `cache.Cache`
(Get/Set/Each под `RWMutex`): он пережил отказ от обращения тура и остался без
потребителей. Второе — аддитивный аккумулятор классов форм, структура, которая
только суммирует веса по ключу. После перехода в классовый режим (ADR-001)
чтение нужно строго **после** завершения фазы записи, поэтому мемоизация с
чтением при промахе не нужна никому.

Прямой вызов `Add` из каждого листа брал блокировку шарда, а rehash карты
происходил под этой блокировкой. Профиль 6×6 d18 показал ~26% CPU в конкуренции
за блокировки. Нагрузка аддитивна и сосредоточена на горячих общих ключах:
`writesB` ~3.6G на 7×7 d22.

## Решение

Оставили одну структуру — `cache.Accumulator`: шардированная карта
`map[path.Path]uint64` из 128 шардов с семантикой `Add(k, w)` — «data[k] += w».
Чтение возможно только полным обходом после барьера фазы. Прежний `Cache`
(Get/Set/Each + `RWMutex`) удалён: достаточно обычного `Mutex`, и исчезла
зависимость пакета от `Symmetry` — канонизацию выполняет писатель.

Писатели обеих генерационных фаз работают через `acc.Local()`, который
возвращает `LocalSink` — персональный буфер одной горутины типа
`map[path.Path]uint64`. Буфер объединяет повторяющиеся ключи в одну запись.
При переполнении (порог `localFlushLimit = 1024`) метод `Flush` догружает каждый
уникальный ключ за один захват блокировки. Вызов `defer sink.Flush()`
гарантирует доставку. Семантика аддитивна, поэтому момент сброса буфера на
результат не влияет. Один `LocalSink` между горутинами не разделяют.

## Последствия

- Блокировок и аллокаций rehash стало меньше: дубликаты объединяются ещё до
  захвата блокировки.
- Чтение возможно только между фазами (барьер errgroup) — это совместимо с
  конвейером.
- Нули не хранятся по построению: запись создаётся только при вызове `Add`.

## Замеры

- Профиль 6×6 d18: конкуренция за блокировки и rehash под блокировкой при
  прямом Add — ~26% CPU.
- На стенде (6×6) `LocalSink` объединяет дубликаты ключей со множителем ~×6.
- Объём записей: `writesB` ~3.6G на 7×7 d22 — метрика монитора, а не уникальные
  ключи.
