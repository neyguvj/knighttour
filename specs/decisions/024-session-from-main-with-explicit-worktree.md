# ADR-024. Сессия оркестратора живёт в main: работа закреплена за worktree явным cwd, перезапуск не нужен

## Статус
Принято (пересматривает пункт «Сессия» в ADR-021)

## Контекст
ADR-021 требовал на каждое изменение пересаживать сессию opencode внутрь worktree
(`cd ../kt-… && opencode`), чтобы субагенты наследовали верный cwd. На практике это означало
ручной перезапуск opencode при каждом новом изменении и потерю контекста оркестратора;
переключение между параллельными изменениями стоило смены терминала и перезапуска.

При этом доступ к worktree из сессии в `main` уже был открыт (permission `~/work/kt-*/**`,
гейт G2), и агент мог работать с ним по абсолютным путям. Проблема была только в неявном cwd:
инструменты и субагенты по умолчанию смотрели в основное дерево.

## Решение
Сессия оркестратора живёт в основном checkout и между изменениями не перезапускается. Изоляцию
даёт не cwd процесса, а **контракт WORKTREE**:

- после `git worktree add ../kt-<NN>-<slug> …` оркестратор фиксирует
  `WT=$(cd ../kt-<NN>-<slug> && pwd)` и выполняет все последующие операции только там: команды
  bash — с cwd=`$WT` (параметр `workdir`) или через `git -C "$WT"`, файлы — абсолютными путями
  под `$WT`;
- промпт каждого субагента начинается со строки `WORKTREE: <абс. путь>` и директивы «все команды
  выполняй в WORKTREE, к основному дереву не прикасайся»; параллельные изменения различаются тем,
  что WT назван в каждом промпте;
- основное дерево до закрытия доступно только для чтения. Механическая страховка на случай, когда
  агент забыл передать `workdir`, — гейт **G8** (плагин `gates.ts`): пока процесс видел
  `git worktree add ../kt-*` и этот worktree существует, инструменты `edit`/`write`/`patch` с
  целью внутри основного дерева блокируются через `GateError`. Закрытие
  (`git -C "$MAIN" merge --squash`) выполняется bash-командой, а не правкой, поэтому гейт его не
  касается.

Операционно механика живёт в skill `workflow` (раздел «Открытие»), командах `/feature` и `/task`,
AGENTS.md («Feature workflow») и директивах субагентов.

## Последствия
- Новое изменение начинается с одной команды `git worktree add`, без перезапуска opencode.
  Контекст оркестратора переживает смену изменений, и параллельные изменения ведутся из одной
  сессии.
- Риск «команда ушла не в тот каталог» закрывается дважды: соглашением (явный cwd обязателен)
  и гейтом G8 (правка `main` при активном worktree физически невозможна).
- G8 хранит состояние в памяти процесса, как штамп G7: множество активных worktree строится из
  наблюдаемых `git worktree add`/`remove`. Worktree, удалённые вне сессии, выпадают из множества
  сами — при следующей правке проверяется существование каталога. Обход через правки основного
  дерева командами bash остаётся возможным, как в G7, и это принято.
- `/quick` на ветке `chore/<slug>` без отдельного worktree гейт не затрагивает: когда множество
  активных worktree пусто, гейт ничего не блокирует.
