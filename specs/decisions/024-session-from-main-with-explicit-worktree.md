# ADR-024. Сессия оркестратора живёт в main: работа пинится к worktree явным cwd, перезапуск не нужен

## Статус
Принято (пересматривает пункт «Сессия» в ADR-021)

## Контекст
ADR-021 требовал на каждую фичу пересаживать сессию opencode внутрь worktree
(`cd ../kt-… && opencode`), чтобы субагенты наследовали верный cwd. На практике это
означало ручной перезапуск opencode при каждой новой фиче и потерю контекста оркестратора;
переключение между параллельными фичами стоило терминал-свитча плюс рестарта.

При этом доступ к worktree из сессии в `main` уже был открыт (permission `~/work/kt-*/**`,
гейт G2), и агент мог работать с ним по абсолютным путям — проблема была только в неявном
cwd: инструменты и субагенты по умолчанию смотрели в основное дерево.

## Решение
Сессия оркестратора не перезапускается между фичами и живёт в основном checkout.
Изоляция достигается не cwd процесса, а **контрактом WORKTREE**:

- после `git worktree add ../kt-<NN>-<slug> …` оркестратор фиксирует
  `WT=$(cd ../kt-<NN>-<slug> && pwd)` и все последующие операции выполняет только там:
  bash — с cwd=`$WT` (параметр `workdir`) или `git -C "$WT"`, файлы — абсолютными путями под `$WT`;
- промпт каждого субагента начинается со строки `WORKTREE: <абс. путь>` и директивы
  «все команды выполняй в WORKTREE, к основному дереву не прикасайся»; параллельные фичи
  различаются тем, что WT назван в каждом промпте;
- основное дерево до закрытия — read-only. Механическая страховка от «забыл workdir» —
  гейт **G8** (plugin `gates.ts`): пока процесс видел `git worktree add ../kt-*` и этот
  worktree существует, инструменты `edit`/`write`/patch с целью внутри основного дерева
  блокируются `GateError`. Закрытие (`git -C "$MAIN" merge --squash`) — bash, не правка,
  гейт его не касается.

Механика живёт в skill `workflow` («Открытие»), `/feature`, `/task`, AGENTS.md «Feature workflow»
и директивах субагентных агентов.

## Последствия
- Новая фича = одна команда `git worktree add`, без перезапуска opencode; контекст оркестратора
  переживает смену фич, параллельные фичи ведутся из одной сессии.
- Риск «команда уехала не в тот каталог» закрывается дважды: соглашением (явный cwd обязателен)
  и гейтом G8 (правка main при активном worktree физически невозможна).
- G8 — stateful в памяти процесса (как штамп G7): множество активных worktree строится из
  наблюдаемых `git worktree add/remove`; удалённые вне сессии worktree самоизлечиваются
  проверкой существования при следующей правке. Обход через bash-правка основного дерева
  остаётся возможным (как в G7) и принят.
- `/quick` на `chore/<slug>` без отдельного worktree не затронут: множество пусто — гейт молчит.
