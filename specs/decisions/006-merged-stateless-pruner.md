# ADR-006. Прунеры слиты в один stateless `Pruner`; глобальные проверки всегда включены

## Статус

Принято.

## Контекст

Исторически существовало два типа: `DeadEndPruner` (локальный dead-end) и
`AdvancedPruner` (связность + эвристика концов), иногда с порогом по остатку K —
глобальные проверки включались только когда непосещённых клеток осталось ≤ K.

## Решение

Один стейт-лесс компонент `pruner.Pruner`. Локальный dead-end — первый (дешёвый)
блок метода `ShouldPruneAfterVisit`, глобальные проверки (`globalCheck`) — второй
блок **того же** метода, отдельного типа больше нет. Глобальные проверки включены
всегда (без порога K).

Прунер не хранит статистику: учёт по видам ведёт вызывающий через возвращаемую
причину `Reason` → `types.Result.CountPrune`. Так сохраняется точная атрибуция без
атомиков на горячем пути.

## Последствия

- Нет переключателей/порогов, меньше состояния, проще инварианты.
- Причина возвращается заодно с флагом — один вызов даёт и решение, и учёт.

## Замеры

Время полного подсчёта (M4 Max, `-benchtime=3x`):

| доска | только dead-end | advanced (порог K=20) | advanced (всегда) |
|-------|-----------------|----------------------|-------------------|
| 5×5   | 3.20 мс         | 0.69 мс              | ~0.7 мс           |
| 6×6   | 16.7 с          | 2.09 с               | ~1.0 с            |

Порог K=20 ускорял 5×5 на ~8%, но на 6×6 проигрывал ~2×; выбран «всегда».
