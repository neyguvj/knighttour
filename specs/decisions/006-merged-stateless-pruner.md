# ADR-006. Компоненты отсечения слиты в одни; `Pruner` не хранит состояние, глобальные проверки всегда включены

## Статус

Принято.

## Контекст

Исторически существовало два типа: `DeadEndPruner` — локальная проверка тупика,
и `AdvancedPruner` — проверка связности плюс эвристика концов. У второго иногда
был порог K по остатку: глобальные проверки включались только тогда, когда
непосещённых клеток оставалось не больше K.

## Решение

Один компонент `pruner.Pruner`, который не хранит состояние. Локальная проверка
тупика — первый, дешёвый блок метода `ShouldPruneAfterVisit`; глобальные проверки
(`globalCheck`) — второй блок **того же** метода. Отдельного типа больше нет, и
глобальные проверки включены всегда, без порога K.

`Pruner` не ведёт статистику. Вызывающий сам учитывает каждый вид отсечения:
он получает от метода причину `Reason` и передаёт её в
`types.Result.CountPrune`. Так сохраняется точная атрибуция без атомарных
операций на горячем пути.

## Последствия

- Переключатели и пороги из кода ушли; состояния стало меньше, инварианты —
  проще.
- Вместе с флагом отсечения метод возвращает причину: один вызов даёт и решение,
  и данные для учёта.

## Замеры

Время полного подсчёта (M4 Max, `-benchtime=3x`):

| доска | только dead-end | advanced (порог K=20) | advanced (всегда) |
|-------|-----------------|----------------------|-------------------|
| 5×5   | 3.20 мс         | 0.69 мс              | ~0.7 мс           |
| 6×6   | 16.7 с          | 2.09 с               | ~1.0 с            |

Порог K=20 ускорял доску 5×5 на ~8%, но на 6×6 проигрывал ~2×. Выбран вариант
«всегда» — глобальные проверки без порога.
