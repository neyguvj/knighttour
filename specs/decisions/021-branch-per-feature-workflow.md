# ADR-021. Feature = ветка вместо feature-flag: переключатель фичи живёт в git, а не в коде

## Статус
Принято

## Контекст
Фичи и оптимизации включались/выключались прямо в `main` через переключатели: флаги,
env-ручки, kill-switch'и. Каждый такой переключатель просачивался в спеки и код, а потом
требовал отдельной зачистки. Прецеденты:

- ADR-007 — L2-прунинг «выключен по умолчанию» (механика позже снята ADR-016);
- ADR-016 — удаление class-mode и env `BENCH_MODE`/`SHAPE_FILTER`;
- ADR-019 → ADR-020 — ручки `BENCH_COUNT_K/B/C`, `BENCH_COUNT_ORDER` заводились в `main`
  ради A/B, жили между коммитами и умирали отдельным «cleanup»-коммитом.

Итог: `main` обрастал временными ветками поведения, а откат фичи означал «поставить дефолт
off», то есть мёртвый код в эталоне. Пользовательский запрос — писать так, будто план уже
принят: каждая фича в изоляции, непринятая просто не попадает в `main`.

## Решение
Переключателем фичи становится сама ветка (git worktree), а не флаг в коде.

- **Запрещено** вводить feature-flag / env-ручку / kill-switch как способ включить поведение,
  провести A/B или обеспечить откат. «Включено» = ветка смёржена, «выключено» = ветка не
  смёржена. **Легальны** параметры ввода запуска (`-size`, `-workers`, `-precompute-depth`,
  `-gc-percent`) — это не переключатели фич.
- **Открытие.** Принятый план → `git fetch` → `git worktree add ../kt-<NN>-<slug> -b <NN>-<slug>
  origin/main`. План, спека, код, тесты и черновик ADR живут только в этом worktree; `main` о
  фиче не знает до закрытия. Именование: `<NN>-<slug>` от номера плана; `/quick` без плана —
  `chore/<slug>`.
- **Сессия.** ~~Каждая фича = отдельный worktree = отдельная сессия opencode~~ — механика снята
  ADR-024: сессия оркестратора живёт в `main`, работа пинится к worktree контрактом WORKTREE.
  Фичи ведутся параллельно и изолированно (изолятор — worktree, не процесс).
- **Замер без флага.** База A/B — `merge-base HEAD origin/main` (не `HEAD~1`); бенчмаркер меряет
  base-worktree с уникальным именем `../kt-base-<NN>-<slug>` против HEAD. Долгие точки
  (`make bench`/`bench-deep` на 7×7) сериализуются через `flock ../kt-bench.lock`, иначе
  параллельные прогоны искажают тайминги и peak RSS.
- **Закрытие.**
  - *Принято (WIN):* squash ветки в один коммит поверх актуального `main` (`git merge --squash`),
    push — только по явному запросу; удалить worktree и ветку.
  - *Отклонено:* docs-only merge — в `main` переезжают только `specs/plans/NN-*.md` (помеченный
    закрытым) и ADR со статусом «отклонено» с числами до/после плюс строка в индексе решений;
    код не мержится; worktree и ветка удаляются.

Правила операционно живут в AGENTS.md («Feature workflow»), командах `/quick` `/task` `/feature`,
агентах `benchmarker`/`coder`/`reviewer` и skill `plan-writing`.

## Последствия
- `main` больше не копит временных переключателей и «выключенных по умолчанию» путей — зачистка
  флага отдельным коммитом становится невозможна by construction (флаг не появляется).
- Отрицательный результат сохраняется: отклонённая фича оставляет rejected-ADR с числами, знание
  «пробовали X — вот почему нет» не теряется.
- Одна фича = одна сессия opencode — отменено ADR-024: сессия общая, переключение фич = смена
  WT-пина, а не терминала/процесса.
- Долгие бенчмарки нельзя гонять параллельно — глобальный lock сериализует их; код и тесты
  (`make check`) параллельными прогонами не конфликтуют.
- Само это мета-изменение проведено bootstrap'ом напрямую в `main` (исключение из правила, пока
  workflow не существует); дальше любое изменение идёт через ветку по новому правилу.

## Замеры
n/a — процессное решение; конвейер подсчёта и его дефолты не меняются.
