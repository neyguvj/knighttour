# ADR-007. Усиленный L2-прунинг живёт только в финальном DP и выключен по умолчанию

## Статус

Принято (этап 0 плана 04). Механизм оставлен для будущих экспериментов.

## Контекст

План 04 предлагал усилить прунинг необходимыми условиями на состоянии `(cur, todo)`:
сочленения (lowlink Тарьяна) и обязательные цепочки (union-find). Вопрос — включать ли
их в генерационный DFS или только в финальный DP `shapecount`, и по какому порогу.

## Решение

L2-проверки (`ShouldPruneState`) вызываются **только** из рекурсии `f(cur,todo)`
пакета `shapecount`; генерационный DFS видит лишь L0/L1 (`ShouldPruneAfterVisit`).
По умолчанию L2 **выключён**: `New` даёт `L2None`, `minL2 = DefaultMinL2 = 10`.
Включение — `SetL2(mask, minTodo)` / `Counter.SetL2`.

Обе проверки O(V+E), без аллокаций (стек и union-find — фиксированные `[64]`-массивы).
ForcedChain корректен только при зафиксированном конце (ровно одна вершина `todo`
со степенью 1 в `H`); иначе форсинг некорректен и пропускается.

## Последствия

- Генерация не дорожает; дорогая атрибуция сочленений — там, где экспонента DP.
- Статистика L2 (`PrunedArticulation/ForcedChain`) появляется только в фазе counting.
- Бенчмарк `BenchmarkCountShapeL2` и свип уровней сохранены для реэкспериментов.

## Замеры

Этап 0 плана 04 (6×6, реальный пайплайн): artic удорожает фазу counting в **×2.3**,
chain — в **×1.5** при сокращении состояний DP заметно меньшем, чем окупает стоимость.
Порога, при котором проверки отбиваются на досках ≤ 7×7, не найдено → по умолчанию выкл.
