# ADR-007. Усиленное отсечение L2 работает только в финальном DP и по умолчанию выключено

## Статус

Принято (этап 0 плана 04). Механизм оставлен для будущих экспериментов.

## Контекст

План 04 предлагал усилить отсечение необходимыми условиями для состояния
`(cur, todo)`: поиск сочленений графа алгоритмом Тарьяна (lowlink) и обязательные
цепочки через union-find. Нужно было решить, включать ли их в генерационный DFS
или только в финальный DP пакета `shapecount`, и при каком пороге.

## Решение

Проверки яруса L2 (`ShouldPruneState`) вызываются **только** из рекурсии
`f(cur,todo)` пакета `shapecount`; генерационный DFS по-прежнему видит лишь
ярусы L0/L1 (`ShouldPruneAfterVisit`). По умолчанию L2 **выключён**: `New` даёт
`L2None`, `minL2 = DefaultMinL2 = 10`. Включают его вызовом `SetL2(mask, minTodo)`
или `Counter.SetL2`.

Обе проверки стоят O(V+E) и не делают аллокаций: стек и union-find лежат в
фиксированных массивах на 64 элемента. Проверка `ForcedChain` корректна только
при зафиксированном конце — когда в `todo` ровно одна вершина степени 1 в графе
`H`. Если это условие нарушено, обязательность цепочки не гарантирована, и
проверка пропускается.

## Последствия

- Генерация от этих проверок не дорожает: дорогая атрибуция сочленений остаётся
  там, где и без неё экспонента DP.
- Счётчики L2 (`PrunedArticulation`/`ForcedChain`) появляются только в count-фазе.
- Бенчмарк `BenchmarkCountShapeL2` и проход по всем уровням L2 сохранены: механизм
  можно переисследовать.

## Замеры

Замер этапа 0 плана 04 на реальном конвейере (6×6): проверка сочленений (`artic`)
удорожает count-фазу в **×2.3**, проверка цепочек (`chain`) — в **×1.5**, а
сокращение числа состояний DP заметно меньше, чем нужно для окупаемости. Порога,
при котором проверки отбиваются на досках ≤ 7×7, найти не удалось, поэтому по
умолчанию L2 выключен.
