# ADR-015. 8×8: измерения class mode сняты, механика забегов сохранена за reversal

## Статус

Принято (2026-09-13). Замеры: n/a — решение объёма, опирается на существующую экстраполяцию
(план 05) и сравнение режимов (ADR-011).

## Контекст

8×8 не замерялась ни разу, эталонного числа нет (`docs/requirements.md`); экстраполяция
плана 05 — часы на точку даже при d=32. Class mode на 7×7 d22 стоит 23.5 ГБ против 9.6 ГБ
у reversal (ADR-011) — на 8×8 ему не хватает памяти априори, requirement «первая точка 8×8
для class mode» невыполним в принципе. Из-за этого шабка A/B-свода и пункт 5 плана 05
блокировали шаг 7 плана 06 (судьба default `-mode`) фантомным требованием.

## Решение

8×8 исключена из roadmap и из требований к A/B-своду (шаги 6–7 плана 06: свод только
6×6/7×7). Из измерений убрано конкретно class-mode ветвление 8×8:

- цель `make bench-8x8` фиксирует `BENCH_MODE=reversal`;
- подтест `size8` в class-режиме — SKIP с поясняющим сообщением (class 8×8 не меряется);
- `sweepDefaults{8}` / гейт `BENCH_8X8` / `bench-size N=8` **сохраняются** как механика
  будущих reversal-забегов («займёмся позже»).

Не меняется: валидность `-size 8` в CLI (битборд uint64 поддерживает 8×8 естественно),
`docs/requirements.md` (не трогается), план 07 (frontier DP) — припаркован с пометкой,
не отклонён.

## Последствия

- Шаг 7 плана 06 разблокирован: блокирующие позиции сняты — RSS-критерий закрыт ADR-014,
  8×8 выведена из объёма этим ADR.
- Цена возврата к 8×8 отложена, но не оплачена заранее: ни одной class-mode попытки на 8×8
  в логах/планах больше не планируется.
- `bench-deep`/обычный свип не затронуты (size8 и так за гейтом).
