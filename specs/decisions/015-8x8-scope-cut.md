# ADR-015. 8×8: измерения class mode сняты, механика прогонов сохранена за reversal

## Статус

Принято (2026-09-13). Замеры: n/a — это решение об объеме, оно опирается на существующую
экстраполяцию (план 05) и на сравнение режимов (ADR-011).

## Контекст

Доску 8×8 не замеряли ни разу, и эталонного числа для нее нет (`docs/requirements.md`).
Экстраполяция плана 05 обещает часы на одну точку даже при d=32. Режим `class` (исторический
режим подсчёта по классам канонизации; удалён в ADR-016) стоит на доске 7×7 глубине 22 целых
23.5 ГБ против 9.6 ГБ у reversal (ADR-011). На 8×8 памяти для него не заведомо не хватит, поэтому
требование «первая точка 8×8 для class mode» невыполнимо в принципе. Из-за этого строка свода
A/B-сравнения и пункт 5 плана 05 блокировали шаг 7 плана 06 (выбор значения `-mode` по умолчанию)
фантомным требованием.

## Решение

Доска 8×8 исключена из roadmap и из требований к своду A/B-сравнения: шаги 6–7 плана 06 охватывают
только 6×6 и 7×7. Из измерений убрано конкретно ветвление class mode для 8×8:

- цель `make bench-8x8` фиксирует `BENCH_MODE=reversal`;
- подтест `size8` в режиме class выводит SKIP с поясняющим сообщением: class mode на 8×8 не
  измеряется;
- таблица глубин по умолчанию `sweepDefaults{8}`, переключатель `BENCH_8X8` и цель
  `bench-size N=8` **сохраняются** как механика будущих прогонов reversal — этим займутся позже.

Ничего из следующего не меняется: допустимость `-size 8` в CLI (битборд uint64 поддерживает 8×8
естественным образом); файл `docs/requirements.md` остается нетронутым; план 07 (frontier DP)
припаркован с пометкой, но не отклонен.

## Последствия

- Шаг 7 плана 06 разблокирован: обе блокирующие позиции сняты. RSS-критерий закрыла ADR-014,
  а объем по 8×8 снял этот ADR.
- Цена возврата к 8×8 отложена, но не оплачена заранее: ни одной попытки class mode на 8×8 больше
  не планируется ни в логах, ни в планах.
- Цель `bench-deep` и обычные проходы по диапазону глубин не затронуты: подтест `size8` был
  отключен переключателем и раньше.
