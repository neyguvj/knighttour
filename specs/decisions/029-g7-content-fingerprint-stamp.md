# ADR-029. Гейт G7 v2: контентный отпечаток вместо булева штампа; авто-commit субкоманды под правилом сопоставления

## Статус
Проект — черновик до кода на feature-ветке `08-g7-stamp-v2` (база `main 82bb52c`). Приёмка по
сценариям 1–13 specs/gates.md; стоимость механизма замерена заранее (ниже).

## Контекст
ADR-023 (v1) зафиксировал два ограничения, вынесенные за рамки v1: (1) правки файлов через bash
(`sed -i`, редиректы, скрипты) не сбрасывают зелёный штамп, и коммит уходит ложно-зелёным; (2)
коммит проходит ложно, если он создан путями, невидимыми правилу сопоставления (алиасы, коммит из
скрипта, авто-commit субкоманды). Булев штамп к тому же глобален процессу без привязки к дереву:
зелёная проверка агента `coder` в worktree легитимирует squash-коммит в main даже после того, как
`git -C "$MAIN" merge --squash` изменил содержимое (main ушёл вперёд). Это отверстие между деревьями
лежит ровно на каноническом пути закрытия `/feature` (skill `workflow`).

## Решение
Содержание v2 подтверждено интервью по фиче: классы правок (#2), критерий детекции и ключ штампа.
Контракт — specs/gates.md («Гейт G7»):

1. Штамп — это множество контентных отпечатков, которое пополняют зелёные прогоны `make check`
   (подтверждение exit 0 и связь цепочкой `&&` — без изменений v1). Отпечаток покрывает всё
   нетигируемое содержимое (`tracked ∪ untracked`); игнорируемые git пути `work/**` и артефакты
   сборки в него не входят. Для каждого пути учитываются рабочая копия и индекс (staged-blob).
   Коммит берёт содержимое из индекса, поэтому отстающий индекс при зелёной рабочей копии — это
   другое содержимое, а `git add` уже проверенного файла даёт тот же отпечаток.
2. Инвалидация по инструментам `edit`/`write`/`patch` и событию `file.edited` удалена: её полностью
   заменяет сверка отпечатка в момент коммита. Побочный плюс — исчезает ложная инвалидация пары
   «правка и откат». Освободившийся код (`MUTATING_TOOLS`, ветка `file.edited` у G7) удаляется в том
   же изменении, как требует AGENTS.md.
3. Правило сопоставления расширено авто-commit субкомандами `merge`, `cherry-pick`, `revert`,
   `rebase` и `am`. Формы, заведомо не создающие коммит (`--no-commit`, `merge --squash`,
   `merge --ff-only`), остаются вне гейта. Инструкция блокировки указывает им корректный
   двухшаговый путь (`--no-commit` → `make check` → явный `git commit`): проверка до merge не
   аттестует результат merge.
4. Если отпечаток не вычислился — нет git, таймаут вызова, цель вне репозитория, — коммит
   блокируется; отказ безопасен в сторону запрета. Цена блока — один прогон `make check`.
   Направление совпадает с правилом v1 «без подтверждения — нет штампа» и сознательно отличается от
   шумного G12, где сбой разрешает операцию (ADR-028).

Отклонённые альтернативы: правило сопоставления для мутирующих bash-команд (`sed -i`, `tee`,
редиректы) — оно неполно, гонка дописываний остаётся, и критерий достаточности не выполняется;
чтение текстов скриптов, переданных интерпретаторам, — это класс осознанного обхода плюс ложные
срабатывания на echo и комментариях; детекция алиасов средствами разбора текста невозможна; строгая
привязка штампа к каждому корню отдельно — лишние прогоны при совпадающем содержимом; включение
игнорируемых файлов в отпечаток — стоимость переписываемых артефактов `work/` при нулевой пользе.

## Последствия
- (+) Класс ложно-зелёного коммита из v1 закрыт полностью: любой способ правки между проверкой и
  коммитом заметен по содержимому, а пара «правка и откат» корректно восстанавливает штамп.
- (+) Отверстие между деревьями закрыто множеством без привязки к корню. Если main не ушёл вперёд,
  squash при закрытии проходит без лишней проверки: содержимое совпадает с зелёным отпечатком. Если
  main ушёл, коммит блокируется, и `make -C "$MAIN" check` аттестует уже состояние после слияния —
  так ловится семантический конфликт с ушедшим вперёд main. Шаг нужно отразить в цепочке закрытия
  skill `workflow` — задача `coder` на будущее.
- (+) Ложных инвалидаций стало меньше, чем у событийного механизма v1: правка, вернувшая файлу
  прежнее содержимое, больше не сбрасывает штамп безвозвратно.
- (-) На каждую попытку коммита приходится проход содержимого дерева (~10 мс здесь; см. раздел
  «Замеры»), и каждая зелёная проверка делает такой же проход при штамповке.
- (-) `git merge`, `cherry-pick`, `revert`, `rebase` и `am` на незелёном дереве блокируются. В
  рабочем процессе репозитория они редки, а переформулировка в двухшаговый путь ничего не стоит.
- Принятый край остаётся: алиасы и коммит из скрипта — класс осознанного обхода; пользовательский
  терминал; обёртка `cmd; echo "exit=$?"`, прячущая сбой за итоговым нулём; `cd` внутри команды,
  потому что дерево разрешается от `-C` или `workdir`; перезапуск процесса теряет множество
  отпечатков.

## Замеры
Стенд — darwin 25.3, дерево `main 82bb52c`: 109 нетигируемых файлов / ~820 КБ. Полный проход
«`git ls-files -c -o --exclude-standard` + чтение + sha256» занимает ≈ 10–11 мс (пробник на python3,
3 прогона); node `crypto` в процессе плагина не дороже. `git ls-files -s` стоит ~10–30 мс с запуском
процесса. При штамповке плагин делает один проход, и попытка коммита — тоже один. Калибровка
стоимости git-вызовов в плагине — ADR-028 (G12, ~8 мс). Сравнение до/после по времени конвейера
счёта n/a: гейт лежит вне горячего пути.

## Проверка
Стенд уровня хуков плагина (прецедент ADR-023: Node ≥23.6, прямой вызов
`tool.execute.before/after`/`event`) покрывает сценарии 1–13 specs/gates.md. Позитивные контроли
правила сопоставления: `merge --squash`, `--no-commit` и `--ff-only` не блокируются; проверяется
устойчивость к битым args/metadata. Контроли из ревью: освобождение распознаётся только вне кавычек
(`-m "…--no-commit…"` и `merge -m "…--ff-only…"` остаются под гейтом, при небалансированной кавычке
освобождения нет); множество отпечатков конечно и вытесняет по FIFO — вытесненный отпечаток не
легитимирует коммит. Прогон стенда выполняется на ветке; ручную приёмку процедуры закрытия
(сценарий 11) проводит оркестратор при закрытии фичи.
