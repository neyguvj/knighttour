# ADR-029. Гейт G7 v2: контентный отпечаток вместо булева штампа; авто-commit субкоманды под матчером

## Статус
Проект — черновик до кода на feature-ветке `08-g7-stamp-v2` (база `main 82bb52c`). Приёмка по
сценариям 1–13 specs/gates.md; стоимость механизма замерена заранее (ниже).

## Контекст
ADR-023 (v1) зафиксировал два ограничения «вне скоупа v1»: (1) правки файлов через bash (`sed -i`,
редиректы, скрипты) не снимают зелёный штамп — ложно-зелёный коммит; (2) ложные пропуски коммита
невидимыми матчеру путями (алиасы, коммит из скрипта, авто-commit субкоманды). Булев штамп к тому же
глобален процессу без привязки к дереву: зелёная проверка `coder`'а в worktree легитимирует
squash-коммит в main даже после того, как `git -C "$MAIN" merge --squash` изменил содержимое
(main ушёл вперёд) — cross-tree отверстие ровно на каноническом пути закрытия `/feature`
(skill `workflow`).

## Решение
Объём v2 подтверждён интервью фичи (классы #2, критерий детекции, ключ штампа). Контракт —
specs/gates.md «Гейт G7»:

1. Штамп = множество контентных отпечатков, поставленных зелёными `make check` (подтверждение
   exit 0 и `&&`-самогейдинг — без изменений v1). Отпечаток покрывает всё нетигируемое содержимое
   (`tracked ∪ untracked`; gitignore-нные `work/**`/артефакты — вне) и для каждого пути включает
   рабочую копию и индекс (staged-blob): коммитится именно индекс, поэтому «старый» индекс при
   зелёной рабочей копии — другое содержимое, а `git add` уже проверенного — тот же отпечаток.
2. Инвалидация по инструментам `edit`/`write`/`patch` и событию `file.edited` снимается: она
   субсумируется сверкой отпечатка в момент коммита (плюс исчезает ложная инвалидация пары
   «правка+откат»). Освободившийся код (`MUTATING_TOOLS`, ветка `file.edited` у G7) удаляется —
   dead code в том же изменении (AGENTS.md).
3. Матчер расширен авто-commit субкомандами `merge`/`cherry-pick`/`revert`/`rebase`/`am`; формы,
   заведомо не создающие коммит (`--no-commit`, `merge --squash`, `merge --ff-only`), — вне гейта.
   Инструкция блока для них указывает корректный двухшаговый путь (`--no-commit` → `make check` →
   явный `git commit`), т.к. check-before-merge результат merge не аттестует.
4. Отказ вычислить отпечаток (нет git / таймаут / вне репозитория) — fail-closed (блок): цена блока —
   один прогон `make check`; направление совпадает с v1 «без подтверждения — нет штампа» и сознательно
   отличается от fail-open шумного G12 (ADR-028).

Отклонённые альтернативы: синтаксический матчер мутирующих bash-команд (`sed -i`, `tee`, редиректы) —
неполная гонка дописываний, criterion «достаточность» не выполняет; чтение текстов скриптов, переданных
интерпретаторам, — это класс осознанного обхода плюс ложные срабатывания на echo/комментариях;
детекция алиасов — текстострочно невозможна; строгая привязка штампа к корню (per-root) — лишние
прогоны при совпадающем содержимом; включение игнорируемых файлов в отпечаток — стоимость гоняемых
`work/`-артефактов при нулевой пользе.

## Последствия
- (+) Класс ложно-зелёного v1 закрыт полностью: любой способ правки между проверкой и коммитом
  детектируется содержимым; пара «правка+откат» корректно восстанавливает штамп.
- (+) Cross-tree отверстие закрыто множеством без привязки к корню: main не ушёл — squash-close
  проходит без лишней проверки (содержимое совпадает с зелёным отпечатком); ушёл — блок, и
  `make -C "$MAIN" check` аттестует уже пост-merge состояние (ловит семантический конфликт с
  ушедшим вперёд main). Follow-up coder'а: отразить этот шаг в close-цепочке skill `workflow`.
- (+) Меньше ложных инвалидаций, чем у событийного механизма v1 (правка «в стол» больше не глушит
  штамп намертво).
- (-) На каждую попытку коммита — проход содержимого дерева (~10 мс здесь; см. Замеры); на каждую
  зелёную проверку — такой же проход при штамповке.
- (-) `git merge`/`cherry-pick`/`revert`/`rebase`/`am` на незелёном дереве блокируются (в workflow
  репо редки; переформулировка/двухшаговость ничего не стоят).
- Принятый край остаётся: алиасы и коммит из скрипта (осознанный обход), пользовательский терминал,
  обёртка `cmd; echo "exit=$?"`, `cd` внутри команды (резолв дерева от `-C`/workdir), рестарт процесса
  теряет множество отпечатков.

## Замеры
Стенд darwin 25.3, дерево `main 82bb52c`: 109 нетигируемых файлов / ~820 КБ; полный проход
«`git ls-files -c -o --exclude-standard` + чтение + sha256» ≈ 10–11 мс (python3-зонд, 3 прогона;
node `crypto` в процессе плагина не дороже), `git ls-files -s` ~10–30 мс с startup процесса. Штамповка:
один проход; попытка коммита: один проход. Калибровка стоимости git-вызовов в плагине — ADR-028
(G12, ~8 мс). До/после по времени counting-пайплайна n/a — гейт вне hot-path.

## Проверка
Харнесс уровня хуков плагина (прецедент ADR-023: Node ≥23.6, прямой вызов
`tool.execute.before/after`/`event`): сценарии 1–13 specs/gates.md, позитивные контроли матчера —
`merge --squash`/`--no-commit`/`--ff-only` вне блока; устойчивость к битым args/metadata. Контроли
из ревью: освобождение распознаётся вне кавычек (`-m "…--no-commit…"`, `merge -m "…--ff-only…"` —
под гейтом, небалансированная кавычка — без освобождения) и FIFO-кап множества отпечатков (вытесненный
не легитимирует). Прогон — на ветке; ручная приёмка close-flow (сценарий 11) — за оркестратором при
закрытии.
