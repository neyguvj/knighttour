# ADR-020. Удаление переменных окружения бенч-харнесса: дефолты зафиксированы, отбор прогонов — в Makefile

## Статус
Принято

## Контекст
В бенч-харнессе накопились семь переменных окружения: включения досок `BENCH_DEEP` / `BENCH_8X8`,
список точных глубин `BENCH_DEPTHS`, параметры настройки count-фазы `BENCH_COUNT_K/B/C` и переменная
порядка выборки `BENCH_COUNT_ORDER`. Переменные отработали своё назначение: K=10000 и B=16 —
измеренный оптимум свода ADR-019 (план 13), C=4 зафиксирован фиксом механики, контраст LIFO/FIFO
закрыт как **TIE** (план 13, 2026-09-16). При этом переменные включения и точных глубин держат в
Go-коде логику пропусков тестов и просачиваются в спеки. Решение пользователя — оставить в коде
только поведение по умолчанию.

## Решение
- В `counter/benchmark_test.go` удалены все вызовы `os.Getenv`: переменные включения досок
  (`deepEnvVar`/`sizeEnvVars`/`gatedSizes`/`gateVar`), переменная точных глубин (`benchDepthsEnv`;
  `sweepDepths` отдаёт только нисходящий проход до `depthFloors`, безусловный потолок `sweepDefaults`
  удалён из кода — он глушил явные точные глубины вне набора) и параметры диспетчеризации
  (`applyDispatchKnobs`/`applyPositiveEnv`/`applyOrderEnv`).
- Настройки count-фазы зафиксированы как значения по умолчанию: K=10000, B=16, C=4 (значения свода
  ADR-019); переопределить их во время выполнения нельзя.
- Ветка выборки FIFO удалена как мёртвый код (`dispatchClaimFIFO`, параметр `fifo` в стеке):
  контракт один — LIFO. Контрастная точка закрыта вердиктом **TIE**, её числа остаются в плане 13.
- Отбор досок и точечные прогоны переезжают в Makefile через фильтры `-bench`: `make bench` →
  `…/size[56]`, `make bench-deep` → `…/size[567]`, `make bench-8x8` → `…/size8`. Аргумент
  `DEPTHS=a,b` остаётся чистым аргументом make и транслируется в якорированный фильтр
  `-bench='…/sizeN/^depth(a|b)$'`: регулярное выражение сопоставляет сегменты без привязки к краям,
  и без якорей точка `1` подобрала бы depth10–19. Ограничение `{32,30}` для 8×8 — фильтр по умолчанию
  у целей size8 только при отсутствии `DEPTHS`; явный `DEPTHS` всегда выбирает свою точку. Go-код об
  отборе досок не знает.
- Служебный тестовый сигнал `PEAKRSS_CHILD` сохранён (`TestPeakRSSUnits` перезапускает свежий
  процесс): это не параметр настройки, человек его не выставляет.

## Последствия
- Прямой запуск `go test -bench=.` выполняет все доски — это часы и дни. Прежняя защита — пропуск
  досок через `t.Skip` — снята; примеры фильтров документирует `specs/benchmarks.md`.
- Валидация глубин сводится к правилу «нет совпадений с фильтром — ничего не запустилось»; прежних
  статусов SKIP и Fail с сообщением больше нет. Несуществующее значение `DEPTHS` молча не запускает
  подтесты.
- Проход по значениям K/B/C без правки кода невозможен. При новом исследовании переменную заводят
  временно и удаляют по завершении; прецедент — заметка ADR-014 о `BENCH_GC_PERCENT`.
- Тестам, которые меняли параметры швов пакетной раздачи, теперь нужны явные аргументы или швы
  формулы `Beff` и ёмкости стека (реализация — за кодером). Кейсы FIFO исчезают из тестов вместе
  с веткой.

## Замеры
n/a — это чистка бенч-харнесса: конвейер и значения по умолчанию не меняются, K/B/C перенесены из
свода ADR-019 без изменений, показания времени и памяти идентичны по построению.
