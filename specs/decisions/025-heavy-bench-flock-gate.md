# ADR-025. Гейт G9 «тяжёлые бенчи только под flock»: stateless-проверка инвокации вместо текстовой дисциплины

## Статус
Принято; реализация — ветка `04-bench-flock` (элемент списка гейтов в `.opencode/plugins/gates.ts`).
Процессное решение, замеры n/a.

## Контекст
ADR-022 называет прогон тяжёлых бенчей без flock одной из систематических проблем: долгие точки
7×7/8×8 (часы на точку), запущенные параллельно разными фичами, искажают тайминги и peak RSS —
вердикты A/B (ADR-021 меряет HEAD и базу по очереди) становятся недостоверны. Дисциплина
`flock ../kt-bench.lock` живёт в текстах (AGENTS.md «Feature workflow», skill `workflow`, агент
benchmarker), но инструкция — не механизм. Permission-слой выразить правило не может: паттерны
позитивные, отрицания нет («заблокировать, если flock отсутствует» не записать) — значит plugin-слой
(ADR-022).

## Решение
Контракт целиком — `specs/gates.md` «Гейт G9»; здесь обоснование выборов:

- **Statelessness.** В отличие от G7 (штамп) и G8 (множество worktree) гейт не хранит состояния:
  смотрит только строку команды в `before`. Сериализацию обеспечивает сам flock(1) между процессами;
  состояние плагина дублировало бы несуществуемое обязательство.
- **Тяжесть по имени цели**: `bench-deep`, `bench-8x8`, `bench-size`; исключение одна — `make bench`
  (5×5/6×6). Отклонён разбор `N=`/`DEPTHS=`: лёгкая точка в контеншене с долгими искажается так же, а
  свободный lock бесплатен; разбор значений добавляет только ложные пропуски.
- **Прямой `go test -bench` накрывается** консервативным классификатором значения флага (size-сегмент с
  7/8 или его отсутствие — все доски). Цели Makefile — тонкие обёртки над `go test`, и обход прямой
  командой обнулил бы гейт; при этом лёгкие значения (`size5`, `size[56]`) остаются без lock'а —
  симметрично исключению `make bench`. По ревью: флаг матчится как `-{1,2}bench` (flag-пакет Go
  эквивалентен одинарной и двойной черте — иначе `--bench=…size7` проходил бы без lock'а), и size-сегмент
  с 7/8 тяжёлый даже без имени бенчмарка: анонимный селектор `-bench=size7` бьёт по единственному
  size-сегментированному бенчу репозитория, ложный блок — в безопасную сторону (прецедент G7).
- **Каноничность lock-файла**: защита только за `<родитель-основного-дерева>/kt-bench.lock` (резолв от
  `workdir` инструмента, иначе cwd процесса — механика базы G8). Отклонено «любой flock-файл»:
  локальный per-worktree lock не сериализует разные фичи — ровно то, из-за чего поднят гейт. Отклонено и
  точное совпадение строки `../kt-bench.lock`: абсолютный путь к тому же файлу эквивалентен.
- **Матчер — соседство `make`+цель по всему сегменту** (не только в голове): обёртки `sudo`/`env`/`time`
  не прячут инвокацию и не мешают подчинению. Ложные срабатывания на текстовые упоминания приняты по
  прецеденту G7 («переформулировка стоит копейки» против стоимости испорченного часового замера).
- Feature-flag отсутствует (ADR-021): переключатель — ветка.

## Последствия
- (+) параллельные тяжёлые прогоны видимыми путями становятся физически невозможны; вместо молча
  съехавших чисел модель получает `GateError` с канонической командой.
- (-) обход скриптами/алиасами/функциями остаётся невидимым матчеру — принятый класс G7/G8.
- (-) `cd` внутри команды не отслеживается: относительный lock резолвится от `workdir`; каноническое
  написание из другого каталога бьёт по иному файлу (WORKTREE-контракт обязывает cwd=`$WT`).
- (-) `flock(1)` нет в базовом userland darwin: отсутствие = неподготовленное окружение (пробы по
  AGENTS.md «Shell environment»), гейт проверяет форму инвокации, не наличие утилиты.
- (-/+) exit code не читается: обёртка `cmd; echo "exit=$?"` (ограничение приёмки G8) на G9 не влияет —
  уязвимы только state-гейты со штампом/множеством.

n/a (процессное решение, не hot-path).
