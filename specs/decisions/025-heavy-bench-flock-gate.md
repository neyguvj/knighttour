# ADR-025. Гейт G9 «тяжёлые бенчи только под flock»: проверка вызова команды без состояния вместо текстовой дисциплины

## Статус
Принято; реализация — ветка `04-bench-flock` (элемент списка гейтов в `.opencode/plugins/gates.ts`).
Процессное решение, замеры n/a.

## Контекст
ADR-022 называет прогон тяжёлых бенчей без flock одной из систематических проблем. Долгие точки
7×7/8×8 (часы на точку), запущенные параллельно разными изменениями, искажают время и peak RSS, и
вердикты A/B перестают быть достоверными: ADR-021 меряет HEAD и базу по очереди. Дисциплина
`flock ../kt-bench.lock` живёт в текстах (AGENTS.md «Feature workflow», skill `workflow`, агент
benchmarker), но инструкция — не механизм. Permission-слой выразить правило не может: паттерны
позитивные, отрицания у них нет — записать «заблокировать, если flock отсутствует» нельзя. Значит,
проверку берёт на себя plugin-слой (ADR-022).

## Решение
Контракт целиком ведёт `specs/gates.md` «Гейт G9»; здесь приводится обоснование выборов:

- **Работа без состояния.** В отличие от G7 (штамп) и G8 (множество worktree), этот гейт ничего не
  хранит: он смотрит только строку команды в хуке `before`. Сериализацию между процессами
  обеспечивает сам `flock(1)`; состояние плагина дублировало бы обязательство, которого не
  существует.
- **Тяжесть определяется по имени цели**: `bench-deep`, `bench-8x8`, `bench-size`; одно исключение —
  `make bench` (5×5/6×6). Разбор значений `N=`/`DEPTHS=` отклонён: лёгкая точка при конкуренции за
  блокировку с долгими искажается так же, а незанятый lock ничего не стоит. Разбор значений добавил
  бы только ложные пропуски.
- **Прямой `go test -bench` накрывается** консервативным классификатором значения флага: сегмент
  размера с 7 или 8 либо отсутствие сегмента означают все доски. Цели Makefile — тонкие обёртки над
  `go test`, и обход прямой командой обнулил бы гейт. При этом лёгкие значения (`size5`, `size[56]`)
  остаются без блокировки flock — симметрично исключению `make bench`. По итогам ревью флаг
  сопоставляется с образцом `-{1,2}bench`: пакет флагов Go приравнивает одинарную и двойную черту,
  иначе `--bench=…size7` прошёл бы без блокировки. Сегмент размера с 7 или 8 считается тяжёлым даже
  без имени бенчмарка: селектор `-bench=size7` попадает в единственный бенч репозитория,
  сегментированный по размеру доски, а ложная блокировка ошибается в безопасную сторону
  (прецедент G7).
- **Каноничность lock-файла**: защищается только путь
  `<родитель-основного-дерева>/kt-bench.lock`; он вычисляется от `workdir` инструмента, а иначе —
  от cwd процесса (та же база вычисления путей, что у гейта G8). Вариант «любой flock-файл»
  отклонён: локальный lock на каждый worktree не сериализует разные изменения — ровно из-за этого
  гейт и поднят. Отклонено и точное совпадение строки `../kt-bench.lock`: абсолютный путь к тому же
  файлу эквивалентен.
- **Сопоставление ищет `make` и цель рядом по всему сегменту команды**, а не только в начале:
  обёртки `sudo`, `env`, `time` не скрывают вызов команды и не мешают блокировке flock. Ложные
  срабатывания на текстовые упоминания приняты по прецеденту G7: переформулировать команду дёшево,
  а сорванный часовой замер дорог.
- Feature-flag отсутствует: переключателем служит ветка (ADR-021).

## Последствия
- (+) параллельные тяжёлые прогоны видимыми путями становятся физически невозможны. Вместо незаметно
  искажённых чисел модель получает `GateError` с канонической командой.
- (-) обход скриптами, алиасами и функциями остаётся невидим для сопоставления — это принятый класс
  ограничений G7/G8.
- (-) `cd` внутри команды не отслеживается: относительный путь lock-файла вычисляется от `workdir`,
  поэтому каноническое написание из другого каталога смотрит в иной файл; контракт WORKTREE
  обязывает cwd=`$WT`.
- (-) в базовом userland Darwin утилиты `flock(1)` нет: её отсутствие означает неподготовленное
  окружение (пробы по AGENTS.md «Shell environment»). Гейт проверяет форму вызова команды, а не
  наличие утилиты.
- (-/+) код возврата не читается: обёртка `cmd; echo "exit=$?"` (ограничение приёмки G8) на G9 не
  влияет. Уязвимы только гейты с состоянием — со штампом или множеством.

## Замеры
n/a — процессное решение, вне горячего пути кода.
