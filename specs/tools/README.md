# Инструменты: индекс и правила

Переиспользуемые утилиты репозитория лежат в `tools/`, их описания — здесь.
Мотивация: агенты плодят одноразовые скрипты с ошибками вместо того чтобы
применять готовое. Правило: **перед написанием любого скрипта снять этот индекс**;
одноразовый скрипт допустим только когда переиспользование вне текущей задачи невозможно.

## Индекс

| Тул | Путь | Назначение | Когда звать |
|-----|------|------------|-------------|
| bench-table | [`tools/bench_table.py`](../../tools/bench_table.py) | Рендер `go test -bench` лога в markdown-таблицы (по доскам, глубины по убыванию, K/M/G-скейлинг) | Любой markdown из бенч-логов: README, ADR, отчёт ([карточка](bench-table.md)) |

## Правила ведения

- **Один инструмент = одна карточка** `specs/tools/<tool>.md` + файл `tools/<tool>.py`.
  Карточка описывает **текущий эталон**: назначение, CLI, вход/выход, ограничения.
  Без истории и примеров «как писалось».
- Инструмент без карточки в индексе не считается существующим — его сначала заводят по
  гайду skill `tools`.
- Индекс обновляется **в том же изменении**, что заводит/удаляет тул. Ревьюер ищет дубли
  существующих тулов (MAJOR) и переиспользуемые скрипты вне `tools/` без карточки (MINOR).
- Конвенции запуска, зависимостей и переносимости — skill `tools`.
