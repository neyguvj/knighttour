---
description: Задача с обязательным spec-first workflow (спеки обновляются до кода)
---

Ты обязан выполнять работу СТРОГО по шагам. Пропуск шага = ошибка.

Задача: $ARGUMENTS

## ШАГ 0 — Спеки (до любого изменения кода)

1. Прочитай specs/README.md и specs/<пакет>.md для всех затрагиваемых пакетов.
2. Отредактируй спеку ПОД новую задачу ДО изменения кода: что меняется в API, поведении или инвариантах — запиши в соответствующий spec-файл.
3. Напиши пользователю одной строкой: `Спека обновлена: specs/X.md`.

## ШАГ 1 — Чек-лист

Создай todowrite со всеми шагами: спеки → код → тесты → проверки. Отмечай статус по ходу работы.

## ШАГ 2 — Код и тесты

Реализуй строго по обновлённой спеке.
Тесты: testify.Assert*, предпочтительно table-driven.
Любое отклонение кода от спеки — остановись и спроси пользователя, не решай самовольно.

## ШАГ 3 — Проверки (обязательно)

```bash
make check
```

Запускает `go fmt` → `go vet` → `go test -race` → автофиксы современных идиом (`go fix`, golangci-lint --fix) → строгий `golangci-lint`.
Если что-то упало — чини и запускай заново. Запрещено сообщать о готовности при неуспешных проверках.

## ШАГ 4 — Бенчмарки (обязательно при оптимизациях)

Если задача затрагивает hot-path (searcher/, counter/, state/, cache/, pruner/) или заявлена как оптимизация:

```bash
make bench
```

Приложи пользователю числа ДО и ПОСЛЕ. Запрещено заявлять об ускорении без замеров.
